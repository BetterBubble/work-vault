> Границы соблюдены: только teststand (38.180.236.39), контент из **main #-файлов** (origin/main `8f8287c`, ssh_upload в scratch `/home/tacticum/tz3-pilot/`, НЕ прод-каталог tacticum-mcp), codex `-s read-only`, не деплой, teardown после.

## Среда (feasibility)
- Хост teststand, codex-cli **0.142.3**, `codex exec --skip-git-repo-check -s read-only` от юзера **tacticum** (PATH += `~/.npm-global/bin`), auth активна (модель gpt-5.5, `~/.codex/auth.json` на месте). Пробный `echo "2+2" | codex exec` → «Four».
- Метод: залил 5 тел навыков из origin/main (fr-authoring, api-contracts-discovery, brd-authoring, pin-authoring, start-task) + 3 FR-фикстуры (v2-plated, v2-approved, v1) в scratch; каждый смоук — свой prompt-вход; РЕАЛЬНЫЙ вывод снят через `--output-last-message` (чтобы не резать транскриптом, где codex эхом печатает всё тело навыка). Падений запуска НЕ было (в отличие от ТЗ#2 — здесь top-level сессия, флаги те же).
- ⚠️ **Ограничение прогона (честно):** MCP аналитика **helm-analyst** (analyst_context/gap_questions/affected_systems/kb_* и т.п.) на codex teststand НЕ подключён (wired: context7, tacticum-mcp, serena, codegraph, playwright). Поэтому P1/P2 гнались как **структурный сухой прогон** (по образцу ТЗ#2 со stub-ADR): фактура — явные заглушки `[n]`, валидируется СТРУКТУРА/ГЕЙТ/ЧЕСТНОСТЬ, не реальная фактура из тулов. Фикстуры FR для P3–P5 — контролируемые входы (не выход codex), как stub-ADR в ТЗ#2; РЕАЛЬНЫМ снят именно ВЫВОД-решение codex.

## Что НЕ прогонялось (честно, осознанно вне скоупа)
- **helm-analyst MCP не подключён** на codex teststand → P1/P2 = структурный сухой прогон (фактура-заглушки, валидируется скелет/честность/гейт, не реальная фактура тулов). Полностью «чистый» P1 использовал бы живой analyst-MCP.
- Фикстуры FR (P3–P5) — контролируемые ВХОДЫ, не выход codex (легитимно, как stub-ADR в ТЗ#2); РЕАЛЬНЫМ снят ВЫВОД-решение codex.
- Полный downstream (BRD→MOCKUPS→PIN→код→TESTS→сборка KMP/Angular) — по решению ГД не гоним (ТЗ#3 менял вход/гейт/скелет, а не билд; билд-среды нет — см. [[pilot-runtime-env-finding]]).
- Провижн через прод-каталог (tacticum-mcp) — намеренно НЕ использован (там прод-контент может быть старым); контент брался из main-файлов.
- P6 (pin К-2/4) — не гнал (опционально по плану; ядро P1–P5 закрыто, гейт/чтение проектных серий уже подтверждены P3/P4).
