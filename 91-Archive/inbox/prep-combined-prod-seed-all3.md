## 2. Роли-композиты — дедуп (ключевое)

Правило: **роль сидится ОДИН раз финальной версией из main**, а не по разу на каждое ТЗ. Иначе — попытка засидить одну и ту же роль дважды разными версиями в одном заходе.

| Роль | Прод → main (сидить) | Кто поднял версию |

| `iva-role-ios` | 0.1.0 → **0.1.1** | ТЗ#2 |
| `iva-role-java` | 0.1.0 → **0.1.1** | ТЗ#2 |
| `iva-role-kmp` | 0.1.0 → **0.1.1** | ТЗ#2 |

**Проверено:** на текущем main все 7 ролей подняты только ТЗ#2 — ТЗ#1 и ТЗ#3 меняли лейны, а не сами роли. Конфликта версий в этом заходе нет. Правило всё равно оставляем: если до утра кто-то из лидов поднимет роль ещё раз, сидить надо **последнюю версию из main на момент сида**, а не ту, что в таблице.

**Пины версий в `depends_on` отсутствуют** — роли ссылаются на лейны по id и подхватывают последнюю активную версию из каталога. Поэтому порядок «сначала лейны, потом роли» обязателен, но жёсткой сверки версий рёбер не требуется.

`iva-role-qa` (0.5.1) и `firebird-role-web` (0.1.0) в дельте отсутствуют — уже актуальны в проде, не трогаем.

## 3. Порядок захода

1. **Read-only pre-flight** — повторить проверку коллизий по всем целевым парам (профиль, версия). Ожидаемо: 26 × `created`, 0 коллизий. Если появилась коллизия — СТОП, не форсировать: значит кто-то засидил версию вручную или изменился контент под той же версией.
2. **Пере-сверка версий из свежего main** — main мог уехать за ночь; сидим фактические версии на момент сида, не из этих таблиц.
3. **Единый `pg_dump` бэкап каталога — ОДИН на весь заход, первым действием.** Уже снят пре-флайтом ТЗ#2: `/root/backups/tacticum_catalog_pre-tz2-seed_20260724_2013.dump` (11 МБ, custom-формат, `pg_restore --list` читается, 56 объектов, данные `profiles`/`profile_versions`/`ingredients` на месте). **Если между этим бэкапом и утренним сидом каталог менялся — снять свежий**, старый оставить как исторический.
4. **`git pull` в `/opt/tacticum`** — свежий main с контентом профилей.
5. **Доставка и сид:** `docker cp` `templates/` + `seed_community.py` в `tacticum-catalog-mcp-1` → сид. **Пересборка образа не нужна** — меняется только контент.
   **Порядок внутри сида: сначала все лейны, потом все роли-композиты** (роли резолвят лейны по последней активной версии).
6. **Verify на живой БД** (см. §4) — запросами, не по логу сида.
7. **Re-pin** — проверить `installations` затронутых профилей; у новых лейнов установок скорее всего 0, тогда re-pin не нужен.
8. **Wiki-sync** — если применимо, нужен токен.
