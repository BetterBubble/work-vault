# Тихая потеря тёмной темы при расхождении форм режимов

Ветка `fix/ds-mode-shape-mismatch` (база `feat/ds-profiles-config`), коммит `ef043cb`.
Worktree `/Users/bubblemac/tacticum-worktrees/ds-darkloss`. Тронуты два файла:
`apps/backend/scripts/merge_iva_tokens.py` и новый
`apps/backend/tests/design/test_merge_iva_tokens_modes.py`.

## Дефект оказался шире, чем в постановке

Разбор кода до правки дал четыре вида расхождений, а не три, и самый частый из них
до проверки «shape mismatch» **вообще не доходил**.

Токен и группа — оба `dict`. Ветка `elif all(isinstance(v, dict) for v in values)`
ловила эту пару раньше, чем `else`, и уходила внутрь рекурсией. Внутри цикл слияния
пропускает ключи на `$`, то есть `$value` и `$type` токена **испарялись молча**, а
единственное предупреждение говорило про выжившего.

Проверено на живом скрипте до правки, вход `light: bg.primary = "#ffffff"`,
`dark: bg.primary = {hover: "#111111"}`:

```
out:  {"bg": {"primary": {"hover": {"$type": "color", "$value": "#111111"}}}}
warn: bg/primary/hover: only in dark, kept the dark value
```

`#ffffff` из светлой темы нет нигде, а предупреждение называет **не тот путь и не тот
режим**. Строка 384 (`shape mismatch … kept {first}`), на которую указывала
постановка, срабатывала только на паре dict против не-dict — то есть на почти
невозможном входе. Это объясняет, почему дефект пережил три ветки: то, что видно в
коде, почти не случается, а то, что случается, в коде не видно.

## Какое решение выбрано и почему

Постановка предлагала три варианта; взят третий — разделение по тому, **что теряет
выход**.

| Расхождение | Что с данными | Решение |
|---|---|---|
| Токен в одном режиме, группа в другом | значение одного режима пропадает | **отказ, код 3, до записи** |
| dict против скаляра | то же | **отказ, код 3, до записи** |
| Разный `$type` | все значения на месте, теряется ярлык типа проигравшего | **код 2, файлы записаны** |
| Ключ есть только в одном режиме | не теряется ничего | предупреждение, **код 0** |

Обоснование границы: отказ стоит там, где иначе уезжает **значение**. Это ровно
принцип файла — скорее не собрать, чем испортить собранное, — и та же дисциплина,
что у отказов по битому конфигу и чужой ДС в каталоге.

`$type` не доведён до отказа сознательно: значения всех режимов там выживают,
портится только ярлык. Это ровно та сделка, что уже принята для неразрешённых
ссылок (код 2, файлы записаны), и заводить для неё более строгое правило, чем для
ссылок, было бы непоследовательно.

«Ключ только в одном режиме» оставлен как есть намеренно. Это **решение предыдущей
ветки**, записанное в докстроке: одинокое значение, завёрнутое в ключ режима, врало
бы, что токен темизирован. Ужесточать чужое осознанное решение попутно с починкой
другого дефекта — не моё дело.

Отдельно заведена оговорка против ложного срабатывания: если **все режимы принесли
буквально одинаковый узел**, он проходит любой формы. Терять там нечего, а без этой
оговорки проверка валила бы сборки на ровном месте — ровно та грабля, на которую
наступила предыдущая ветка с проверкой «вход не дал ничего».

## Сколько расхождений на реальных данных

**Ноль.** Ни одного, ни в одной из двух закоммиченных ДС.

Оговорка по методу: исходных выгрузок Tokens Studio в репозитории **нет** —
`docs/concept/design/tokens/` не существует, в истории по всем ссылкам не
коммитился (`git log --all --diff-filter=A`), на диске машины не найден. Профили
указывают на некоммитимый каталог. Поэтому пересобрать ДС из настоящих входов
нельзя, и это надо знать при чтении цифр ниже.

Что удалось сделать вместо этого — две независимые проверки.

**1. Статический разбор закоммиченных `tokens.json`.** Расхождение формы оставляет
след: узел, взятый от одного режима, попадает в выход **неразветвлённым**. Считаем
листья с `$value: {light|dark: …}` против листьев с простым `$value` в темизируемых
пространствах имён:

| ДС | Темизируемые ns | Разветвлённых листьев | Неразветвлённых |
|---|---|---|---|
| iva-web | bg, border, functional, icon, text | 342 | **0** |
| iva-mobile | bg, bg (Grouped), border, functional, icon, text | 331 | **0** |

Ноль неразветвлённых означает, что ни один из видов расхождения, оставляющих след
(токен-против-группы, dict-против-скаляра, ключ-только-в-одном-режиме), на этих
данных не встречался. Заодно проверено: битых узлов (`$value` без `$type`,
не-dict-лист) в обеих ДС тоже ноль.

**2. Полный прогон нового скрипта на реальном содержимом.** Режимные входы
восстановлены из закоммиченных `tokens.json` (каждая ветка `$value` — в свой файл),
дальше обычный запуск скрипта с временным конфигом:

```
iva-web:    1018 токенов, Merge warnings 0, отказов 0, $type conflicts 0 → код 0
iva-mobile:  962 токена,  Merge warnings 0, отказов 0, $type conflicts 0 → код 0
```

То есть новый отказ на реальном масштабе IVA (около двух тысяч токенов, живые
цепочки ссылок) **не срабатывает ни разу** и ничего не ломает. `$type`-расхождение
следа в выходе не оставляет, посчитать его археологией нельзя — но раз законных
расхождений на этих данных нет вовсе, риск ужесточения нулевой.

## Мутационное доказательство

Новые тесты прогнаны против скрипта **до** правки (`git checkout` файла, прогон,
возврат):

```
7 из 9 упали, 2 прошли
```

Упали ровно те, что описывают починку: четыре отказа с кодом 3 (токен-против-группы
в обе стороны, dict-против-скаляра, расхождение на глубине), `$type` с кодом 2 и два
теста на новые поля отчёта.

Прошли **обе** проверки законного поведения — ключ только в одном режиме и
одинаковый узел во всех режимах. Так и задумано: это сторожа против ложного
срабатывания, они обязаны быть зелёными по обе стороны правки. Если бы они упали,
это значило бы, что починка сломала законный случай.

С правкой — 9 из 9.

## Что сделано ветками до этой — не задето

Прогон всей `tests/design` зелёный, то есть на месте: сохранение курируемых данных
(`$extensions`, ключи yaml), отказы с кодом 3 по конфигу и чужой ДС, фильтр скрытых
переменных, рекурсивный резолв ссылок с циклами и глубиной, конфигурация профилей,
устойчивость порядка ключей к хеш-сиду.

Границы соблюдены: `templates/`, `design-systems/`, чужие репозитории не тронуты,
в `main` ничего не уезжало, ветка не пушена.

## Что осталось за рамками

Групповые `$description` и `$extensions` (то есть на узле-группе, а не на токене)
теряются при слиянии режимов всегда — цикл пропускает все ключи на `$`. Это
законный DTCG, потеря настоящая, но она **не про расхождение режимов**: происходит
одинаково во всех режимах и была до этой ветки. В объём задачи не входит, молча
расширять не стал. На закоммиченных ДС таких узлов нет.
