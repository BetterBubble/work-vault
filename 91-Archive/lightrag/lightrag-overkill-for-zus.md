# Решение: LightRAG для Залога Успеха — overkill, откладываем

> ⚠️ **ПЕРЕСМОТРЕНО 2026-07-01 → [[0002-zu-lightrag-graph-rag]].** Условие пересмотра ниже («делать, только если клиент явно попросит») **сработало**: тех-лид ЗУ Василенко предложил LightRAG, руководитель одобрил развёртывание для сравнения по данным. Это решение сохранено как история; актуально — ADR-0002.

Дата: 2026-07-01. Источник: [[call-2026-07-01-daily-baseline]].

## Решение
LightRAG (graph-based RAG) сейчас **не внедряем** в Залог Успеха.

## Обоснование
- Текущий baseline уже даёт хорошие метрики: Recall 0.97 (семантика), клиентские вопросы 0.94.
- Вопросы клиента фактологические — без сложных многошаговых связей, ради которых нужен граф.
- Прирост качества в гибриде обеспечивает reranker, а не графовые связи.

## Условия пересмотра
- Делать только если **клиент явно попросит**, и после его ответа.
- Предварительно оценить трудоёмкость реализации (в фоне).

## Действие
Оформить внутреннее письмо-статус: как замерить текущий baseline + теоретическое обоснование, почему LightRAG здесь overkill.
