# Helm — операторская консоль ревью (Настройки как HITL): дизайн

Спроектировано в обсуждении 2026-07-08. **Статус: дизайн согласован, ADR-кандидат, не реализовано.** Идея пользователя: Настройки = место, где оператор апрувит/правит/добавляет данные (строки+связи), в которых сервис не уверен. Обобщает уже-существующий «операторский гейт» (confidence=check, Need candidate, фаззи-связи, генезис, дедуп) в единый пульт. Связано: ADR-0001 (`docs/adr/0001-conformance-requirement-model.md` — источник `overall`), [[Helm — инжест Need-потребности (механизм готов, черновик на отсмотр)]], [[Helm — клиентский слой Этапа 2 (готово в ветке, ждёт данных)]].

## Назначение
- [decision] Настройки = операторская консоль ревью (human-in-the-loop) для НЕуверенных/деривативных данных, разбитая по вью. «Требует проверки» — не новая сущность, а сбор существующих флагов неуверенности (`confidence=check`, `status=candidate`, фаззи/unmatched, дубли).
- [decision] Попутно закрывает дыру ADR-0001: решение оператора по ячейке = источник **`overall`** (согласованный вердикт).

## Два авторитетных слоя (оба переживают пере-ингест)
- [decision] **Слой А — алиасы/мердж** (расширяем существующую таблицу `alias`, 445 строк): `raw_key → canonical`, применяется НА ЗАГРУЗКЕ (resolve-on-ingest, пере-привязка). Действия: **merge, split (размёрджить ошибочное), set-canonical**. Расширить на клиентов/компоненты/требования/людей.
- [decision] **Слой Б — решения/overrides** (новый, одна generic-таблица): `(entity_type, стабильный_ref, тип[approve|edit|add|reject|promote], значение_оператора, доказательство_на_момент, кто, когда, причина, статус[pending|approved|stale|rejected])`. Применяется НА ЧТЕНИИ/СТАТУСЕ (overall-вердикт, candidate→active). Аудируемо.

## Две поверхности (это одна таблица Б под фильтрами)
- [decision] **Очередь ревью** (на вью) = `status=pending`. Тает, сходится.
- [decision] **Вайт-лист** = `status=approved` — редактируемый пульт решений; `stale`-флаги наверх («данные изменились с момента апрува»). Массовая ревизия.

## Жизненный цикл item’а
- [decision] `pending → approved (применяется) → пере-прогон с новым доказательством → stale (решение ДЕРЖИТСЯ, дэш не мигает, подсвечено) → оператор подтвердил/переделал → approved`. Плюс `rejected`. **Дэш никогда не мигает молча.**

## Анти-treadmill правила (гарантия «не бесконечно») — СОГЛАСОВАНО
- [decision] 1. **Авто-пасс согласия:** два согласных источника (agent==internal) → пасс; одиночный `high` → пасс; одиночный `check` или конфликт → в очередь.
- [decision] 4. Изменилось доказательство → **флаг в вайт-листе, не заново в очередь**.
- [decision] 6. **Приоритет = важность×неуверенность: важное по умолчанию** (пилот-крит+высокий приоритет+расхождения) + **«показать все»** + **сортировка**.
- [decision] Групповые действия (пачкой), стабильный ключ item’а (контент-хеш/натуральный) → апрувнутое не переспрашивается.

## UI-форма
- [decision] **Гибрид гранулярности:** очередь по ячейкам `(треб×комп×трек)`, но **группировка по требованию** (карточка). Контекст в карточке (доказательство agent, комментарий, deep-link) + **предзаполненная догадка** → апрув = один клик.
- [decision] Мердж-кандидаты — **по кнопке «найти похожие»** (фаззи по имени/ИНН), не авто. Split — из канон-карточки.
- [decision] **«Добавить»** (тип=add в слое Б) переживает пере-прогон; сервис сам предлагает кандидатов на добавление (требование без оценки → «добавить вердикт?»), ручное «с нуля» — только для реально неизвестного.

## Ценность (замыкание петли)
- [decision] Решение сразу отражается в дэше (ячейка → согласованный overall, позеленела). Оператора ведут туда, где суждение решает. Вайт-лист копит **ground-truth** → позже до-тюн agent/авто-резолва (консоль сама себя разгружает).
