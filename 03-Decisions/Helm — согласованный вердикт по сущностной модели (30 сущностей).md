# Helm — согласованный вердикт по сущностной модели (30 сущностей)

Зафиксировано 2026-07-06. Арбитраж тимлида (канон+данные+код) поверх независимой панели 4 бизнес-ролей IVA. Выход: `data/concept-entity-provenance.md` + Artifact. Итог: 11 ✓ готово / 16 ⚙ уточнить / 3 ⚠ переделать.

## Принятые архитектурные решения
- [decision] **Продукт — 5 канонических (One/Mail/MCU/CS/Largo), НЕ 16.** Осознанное укрупнение для витрины ГД (решение оператора). Реальный портфель IVA шире (терминалы/SBC/GPT — панель нашла 11-16), но под-линейки — атрибут, не отдельные продукты.
- [decision] **Initiative — единая единица-агрегат, НЕ разделять** на эпик/цель/сделку. Источники (Эпик/Цель/Сделка/Requirement) остаются отдельными сущностями; Initiative ссылается на них genesis-рёбрами с `genesis_source` (провенанс), не поглощает. Обоснование: ценность инициативы («золотой эпик» = сходятся цель+деньги+работа) считается только при единой точке сборки. Защита: жёстко хранить genesis_source, не смешивать в отображении.
- [decision] **Цель и Директива — ДВЕ сущности** (по канону). Цель = что достичь (стратегия/OKR, живёт долго). Директива/поручение = что поручено на встрече (MeetingDecision, привязка к дате). В данных совпали (ceo_directives) — артефакт первой встречи ГД. Ребро: Директива → уточняет/порождает → Цель/Инициатива.
- [decision] **ЕОЛ — роль-владелец Блока** (eol_email→Человек), НЕ отдельная сущность.
- [decision] **Организация — разметить CompanyRole** (мы/клиент/партнёр): развести внутренние юрлица IVA и клиент-юрлица.
- [decision] **Signal — технический ETL-слой**, не показывать в витринах ГД.

## ⚠ Переделать (3): ЕОЛ (→роль), Организация (→CompanyRole), Conformance (нет данных — трек C1 + фикс SCIP KMP<RN).

- [plan] Механика: симптомы → кластеризация по проблеме → Need-кандидат → гейт оператора. Дедуп по проблеме, не по решению.
- [plan] Добрать ИЗ выгрузки (есть, не используем): **проигранные сделки** (стадия «Отменено» 602 в crm_deals), critical_cases, fr_backlog.
- [followup] Внешне нужно: **тела вики/Confluence** (есть 3/3154) — даст видение PO/аналитиков (потребности «сверху», не только симптомы из поддержки).
