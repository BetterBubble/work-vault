# FR-postanovka SKILL — отчёт

## Что создано
Файл `.claude/skills/fr-postanovka/SKILL.md` (191 строка) — well-crafted
инструкция для Claude Code. Скилл — «водитель»: оркеструет тулы analyst-MCP (ИВА)
и собирает из их данных ЧЕРНОВИК постановки (FR). Python-логики генерации нет,
только лёгкая композиция фактов из тулов (по ТЗ лида).

## Структура SKILL.md
- **Frontmatter:** `name: fr-postanovka`, `description` — когда применять
  (сырое требование аналитика → черновик постановки ИВА + gap-вопросы).
- **Когда использовать** — вход (сырое требование, «пустое окно»), выход
  (черновик FR + недостающие секции), предусловие (analyst-MCP подключён).
- **Таблица тул → секция FR** — 12 тулов analyst-MCP с указанием что даёт и в
  какую секцию ложится + примечание про glossary/термины.
- **Поток 7 шагов** (маппинг тул→секция):
  1. Понять — `analyst_context` + `requirement_coverage` (+glossary) →
     Начальная постановка + вердикт новое/доработка (`is_new`).
  2. Gap-чек (ключевой) — `gap_questions` → показать пробелы + вопросы (актор,
     отказ, нагрузка, безопасность, миграция, релиз/клиенты), ЯВНО спросить
     аналитика ПЕРЕД сборкой → подсекция «Вопросы» + пометки [уточнить].
  3. Системы — `affected_systems` + `arch_container` → Серверное описание + ФТТ.
  4. Прецедент — `nearest_spec` → взять за основу и адаптировать.
  5. Координация/срок — `who_to_involve` + `effort_hint` (справка, НЕ оценка).
  6. Собрать черновик по скелету с цитатами [n], неуверенное → [уточнить].
  7. Ревью аналитиком + дозапрос тулов по ответам на gap.
- **Скелет черновика FR** (канон ИВА, проверен на IVCS):
  Метаданные (Заказчик · Представитель · Задача Jira · Best practice ·
  IVA MCU Guideline · Серверное описание) →
  Требования (1. Начальная постановка + Вопросы · 2. БФТ · 3. ФТТ «Система
  должна…» · 4. НФТ · 5. Интерфейсные) →
  Дизайн-спецификация (1. Функциональный · 2. UI · 3. Клиентский рабочий
  процесс) → блок Источники [n].
- **Правила честности** (6 пунктов): цитата на каждый факт; нет данных →
  [уточнить у пресейла/заказчика]; риски/contradiction — кандидаты на проверку;
  `effort_hint` — справка, не оценка; gap до сборки; скилл не пишет финал за
  аналитика; дисклеймеры тулов не терять.

(ветка `feat/analyst-mcp-server`): `analyst_search`, `analyst_context`,

реализованы (планируемые). Скилл написан под полный набор из ТЗ лида — под них
готов, как только тулы появятся.
