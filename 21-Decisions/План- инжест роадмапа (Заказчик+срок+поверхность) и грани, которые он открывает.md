## Грани/связи, которые открываются (соединяет 3 мира: соответствие · клиенты · сделки)

| # | Связь | Что даёт |
|---|---|---|
| 1 | Заказчик → **RequirementClient оживает** | ось «Заказчик» в многомерном соответствии |
| 2 | Клиент × verdict | **«Готовность по пилоту»**: N требований, X% готово |
| 3 | Срок (Статус=квартал) × verdict | **риск-панель**: критично+Q2 2026+absent = красный |
| 4 | Крит.(Пилоты) → **ADR-0002** | вход «важность» для приоритета очереди ревью |
| 5 | Поверхность ← **Component** | rn-*→mobile, web-*→web, desktop. Новая ось |
| 6 | Клиент × поверхность | **ожидания в разрезе форм-фактора** (killer-cross) |
| 7 | «Общие запросы» → **Need/Бэклог** | cross-cutting потребности с спросом неск. клиентов |
| 8 | AltLinux/Windows | под-разрез desktop по ОС → импортозамещение/ИБ |
| 9 | Менеджер → **ComponentPerson** | ownership/ответственность на требование |
| 10 | Версия | сверка Requirement.generation с Excel (data-quality) |
| 11 | Клиент × **DealPipeline** | **мост CIO-соответствие ↔ CCO-pipeline через клиента** |

Сильнейшие: №6 (клиент×поверхность×готовность к сроку — связка ожидания↔требования) и №11 (соответствие↔сделки).

## План (после 3 веток Фазы 1 — влиты/задеплоены da1ba22)
- **Фаза A — Инжест роадмапа → клиентский слой**: loader Excel → match требования (Функция+Компонент+Версия / №) → RequirementClient(pilot_critical) + target_quarter из Статус. Сплит мульти-клиента, фильтр шума, unmatched → operator_review.
- **Фаза B — Поверхность как ось**: derive surface (Component+текст) → requirement↔surface (M:N) → фильтр/ось + summary в ConformanceV2.
- **Фаза C — Ожидания клиента**: client→(поверхности+вес+дедлайн) из заметок → вью «клиент × поверхность × готовность к сроку».
- **Фаза D — Риск-панель**: target_quarter × verdict × pilot_critical → «критично, не готово, срок близко».
Порядок A → B → C → D; A+B — ядро.

## Какую вью трогает каждая фаза (важно!)
- **A** — в основном **многомерное соответствие** (ось «Заказчик» + готовность по пилоту); ПОПУТНО кормит **операторскую консоль** (Settings): unmatched-клиенты в очередь + pilot_critical как приоритет.
- **B** — **только многомерное соответствие** (чистая новая ось «поверхность» + summary).
- **C** — **выходит за рамки матрицы**: клиент-центричный ракурс (карточка пилота, а не матрица требований). Развилка: pivot ВНУТРИ соответствия vs отдельная вью «Пилоты/Клиенты». РЕШИТЬ.
- **D** — **отдельная риск-панель** + мост к **Pipeline (CCO)**: сделка зависит от неготовых требований к сроку. Уже не соответствие, а пересечение соответствие×продажи.
Итог: A/B = ядро соответствия; C = новый клиент-ракурс (развилка); D = риски + связь с Pipeline.

## Data-quality / что уйдёт в ревью
Мульти-клиент сплит; шум в «Заказчик»; поверхность-дерайв (fallback по тексту неуверенный); unmatched требования; сверка поколения. Всё спорное → operator_review (ADR-0002), не молча.
