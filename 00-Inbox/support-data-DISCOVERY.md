# Support-MCP — разведка ДАННЫХ сервис-деска (READ-ONLY)

> Все примеры обезличены: имена клиентов → `<клиент>`, контракты → `<контракт>`, ФИО/тел/почта → `<PII…>`. Сырые PII-строки в отчёт не переносились.

## TL;DR
- **Материал для прецедент-корпуса «как чинили» почти отсутствует.** Единственный источник текста решения — колонка **«Решение» в crm_open**, где заполнено всего **23** строки (реальных, без placeholder — **21**). И эта колонка **не доходит до витрины** (маппер её не читает, в модели нет поля).
- **naumen (42 277 строк) резолюций не содержит вообще** — единственное текстовое поле «тема», и это дайджесты/анонсы/заголовки заявок, без описания решения.
- Значит прецедент-корпус питать сейчас нечем; нужен новый источник резолюций либо доработка ingest под «Решение» (но объём 21 запись — мизер).

## 3. Пробел ingest (`src/helm/ingest/servicedesk.py` + модель `SdRequest`)

**`_crm_open_mapper` (строки 145–181):** читает `Комментарий клиента → comment`, но **колонку «Решение» НЕ читает вообще**. Также маппит: Заявка→ext_id, Статус, Группа статуса, Дата создания, Возраст, Приоритет, Тип, Заголовок→title, Код клиента, Клиент, Продукт, Тариф, Контракт, Исполнитель, team (фаззи ФИО→teams.csv), Placeholder/test→is_test.

**`_naumen_mapper` (строки 89–114):** taskid→ext_id (`SD-<id>`), статус, создана, age, категория, подкатегория, приоритет, срок→due, просрочена→overdue, percent, закрыта→closed, **тема→title**, автор→author. (Резолюции в источнике нет — читать нечего.)

**Модель `SdRequest` (`src/helm/infrastructure/db/models.py:795–842`):** есть `comment` (Text) = «Комментарий клиента», но **поля `resolution`/`solution`/переписки НЕТ**. Текстовые поля витрины: только `title` и `comment`. Есть `theme_id` (FK на sd_theme) — SD5 авто-кластер тем застрявших обращений (проставляет пайплайн).

> **Дыра:** даже те 21 реальную резолюцию из crm витрина не сохраняет — колонка «Решение» отбрасывается на ингесте, и класть её некуда (нет поля в модели). Прецедент-корпус «как чинили» строить не из чего без (а) новой колонки resolution в SdRequest + чтения её в маппере, (б) а лучше — нового источника с реальными решениями (текущий объём 21 записи нерепрезентативен).

## Вывод: чем питать прецедент-корпус и где дыры
1. **Единственный текст «как решали» = crm «Решение» → 21 реальная запись.** Мало и нерепрезентативно.
2. **Эта колонка теряется на ingest** (маппер не читает + нет поля `resolution` в `SdRequest`). Даже имеющееся не доезжает до витрины.
3. **naumen резолюций не содержит** — только «тема» (заголовки/анонсы). 42k строк объёма, но для прецедентов бесполезны.
4. **«Комментарий клиента» (782/782)** — это формулировка проблемы клиентом, не решение; может служить входом для матчинга «похожее обращение», но не выходом «как чинили».
5. Для реального прецедент-корпуса нужен **новый источник с резолюциями** (переписка/итоговое решение по обращению) — в текущих двух выгрузках его нет.

### ⚠️ Замечания по безопасности
