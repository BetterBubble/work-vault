## 1. Ветка/worktree — ✅ ок

## 2. Разрыв схемы changelog — ВАЖНО, делаем чтобы РЕНДЕРИЛОСЬ
Цель — чтобы данные экстрактора реально попадали в текст `build_document` (не пустой changelog). Поэтому НЕ оставляем разрыв «на потом»:
- Выдавай `ch` в формате, который текущий прод-`_render_changelog` реально читает (ты его смотрел — плоские записи по смене поля). Денормализуй author/created в каждую запись: `{field, from, to, author, created}` (одна запись на изменение поля).
- **Добавь юнит-тест**, который прогоняет твой `ch` через реальные `_render_changelog`/`build_document` (импорт из `infrastructure.rag2.ingest`) и проверяет, что в тексте есть **сами значения** changelog (не только заголовок «История изменений»). Это и есть проверка, что разрыва нет.
- `ingest.py` НЕ трогаешь. Канон я поправлю на плоский формат — приоритет у того, что реально рендерится.

## 3. Epic customfield — ✅ как предложил
`jira_issue_to_record(..., epic_field: str|None=None)` + fallback `fields.epic.key`. `par`(parent) отдельно, не путать. Реальный `customfield_id` для ИВА я добуду на живом прогоне (доступ к Jira есть) и передам параметром — ты его не хардкодишь.

## 4. Exclusion list — ✅ как предложил (config-driven, не хардкод)
- Список — через `QualityConfig.exclude_spaces` / `--exclude-spaces-file`, дефолт пустой. Не зашивать в git магией — правильно.
- Универсальные фильтры всегда: **personal-пространства** (лучше по `space.type=="personal"`, если поле доступно; иначе fallback на префикс ключа `~`) + 🔴 в названии.
- Финальный боевой список исключений — в канон-заметке «RAG#2 pipeline… канон», раздел «Финальный список исключений». На прогоне подложу его как `--exclude-spaces-file`. В код не зашивай.
