# Аудит интеллектуальных фич — досье фичи

**Статус: в работе.** Блокер снят 03.08 ~12:30 — руководитель прислал слайд.

## Зачем

У продуктовых направлений (мессенджер, почта, ВКС и другие) есть набор «интеллектуальных» фич,
которых хотят сейлы — прямо названа **суммаризация сообщений**. Руководителю нужно понять,
**что из этого уже построено**, что надо строить, и сколько это стоит.

Ключевая гипотеза руководителя: **часть уже реализована и просто «зарыта внутри кода»**.
Первый шаг — не проектирование, а поиск.

### Найден источник «задач от сейлов»
Руководитель говорил, что часть хотелок «есть в трекере». Найдены два реальных механизма:
- **Jira-проект `SCORE`** — очередь запросов на скоринг фич со статусами `Оценка Sale` →
  `Оценка Product` → `Оценка Development` → `Score Result`. Пример прямо по теме:
  **`SCORE-662`** «ВКС + почта = Автоматическая отправка протокола/записи/саммари/файлов по
  итогам встречи на почту/таск-менеджер», статус «Оценка Product». Регламент —
  Confluence `140970118`, `140970479`, `192547296`.
- **Отчёты по встречам с заказчиками** (пространство `IVAPROJECT` → ЗАКАЗЧИКИ): таблицы
  «требование → есть / в roadmap / нет → срок». Например `192547262` (МосБиржа) и
  `192547438` (RFI), `195429221` (Roadmap Discussion 21.04.2026).
