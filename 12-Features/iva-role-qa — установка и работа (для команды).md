# iva-role-qa — установка и работа

Профиль автоматизации автотестов для **KMP-клиента iva-one** (репозиторий **one-web-kmp**), стек **pytest + Playwright** (canvas-рендер KMP). Ставится в Codex через каталог, без ручного копирования файлов. Ведущий CLI — **Codex**; «умные» шаги профиль делает через трёх субагентов.

> **Про стек и репозиторий.** Профиль настроен на стек **pytest + Playwright (canvas)** — это репозиторий **one-web-kmp** (новый KMP-клиент). Angular-клиент (`one-web`, стек pytest + Selenium) — это другой стек, здесь не покрыт.

---

## 0. Что нужно заранее

- **Рабочее окружение one-web-kmp** — venv/autocore, `playwright-cli` / `allurectl` / `glab`, настроенный CI. Профиль окружение НЕ поднимает, рассчитывает на готовое.
- **Codex CLI** — установлен, вы под ним работаете.
- **Токен на подключение к каталогу** (`TACTICUM_TOKEN`) — ваш личный. Если вы уже пользуетесь `tacticum-mcp` для других профилей, это тот же токен, новый не нужен.
- **Три доступа** (пропишете как секреты на шаге 4): Allure TestOps (apitoken), личный Atlassian PAT для Jira, доступ к факт-базе.

---

## 1. Подключить каталог (tacticum-mcp)

В корне репозитория one-web-kmp в файл `.codex/config.toml` добавьте:

```toml
[mcp_servers.tacticum-mcp]
url = "https://mcp.tacticum.dev/mcp"
bearer_token_env_var = "TACTICUM_TOKEN"
```

И экспортируйте свой токен:

```bash
export TACTICUM_TOKEN="phk_…"   # ваш личный токен
```

---

## 2. Поставить профиль

Дайте Codex-агенту в этом репозитории задачу:

> «Поставь профиль iva-role-qa».

Агент сам:
- через `whoami` видит вашу установку профиля в каталоге;
- вытягивает содержимое (`pull`) и раскладывает скиллы в `.agents/skills/` и трёх субагентов;
- обновляет входные точки (`AGENTS.md` / `.codex/config.toml`).

После этого **перезапустите Codex**, чтобы скиллы и субагенты попали в сессию.

**Проверка установки:** попросите агента перечислить доступных субагентов — должны быть три: `codebase-analyst`, `dom-explorer`, `code-writer` (модель `gpt-5.4`).

---

## 3. Прописать секреты

Профиль сам рендерит конфиги, но токены подставляете вы — через env или через gitignored-файл `./secrets.yaml` (форма — в `secrets.yaml.example`, секция `testops:`).

```bash
# Allure TestOps (чтение ТС + публикация автотестов)
export TESTOPS_ENDPOINT="https://<ваш-testops>"
export TESTOPS_TOKEN="<apitoken>"          # apitoken из TestOps, не пароль
export TESTOPS_PROJECT_ID="<числовой id>"

# Atlassian PAT для Jira (заведение/обновление дефектов) — личный
export JIRA_URL="https://jira.iva.ru"
export JIRA_PERSONAL_TOKEN="<ваш личный PAT>"
```

Доступ к факт-базе (read-срез для ревью покрытия) идёт под тем же `TACTICUM_TOKEN`.

`secrets.yaml` уже в `.gitignore` профиля — секреты в репозиторий не попадут.

---

## 4. Первый прогон (проверка, что всё работает)

В one-web-kmp с активным venv, на живом тест-кейсе:

1. **`write-autotest`** — дайте URL тест-кейса из TestOps → «напиши автотест». **Ок:** появился каталог задачи с анализом/локаторами, тест-функция в `tests/test_<feature>.py`, `pytest --collect-only` зелёный; в трейсе видно, как спавнятся субагенты.
2. **`run-tests`** — прогон с браузером + сбор Allure-результатов.
3. **`fix-failed-test`** (если упало) — разбор причины по категориям + правка до зелёного ре-прогона.

Если субагенты видны и цепочка отработала — профиль на месте.

## Механика: что умеет и как этим пользоваться

**Генерация тестов**
- `write-autotest` — по ссылке на тест-кейс в TestOps пишет готовый pytest+Playwright тест.
- `batch-autotest` — то же пачкой по фильтру TestOps (веер тестов за один заход).

**Как профиль «понимает» интерфейс** (три субагента)
- `dom-explorer` — заходит в реальный UI браузером и снимает актуальные локаторы (не выдуманные).
- `codebase-analyst` — read-only инвентарь страниц / флоу / i18n / enum + пробелы.
- `code-writer` — пишет код тест-слоя.

**Прогон и починка**
- `run-tests` — прогон с браузером, сбор Allure-результатов.
- `fix-failed-test` — диагностика падения по категориям и починка до зелёного.

**Интеграция с процессом**
- `jira-issue-autotest` — из Jira-issue разворачивает автотесты и гоняет пайплайн.
- `prepare-mr-branch` — готовит чистую MR-ветку.
- Заведение/обновление дефектов прямо в **Jira**, публикация прогонов в **Allure TestOps** — единый след по каждому тесту.

**Ревью покрытия**
- Узкий read-срез факт-базы требований: статус покрытия требований автотестами, пробелы, смежные постановки — видно, что уже покрыто и где дыры, чтобы дополнить тест-кейсы предметно.

**Поддержка окружения**
- `rebuild-autocore` — пересборка autocore-venv (на Codex запускается вручную).
- `retro` — housekeeping.

## Обновление профиля

Когда выйдет новая версия — не нужен новый провижн: дайте агенту задачу обновить профиль (pull с обновлением), он подтянет новую версию из каталога.

---

## Если что-то не встало

- Субагенты не видны → перезапустите Codex; проверьте, что задача установки отработала без ошибок.
- TestOps/Jira-запросы падают на авторизации → проверьте, что заданы `TESTOPS_*` и `JIRA_*` (env или `secrets.yaml`).
- `tacticum-mcp` не отвечает → проверьте `TACTICUM_TOKEN` и блок `[mcp_servers.tacticum-mcp]` в `.codex/config.toml`.

По вопросам — пишите, разберёмся.
