## Суть

Бот-участник дизайн-сессии в чатах iva-one (заказчик + архитектор + аналитик + тимлид): отвечает по корпоративному контексту через `helm-analyst`, непрерывно ведёт кандидатов в решения (детекция по чату), доводит сессию до FR и задач в трекере. Плюс **«Живая документация»** — агент, отвечающий на комментарии к документу в Confluence из журнала обсуждений.

Три поверхности (IDE-агент роли ∥ session-bot ∥ «Живая документация») — один контекст. Дорогой актив — **журнал обсуждений**; строится первым.

## Деплой: всё в helm, ни одного нового рантайма

- **Журнал** — Postgres helm (рядом с `meetings`/`media_transcript`/`dialogue`); чтение — MCP `discussion_*` как расширение `/mcp/analyst`.
- **session-bot** — третий бот helm по паттерну «Поддержки» и `bot_iva_write`: webhook-роут `/api/bot/session/webhook`, исходящие через Bot API платформы, карточки = `ReplyKeyboard`. **Клиентская разработка iva-one не нужна.**
- **«Живая документация»** — воркер полосы `bot_task`, поллинг комментариев Confluence раз в 5 минут; техучётка со скоупом только `confluence_add_comment`.
- **Леджер решений** — arch-mcp (SoR), доступ через REST-фасад `dev.tacticum.dev`; единый словарь диспозиций с контуром ревью ADR-0064.

## Транскрибация — Фаза T (решение owner 2026-08-06)

v1 работает на чат-детекции. Доступ к транскрибации ВКС (чат ONE → «Создать ВКС» → MCU) проектируется **отдельной дизайн-сессией, проводимой в чате с уже работающим ботом** — его первый боевой кейс. Собранные факты — ADR-0065 (Контекст, Р.10): MCU `PhraseEvent` с авторством, хранение ресурсом `TRANSCRIPT`, app-JWT, поллинг конца конференции; блокеры: боты не приглашаются в звонки, системные сообщения ботам не доставляются, конференц-событий в Bot API нет. Ручной мост уже работает: запись встречи → конвейер `/transcribe` helm.

## Блокеры до старта Фазы 1 — закрыты все (2026-08-06)

1. ✅ Policy кнопки фиксации — **утверждена owner**: архитектор/аналитик/тимлид жмут `enforce` сразу, заказчик — `pending` с approve любым из трёх; классификации решений по типам в v1 нет.
2. ✅ Retention журнала — **180 дней** (единая политика с `/transcribe`).
3. ✅ Baseline — **замерен** по Jira IVAONE (Analytics Task, история статусов; BRD § 9.0): работа аналитика ~7 дн (медиана), согласование 14 дн (хвосты 99–226), активный цикл постановки 75 дн; у разобранного кейса 4 из 7 порождённых задач — Rejected. Целевые значения пилота пересчитаны от этих цифр.

## Связанные задачи (не блокеры)

- Техучётка «Живой документации» + OAuth-согласие (порядок: Jira → Confluence) — к деплою Фазы 2.
