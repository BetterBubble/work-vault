# Дисциплина заполнения Jira — отчёт по трём репозиториям

> Основа: 29 тикетов, прочитанных через iva-mcp 2026-07-23, + недельная git-история
> (14–23.07) репозиториев iva-one (web), kmp, messenger (iOS). Детали и дословные
> тексты — в `gate-calibration-inputs.md`. Формат: что обнаружено → чем грозит
> (для агентного конвейера в первую очередь) → что предлагаем.

## Сводная картина

| Репо | Баг-тикеты (QA) | Задачи разработки | Работа мимо трекера (за неделю) |
|---|---|---|---|
| web (iva-one) | стабильный шаблон Шаги/ФР/ОР | половина — пустые или заголовок | ~2 NO-TICKET коммита в master |
| kmp | образцовые (шаги+ФР/ОР+аттачи) | однострочные («Редизайн звонков») | **~50% коммитов недели без тикет-рефа** (Room 3, Centrifuge, стабилизация, сборка, релизы) |
| ios (messenger) | подробные, с видео и логами | без описания или гипотеза-однострочник | perf-инструментарий, RPC-фиксы, конфиги — без тикетов |

Общий паттерн во всех трёх репо: **QA пишет дисциплинированно, разработка ставит
задачи заголовками**. Хуже всего документированы ровно те классы работ, на которых
падает агентный конвейер: рисерч, рефакторинг, инфраструктура.

## web (iva-one)

**Что хорошо.** Баг-тикеты единообразны: «Шаги / ФР / ОР» присутствуют в 9 из 13
прочитанных; шаги короткие, но воспроизводимые (12570, 12629, 12572, 12638, 12635).

**Проблемы:**

1. **Пустые «Задачи».** IVAONE-12770 (рисерч без MCU) — описание пустое; IVAONE-12059
   (миграция DsDivider) — только заголовок. → Агент получает на вход одну строку и
   генерит «воду» — это прямая причина жалобы «формальные артефакты».
2. **Тип тикета врёт.** Рисерч и задача-по-макету заведены как «Ошибка», расследование —
   как «Задача». → Автоматике нельзя опираться на тип; режим работы придётся
   определять по тексту.
3. **Несколько дефектов в одном тикете.** IVAONE-12634: датапикер + отдельный баг
   ключа локализации, плюс «задеты все датапикеры». IVAONE-12568: p.s. расширяет скоуп
   на вложения MCU. → Скоуп задачи открытый, план и оценка невозможны без уточнений.
4. **ТЗ-скриншот.** IVAONE-12691 — описание из одной картинки. → Текстовый конвейер
   слеп; нужен либо разбор вложений, либо запрос текста.

**Предложения:** обязательный минимум описания для типа «Задача» (сейчас шаблон есть
только у багов); правило «1 тикет = 1 дефект»; тип «Research» или метка для
исследовательских задач.

## kmp

**Что хорошо.** QA-тикеты федерации (IVAONEHALF-601/602/604) — образец: шаги,
ФР/ОР, аттачи (видео/скрин). Задача 641 (трёхпанельный режим) — редкий пример
внятной постановки фичи: платформы, модуль, три пункта результата.

**Проблемы:**

1. **Эпики-однострочники.** IVAONEHALF-514 «Редизайн звонков» = «Отдельный адаптив
   ui ux под веб» — при этом в репо это серия MR на тысячи строк за 3+ дня. → Ни
   декомпозиции, ни критериев готовности; для агента это чёрная дыра.
2. **Половина недели — мимо трекера.** Миграция Room 3 (с хвостом фиксов на 3
   платформы), reliability-фиксы Centrifuge, кампания стабилизации (утечки памяти,
   god-объекты), ускорение сборки, релизы — всё без тикетов. → История решений живёт
   только в commit message; KB и трекер не знают о самой дорогой работе недели.
3. **Мусорное форматирование.** IVAONEHALF-524 — копипаст-артефакты, битые ссылки,
   «нужен доступ к фигме» внутри ТЗ; тип «Ошибка» у задачи по макету.

**Предложения:** для эпиков — обязательная декомпозиция до задач с ОР (гейт мог бы
это подсказывать); завести практику тикетов на инфра/рефакторинг-кампании (хотя бы
ретроспективно, одной строкой с ссылкой на MR); шаблон задачи с полем «критерий
готовности». Отметим: команда сама завела `lite-task-workflow` в доках агентов —
дисциплина процессов у них живая, дисциплина трекера отстаёт.

## ios (messenger)

**Что хорошо.** QA-баги подробные: 12520/12565/12179 — шаги + видео + окружение
(сборка, девайс), 12150 — cross-device сценарий + приложенные логи. Это лучший
QA-уровень из трёх репо.

**Проблемы:**

1. **Задачи разработки без ТЗ.** IVAONE-9806 (зум демонстрации) — описания нет
   вообще; реальная постановка жила в голове разработчика и попала только в промпт
   агенту. IVAONE-11584 (DLP) — описание = две ссылки (wiki, figma). IVAONE-12763 —
   одна строка. → Тикет не является источником требований; при смене исполнителя
   или ретроспективе контекст потерян.
2. **ТЗ-гипотеза вместо требования.** IVAONE-12470: весь текст — «Вероятно, нужно
   добавить черновик на файлы»; реализация — 12 файлов, +1022 строки. → Требование
   и решение перепутаны; агент примет гипотезу за утверждённый дизайн.
3. **Один MR на несколько тикетов — норма.** 12520+12565, 12179+12393. → Трассировка
   тикет↔код размывается; для 12179+12393 два разных симптома оказались одним
   механизмом — это знание нигде не зафиксировано, кроме заголовка коммита.
4. **Битые рефы.** Коммит «[IVAONE-12256] Видео без превью…» ссылается на тикет про
   контракты админ-панели. → Автоматическая привязка коммитов к тикетам ненадёжна.

**Предложения:** те же минимум-требования к «Задачам»; ссылка-ТЗ допустима, но
с одним абзацем резюме в тикете; при закрытии MR на несколько тикетов — комментарий
в каждый с итогом.

## Что это значит для Tacticum

1. Конвейер не может рассчитывать на Jira как на источник ТЗ — реальный вход это
   промпт пользователя, тикет лишь подспорье. Гейт режимов обязан уметь сказать
   «ТЗ недостаточно» и задать вопросы (см. `workflow-modes-proposal.md`).
2. Самые недокументированные классы работ (рисерч, рефакторинг, инфра) — ровно те,
   под которые мы проектируем новые режимы; там агент чаще всего останется без ТЗ.
3. Отчёт можно показать лидам всех трёх команд как аргумент к минимальным шаблонам —
   это дёшево и поднимет качество работы и людей, и агентов.
