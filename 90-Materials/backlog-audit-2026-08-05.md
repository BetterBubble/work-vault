## Как читать оценки

| Ось | Шкала |
|---|---|
| **Эффект (Э)** | 1 — косметика; 2 — раздражает, обходится; 3 — заметно мешает работе роли; 4 — блокирует часть пользователей или ломает щит от регрессий; 5 — ложный успех / полный отказ у всех |
| **Сложность (С)** | 1 — правка в 1-2 файлах, ≤ полдня; 2 — до дня, с тестом; 3 — несколько дней, затрагивает контракт; 4 — неделя+, дизайн-решение; 5 — эпик |

**Приоритет** выводится из пары: P0 — высокий эффект при любой сложности либо средний эффект при С≤2; P1 — заметный эффект, обозримая цена; P2 — реальный дефект без горящего следствия; P3 — хвост.

### Три ловушки параллельной работы

1. **Голден-гонки.** `apps/backend/tests/e2e_install/golden/` перегенерируется почти при каждой правке контента профиля. Регенерировать **последним шагом** перед мержем; после ребейза — заново; такие PR мержить по одному.
2. **Лейн без роли не доезжает.** Ребро `depends_on` фиксируется в момент сида, версия базы в манифесте роли не указана. Бамп лейна без бампа зависящих ролей до пользователей не доходит **при всех зелёных проверках**. Лейн и роли — одним PR; выкатка: лейн → роли → перепин → pull. Автопроверки нет — это и есть **#775**.
3. **Разводить по владельцам контента, а не по номерам задач.** Две задачи в одном лейне у разных людей дают конфликт в manifest и CHANGELOG на каждом коммите.
