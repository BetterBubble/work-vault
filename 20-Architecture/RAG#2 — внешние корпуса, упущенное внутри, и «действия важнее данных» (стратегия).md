# RAG#2 — внешние данные, упущенное внутри, действия > данные

Вход от пользователя + заземление через iva-mcp. Дополняет [[rag-2-dlia-analitika-sloi-dannykh-za-predelami-topologii-glossarii-dizain]].

## Архитектурный поинт (подтверждён фактом)
Публичная дока RAG#1 (iva.ru/docs) — уже в on-prem: коллекция `iva_docs__bge_m3_1024` = 8272 точки, RAG#2 её уже федеративно видит (`docs_ask`). Контур односторонний: **публичное ВНУТРЬ можно** (не нарушает ADR-0003), наружу внутреннее — нельзя. Дока = «как система ведёт себя СЕЙЧАС» → аналитик обязан знать «как есть», прежде чем писать «как должно». Краулер пишется ОДИН раз → питает оба рага → **аргумент делать RAG#1 первым** (он ещё и источник для RAG#2). Тем же краулером — внешняя публичная нормативка/протоколы.

## Внешние корпуса — приоритет
1. **Нормативка/регуляторика** — самое важное («почему нельзя» снаружи: 152-ФЗ, ФСТЭК, КИИ, реестр Минцифры, импортозамещение, ГОСТ). НО заземление: **applied-нормативка уже ВНУТРИ** — спейс **IS** (Information Security: «Подготовка к сертификации», приказы ФСТЭК 17/21/31/239), «Сертификация ... ФСТЭК» (IVCS/SBC), реестры ProductOffice («Артефактриум», МинЦифры/ФСТЭК АС/ГИС/ИСПДн/КИИ), колонка 152 в требованиях. → Приоритет: индексировать внутренний compliance-слой (IS, ProductOffice) — почти в периметре; сырые внешние тексты (приказы/ГОСТ) — публичны, краулером позже.
2. **Стандарты/протоколы** (SIP, H.323, WebRTC, SMTP/IMAP) — стабильный публичный корпус, дёшево, для интероп-требований («работает с Cisco», «по SIP»). Средний приоритет, дёшево.
3. **Док системы-интеграций** (1С/CRM/LDAP-AD; в Jira есть IVA1C, IVACRM). Внешняя вендорская дока. Средний.
4. **Конкуренты** (Zoom/Teams — «как в Zoom») — отложить (шум, маркетинг, меняется).
5. **Тендеры/ТЗ заказчика** — корпус RAG#3, НЕ дублировать.

## Упущенное внутри (конкретные gap'ы)
Наш текущий jira-scope = 14 продукт/dev-проектов. **НЕ входят** (проверено по списку):
- **IVASUP** (поддержка/service desk) — огромный недооценённый сигнал: поток тикетов = что реально болит; «40 обращений по фиче за полгода». Высокая ценность, тот же пайплайн (добавить в priority-list). Объём может быть большой + иная ценность.
- **IVA1C / IVACRM** — интеграционные проекты (половина ответа про интеграцию — в них).
- **Тест-кейсы** (Jira test-issues по контейнеру) → прямой вход в критерии приёмки.
- **Что обещано клиенту** — реестр Helm + вердикты покрытия (`requirement_coverage`, `requirement_client`) → приоритет/срок другие. Данные ЕСТЬ, надо surface.

## ⭐ Действия важнее данных (ключевой вывод — тут ценности больше, чем в ещё одном корпусе)
И критично: **почти всё строится на данных, что УЖЕ есть:**
- **Gap-вопросы к требованию** — сравнить сырое требование с типовой структурой прошлых FR → «не хватает: кто актор, что при отказе, какая нагрузка, нужна ли миграция». Экономит круг переписки с пресейлом. (данные: корпус FR — есть)
- **Проверка на противоречия** — «конфликтует с ADR-N и требованием R-123». Ловить на постановке, не на ревью у архитектора = **самая большая экономия**. (данные: requirement-матрица + ADR/constraint-доки — надо доиндексировать ADR)
- **Ближайший аналог** — «самая похожая постановка год назад, возьми за основу». Аналитик адаптирует, не пишет с нуля. (строится СЕЙЧАС на `analyst_context`/`related_tasks`)
- **Кого дёрнуть** — владелец контейнера + кто вёл похожую задачу. (есть: `affected_systems.owner` + `related_tasks.assignee`) — тривиально, экономит полдня.
- **Оценка по истории** — из выкачанного **changelog** (8693 события у IVAONE) посчитать «похожие задачи в этом контейнере жили в среднем ~3 недели». Справка, не замена аналитика. (данные ЕСТЬ)

## Предлагаемый порядок (синтез)
- **Tier 0 (сейчас, макс ROI, без новых данных):** действия — ближайший аналог · кого дёрнуть · оценка по истории (из changelog); затем gap-вопросы + проверка противоречий (нужен ADR/constraint-индекс).
- **Tier 1 (дёшево, высокая ценность):** глоссарий (харвест+expansion); surface внутр. compliance (IS/ProductOffice) + IVASUP-сигнал + тест-кейсы + «обещано клиенту».
- **Tier 2 (внешнее публичное, тот же краулер, позже):** протоколы (SIP/WebRTC), вендорская дока интеграций, сырые тексты нормативки.
- **Отложить:** конкуренты; тендеры — RAG#3.
