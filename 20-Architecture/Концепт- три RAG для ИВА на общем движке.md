## Статус
Концепт готов, **отправляется руководителю на апрув**. После апрува — правим при необходимости.

**Файл (источник истины):** `helm/docs/iva-knowledge-rag-concept.md` (в репо helm).

## Суть
Три базы знаний (RAG) для ИВА на **одном движке**, тиражируемом под задачи. Движок — **дубль рабочего `rag_eval_service` (codex ЗУ)**, платформу (`knowledge_rag`) пока не используем (вынесена отдельным разделом как целевой путь).

**Водораздел — по контуру данных, не по аудитории:**
- Публичный контур (можно у нас): **RAG#1** — публичная документация `iva.ru/docs`.
- Внутренний контур ИВА (только on-prem, наружу не уходит, vLLM triva / свой Qwen): **RAG#2** (wiki/jira/EVA для аналитиков, MCP-морда), **RAG#3** (пресейл — ассистент требований + чаты/почты, ОДНА морда).

## Ключевые решения
- RAG#3 = **одна морда** (реестр требований HELM + чаты/почты — два источника в одну базу).
- Платформу пока не учитываем — осознанный дубль codex; путь к платформе описан отдельно (морды писать за портом retrieval, чтобы позже сойтись дёшево).
- RAG#2 проектируем **от природы wiki/jira** (реляционный/темпоральный корпус) → hybrid + граф уместны; замер LightRAG на ЗУ (плоская фактология, граф проиграл) сюда НЕ переносится.
- Улучшения над ЗУ: включить reranker, hybrid по умолчанию, структурный чанкинг + богатые метаданные, answer-eval/LLM-judge.

## Проверенная готовность (живьём)
- RAG ЗУ (codex, zu_demo): ✅ работает, 784 чанка, отвечает; reranker выключен.
- iva-mcp (Jira/Confluence): ✅ 72 проекта.
- knowledge_rag (платформа): ✅ 37 тестов зелёные, но живого smoke не было.
- Ассистент требований (helm): ⚠️ только доменный скелет (нет router/Meili/туннеля vLLM).
- LightRAG-стенд (zu_demo): ✅ развёрнут (граф 1302 сущности/1438 связей) — можно замерять на данных ИВА.

## Открытые вопросы (к Фазе 0)
1. Эмбеддер on-prem: bge-m3/TEI (рекоменд.) vs свой Qwen-embedding.
2. Хост on-prem инстанса: adp_emb vs выделенный сервер в контуре ИВА (рекоменд.: выделенный).
3. Финальный внутренний LLM: triva/Gemma vs свой Qwen.

## Фазы
Фаза 0 подготовка (решить хост/эмбеддер/LLM, доступы) → Фаза 1 RAG#1 (docs + краулер) → Фаза 2 RAG#2 (wiki/jira/eva, hybrid+граф) → Фаза 3 RAG#3 (ассистент+чаты/почты).

## Термины
- **EVA / IVA Desk** — внутр. трекер ИВА на CMF (eva.iva.ru), 6634 задачи/25 проектов; оборачивается eva-mcp.
- **vLLM triva** — self-hosted Gemma в контуре ИВА (10.0.196.14:9034), внутренний LLM.
- **codex** — рабочий RAG ЗУ (`rag_eval_service`), донор движка.
