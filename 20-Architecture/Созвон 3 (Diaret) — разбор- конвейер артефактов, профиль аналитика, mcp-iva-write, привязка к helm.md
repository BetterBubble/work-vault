# Созвон 3 с Diaret — структурный разбор

Разбор транскрипта `helm/data/Созвон 3.rtf` + доска-схема. Два независимых прохода (ГД + агент) сошлись. Ждём ADR от руководителя — план уточнится.

## Куда движемся (стратегия)
- **helm = центр требований.** Сводит ВСЕ ~1500 требований по всем продуктам/стекам («монолиз» знаний: RAG по Jira/Confluence/Allure/коммитам, знает C4-архитектуру и контракты).
- **Идея «единый ответственный за требование сквозь все продукты».** Требование может касаться нескольких продуктов (ИВА-Ван = единая апка почта+мессенджер+…; есть отдельные продукты — просто почта; MCU/МСУ — стабильный). Сейчас декомпозицию на 100-500 команд вручную сводят PM-ы → хаос. Целевая модель: один человек сквознячком аккумулирует и рулит командами, видит реализацию требования на всех продуктах разом.
- **Корневая боль:** Солонко зашил генерацию аналитики ПРЯМО в профиль разработчика → обычным разрабам это лишнее и сложно, задача на 20 мин растягивается на 1.5ч. **Решение — выделить аналитику в отдельный профиль.**
- **Приоритет:** «начинаем с того, что больше всего болит» = аналитика. Продуктовую часть (БТ/PO) пока НЕ берём.

## Конвейер артефактов (шаг 2: Аналитик + Архитектор + DevSec)
БТ(вход) → **БРД/БФТ** (Солонко умеет, но НЕ адаптирован под их стандарты) → **ФТ/5ФТ** → **тех.план/спецификация** → **A.C./контракты** (что дёргать/у кого — критично для бэка) → **UC** (use case) → **SD** (sequence diagram) → **CJM** → **Дизайн** (только фронт, по UI/UX rulebook, хранить HTML) → **PIN/план** (комплексный план задач по командам: бэк-Java / фронт-Angular; в Jira → прямо задачи) → **TC/тест-кейсы** (стык аналитик/QA → Allure).
Правило: фронт → нужен дизайн+CJM; бэк(Go) → нужны контракты, дизайн не нужен. Аналитик не просто генерит — смотрит, **согласует** (дизайнеры/архитекторы), умеет протестировать.

## 3 ключевые задачи
### A. Профиль аналитика (ПРИОРИТЕТ №1)
Отдельный профиль (набор скиллов + MCP), выдаёт ВСЕ артефакты «шага 2» (5-6 документов). Приземлить на стандарты команд (стандартов по сути нет → взять примеры из их вики, возможно улучшить). Хранит пока локально MD/HTML → вручную выгружает в Jira/Confluence, отдаёт связки «артефакт→ссылка».

### B. mcp-iva-write (MCP для записи)
Сейчас есть только read-MCP (аналитика). Нужен write: создавать/править страницы Confluence, заводить задачи Jira (из PIN), писать тест-кейсы в Allure. **Персональные PAT:** каждый вставляет свой ключ от Jira/Confluence (назвать «Iva Write»; вероятно один ключ на обе системы — проверить), пишет из-под себя. Нужна инструкция «как вести артефакты для бота».

### C. Артефакты ↔ требование (helm)
По каждому из ~1500 требований аналитик создаёт артефакты → **привязаны к требованию в helm**. Разработчик берёт самое приоритетное требование, у которого уже есть артефакты. Своя MCP отдаёт 5-10 требований по приоритету на выбор. **Развилка — где хранить артефакты:** репа рядом с helm / Jira+Confluence / папка / вики (НЕ решено). Нужна spec/схема для helm (привязка).
