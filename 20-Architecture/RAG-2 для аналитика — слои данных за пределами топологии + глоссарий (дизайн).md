# RAG#2 для аналитика — слои данных за пределами топологии

Инсайт (обсуждение с пользователем): C4-топология показывает «что существует», но решение аналитик принимает на слоях, которых в топологии НЕТ. Постановка (FR — см. [[format-postanovki-analitika-iva-fr-feature-request-kanon]]) без этих слоёв «есть, но принять решение нельзя» / «архитектор развернёт».

## Слои → источник в ИВА → есть ли в RAG#2 сейчас → gap/инструмент

1. **«Почему нельзя»** (ADR / арх-ограничения + НФТ: нагрузка, latency, безопасность, доступность).
   - Источник: секция «Нефункциональные требования» в FR; арх-доки Confluence; **таблица `arch_risk` в helm** (arch_map уже отдаёт `open_risks` по узлу).
   - Есть: НФТ — да (в confluence-корпусе); риски — да (в графе helm).
   - Gap: нет отдельного ADR/решения-слоя и тула. Добавить `constraints(system)` (риски + связанные решения + НФТ).

2. **«Кто и когда»** (владельцы/команды — с кем согласовывать; релизы/roadmap — в какой релиз влезет; клиенты/покрытие — кого сломаем).
   - Источник: владельцы контейнеров (helm arch), Jira `fixVersion` (извлекаем как `fv`), roadmap-доки (спейс roadmap), `requirement_client` в helm.
   - Есть: владельцы — да (`affected_systems.owner_name`); fixVersion — извлекается; roadmap — в corpus.
   - Gap: не выведено релиз/roadmap/«кого сломаем». Расширить `affected_systems` (fixVersion + клиенты).

3. **«Как устроено внутри»** (модель данных; API/интеграционные контракты затронутого контейнера; существующие тест-кейсы).
   - Источник: секция «Функциональный дизайн» в FR (таблицы настроек, REST API path/responses, события NATS-шины, системные сообщения); тест-кейсы Jira (напр. VCSWEB2-T970).
   - Есть: да — API-контракты и события лежат внутри FR (эталон 150113311), в confluence-корпусе, ищутся.
   - Gap: выделить `contracts(system)`; тест-кейсы подтянуть/связать.

4. **Прецеденты и история** (похожие задачи; changelog статусов; обсуждения в комментариях — решение часто в комментах, а не в описании).
   - Источник: Jira. Извлекаем **changelog** (8693 события у IVAONE) + **comments** в payload.
   - Есть: похожие — `related_tasks`; changelog/комменты — в payload, ищутся.
   - Gap: не выведены явно. Surface changelog/комментов (взвесить — там решения).

5. **Глоссарий** ⭐ (самый недооценённый, критичен для качества ретрива в мультипродукте 16 продуктов).
   - Заказчик: «видеозвонок»; система: «conference session»; Jira: компонент MCU; wiki: «Сеанс связи». Без словаря синонимов retrieval систематически промахивается, реранк не спасает.
   - Найдено в Confluence: **IVCS Глоссарий (page 149651699) — ~195 записей**, формат `| Термин (+EN-синоним, аббревиатура) | Определение | Продукт |`; **161/195 с латиницей** (EN/код) + колонка Продукт (Common/…). Пример: «Видеоконференцсвязь, ВКС (videoconferencing)», «Feature request, FR». Плюс россыпь: per-space «Термины и определения» (UWC, PHON, IVAUC, IOA, IM, hydroacoustic), в User Guide-PDF, и **секция «Глоссарий (опционально)» прямо в FR-шаблоне**.
   - Есть: страницы глоссариев залиты как обычные доки (ищутся).
   - Gap: **(1)** нет структуры (единая таблица термин→синонимы); **(2)** нет query-expansion слоя в раге; **(3)** нет тула `glossary(term)`.

## Главный вывод
Сырьё **почти всё уже залито** (FR с НФТ/API/дизайном, глоссарии, changelog, комменты; владельцы/риски/requirement-матрица в helm). Настоящие пробелы — НЕ «данных нет», а: (1) **выделить слои в отдельные инструменты / выровнять выход MCP под FR-скелет**; (2) **построить глоссарный слой синонимов + расширение запроса**.

## План «начать делать»
**Фаза 1 — Глоссарий (маленький, самый окупаемый):**
1. Харвест всех глоссариев (IVCS 195 + per-space «Термины») → таблица `термин → {синонимы RU/EN, аббревиатура, продукт, определение}`.
2. Query-expansion в RAG#2: расширять запрос синонимами ДО эмбеддинга/поиска (детерминированно, дёшево, до реранка). За флагом.
3. MCP-тул `glossary(term)` («что такое X»).

**Фаза 2 — вывести слои как инструменты** (данные есть, надо surface): `constraints` (НФТ+риски+ADR) · release/roadmap/clients (расширить affected_systems) · changelog/комменты · `contracts`. Выровнять выход под секции FR (Начальная постановка · БФТ · ФТТ · Нефункц · Интерфейсные · Дизайн).
