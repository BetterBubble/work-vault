# Свежесть RAG#2 — дизайн (updated-since delta + as_of badges)

Ночь 2026-07-16, дата-независимый дизайн (без нагрузки на гейтвей, чтобы не мешать доеданию гигантов). Трек концепта «актуальность/свежесть», ранее не спроектирован.

## Проблема
Оффлайн-корпус RAG#2 отражает состояние на момент выгрузки (`as_of`), НЕ реальное время. Аналитик может получить устаревший статус/поля задачи и не знать этого. Два аспекта: (1) как ОБНОВЛЯТЬ корпус инкрементально без полной пере-выгрузки; (2) как ЧЕСТНО показывать возраст данных в ответах тулов.

## Что уже есть (факт, из payload jira)
Payload несёт `as_of` (момент выгрузки чанка) и `updated` (последнее изменение задачи в jira). Значит оба механизма СТРОЯТСЯ на существующих полях, без пере-индексации.

## A. Инкрементальный delta-sync (updated-since)
- **Механизм:** новый режим харнесса `--updated-since <ISO>` → JQL `project=X AND updated >= "<ts>" ORDER BY updated DESC`. Тянет только изменённые с прошлой выгрузки задачи (обычно десятки-сотни, не тысячи).
- **Upsert по ключу:** переиндексировать чанки задачи (delete по `key` + re-insert) — дедуп-ключ уже `key`. Идемпотентно.
- **Курсор свежести:** хранить per-project `last_synced_at` (в progress-файле или отдельном `freshness.json`); брать max(`updated`) из последней дельты. Первый прогон = max(`updated`) текущего корпуса (взять scroll-ом).
- **Стоимость:** дёшево (мало задач) → можно гонять часто (cron/ручной), НЕ конкурируя за гейтвей как полная выгрузка. Serialize так же (общий ключ).
- **НФ-требование:** не ломать резюмируемость полной выгрузки — delta это отдельный режим, не смешивать с window-resume гигантов.

## B. as_of badges в ответах тулов (честность возраста)
- **Правило:** каждый тул, отдающий задачи/доки (related_tasks, affected_systems, nearest_spec, effort_hint, search/context), добавляет в элемент `as_of` (из payload) и вычисляемый `age_days = now - as_of`.
- **Порог:** если `age_days > N` (напр. 14) — badge `stale: true` + note «данные на <as_of>, могут быть устаревшими; для точного статуса — live-MCP по ключу». N вынести в конфиг.
- **Клиент/FR-скилл:** обязан показывать as_of и не выдавать индексный статус за реальный сейчас (это уже покрыто ловушкой `freshness-trap` в routing_golden.json — согласовано).
- **Не выдумывать свежесть:** если `as_of` отсутствует в payload — badge `unknown`, не подставлять now.

## Границы (честно)
- RAG#2 остаётся broad-recall индексом; для точного live-статуса — точечный live-MCP по ID (режим `live` из rag2_golden meta). Свежесть-badge НЕ заменяет live, а сигнализирует, когда он нужен.
- Delta-sync ловит `updated`-изменения, но НЕ удаления задач (deleted в jira не придёт по updated-JQL). Удаления — отдельный редкий кейс, отложить (пометить как известное ограничение).

## Статус
Дизайн. Реализация — отдельная задача (режим харнесса `--updated-since` + badge-хелпер в analyst_server + конфиг порога). Данных не ждёт, но приоритет ниже Ф0/eval. Changelog re-index (для effort_hint durations) — родственный, но отдельный и дороже (пере-индексация) → след. день.
