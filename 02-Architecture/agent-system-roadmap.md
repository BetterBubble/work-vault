# Claude Code — система агентов: цель, статус, дорожная карта

Хендофф-заметка мета-проекта «построить автономную систему агентов в Claude Code». Единая точка входа: где мы, что сделано, что дальше. Ведётся по [[memory-protocol]]. Обновлять при закрытии каждого узла.

---

## 1. Цель
Максимально грамотная и **автономная** работа с Claude Code: команда/компания агентов с чёткими ролями, где всё понятно, красиво по архитектуре и работает почти без ручного участия. Документы/инструкции — фундамент на годы, поэтому образцовые.

## 2. Рабочий контекст пользователя
Разработчик: пишет/деплоит сервисы для клиентов (ИВА, ЗУ) в экосистеме Tacticum. Задачи ставит гендиректор (зум/тг/звонок) — иногда со сроком/приоритетом, иногда «повари и реши сам». Приоритеты могут меняться на середине задачи. Задачи бывают на день, бывают на 1–3 недели, к некоторым возвращаются через неделю.

## 3. Инвентарь системы (сейчас, с путями)
- **MCP-серверы (8, user-scope, `~/.claude.json`):** basic-memory, context7, helm-analyst (собств. инструмент пользователя, не для этой цели), iva-mcp (Atlassian заказчика), serena, ssh-manager (4 сервера: zu_demo/helm/gateway/adp_emb), taiga, wiki-mcp. Все deferred (0 токенов в контексте).
- **Агенты (`~/.claude/agents/`):** `explorer` (разведка кода), `implementer` (правки в git-worktree), `verifier` (eval+вердикт), `critic` (независимый ревизор доков — создан в этой сессии).
- **Команды (`~/.claude/commands/`):** `morning`, `catchup`, `after-call`, `wrap`, `tidy` (создана), `transcribe-md` (внешний скилл).
- **Хуки (`~/.claude/hooks/`):** `session-start`, `pre-compact`. (`stop` удалён — спамил.)
- **Память:** vault `~/tacticum-vault` (Obsidian + git) = факты проекта; авто-память `~/.claude/projects/-Users-bubblemac-tacticum/memory/` = правила поведения.
- **Версионирование:** vault под git; конфиг `~/.claude` под git (scoped: commands/hooks/agents/CLAUDE.md, без секретов).

## 4. Диагноз: 14 проблем → 7 узлов (с корнями)
1. **Память (боли 1, части 9,10)** — мусор/протухшее, агент опирался на старое. Корни: `stop.sh` спамил work-log (1958 строк); session-state дописывался (3 версии cross-rerank рядом); авто-память замерзала; Inbox — свалка (71); дубли-каноны. **→ РЕШЁН (см. §6).**
2. **Оркестрация команды (боли 2,3,8, части 5,7)** — тимлид лезет делать сам и засоряет контекст; агенты общаются «через раз»; кривые доступы. Корни: в CLAUDE.md НЕТ модели команды/делегирования; память централизована на лиде; `implementer` в закрытом `tools:` БЕЗ `SendMessage` (нужного доступа нет); `explorer`/`verifier` без `tools:` → наследуют деструктивные правки (лезут куда нельзя); транспорт `teammateMode: iterm2` хрупкий; синхронный «жди одобрения» через единственную точку.
3. **Планирование/«варка идеи» (боли 6,5)** — несколько мнений под углами + проверки на реальных данных; план→апрув→автономное выполнение. Инструменты есть (deep-research, judge-панели), не собраны в workflow.
4. **Деплой/сервер (боль 9)** — 4–5 несовместимых механик выката, нет единого runbook'а → агент выбирает наугад. Секреты ad-hoc (пароли в plaintext .env у gateway/adp_emb). Есть спроектированное решение `platform/deploy` (профили), в статусе bootstrap.
5. **Верификация/достоверность (боль 10)** — правило verify-data-credibility есть, но не гейт; нужны проверки UI и данных.
6. **Автономность: телефон + always-on (боли 11,12,7)** — контроль/статусы с телефона; Claude Code на always-on сервере; ночная работа без остановки на первой проблеме. Пока нет.
7. **Личная гигиена + переключение (боли 14,4,13)** — свой задачник; удобный хендофф контекста; умный рус. транскрибатор с диаризацией дёшево.

## 5. Дорожная карта / приоритеты
Порядок по зависимостям:
1. **Память** — фундамент. ✅ **СДЕЛАНО.**
2. **Оркестрация (узел B: 2+3+5+7+8)** — ядро видения «компании агентов». ← следующий кандидат.
3. **Автономность-инфра (F: 11+12)** — enabler ночной работы.
4. **Деплой + верификация (D+E: 9+10)** — доменная надёжность.
5. **Транскрибатор (G: 13)** — независимый быстрый выигрыш.
6. **Личная гигиена/задачник (14+4)** — обвязка.

## 6. СДЕЛАНО: узел «Память» (что / как / почему)
Не разовая уборка, а система: любой агент, ведущий память, обязан следовать регламенту; `/tidy` + `critic` не дают зарастать снова.
- **Obsidian** — UI памяти на `~/tacticum-vault` (почему: vault уже Obsidian-формат, бесплатно, граф+правки).
- **Уборка:** work-log 1981→17 строк (спам в git); session-state 262→43 (хроника в `04-Sessions/session-archive/`); 68 заметок в `99-Archive/` (концепты/LightRAG/Inbox-выхлоп); авто-память landscape помечена ⚠️-устаревшей. Почему: убрать источники, на которые агент опирался как на актуальные.
- **Регламент [[memory-protocol]]** (Слой 1) — 10 разделов: две системы+граница, таксономия, контракт (`status`/`created`/`updated` со ВРЕМЕНЕМ), дисциплина по типам, supersede, ЖЦ, связь **репо→направление→задача** (Taiga опц.), именование, анти-паттерны, enforcement. Role-agnostic.
- **Директива [[memory-rules]]** (Слой 2, авто-память) — 8 правил always-loaded + указатель на регламент.
- **Карта [[01-Repos]]** — репо→направления + Taiga-привязка (helm детально). Почему: заметкам есть на что ссылаться в `repo`/`project`.
- **Команды следуют регламенту** (Слой 3): `wrap`/`catchup`/`morning`/`after-call` пересобраны — динамическая ось репо→направление (не хардкод ЗУ/платформа), контракт со временем, канон-vs-архив. `pre-compact` — «перепиши компактно». `stop` удалён.
- **`/tidy`** (Слой 4) — ночной аудит соблюдения + гибридная уборка (безопасное сам, спорное → `00-Inbox/tidy-review-<дата>` на апрув).
- **Ревизор `critic`** — независимый агент; каждый фунд. док гоняется через него (см. [[critic-review-process]]).
- **Точки отката:** vault `git -C ~/tacticum-vault` (откат `4bc0cbe`); конфиг `git -C ~/.claude`. Ничего не пушилось (у vault нет remote).

## 7. Рабочая модель (как мы работаем над целью)
- **План → апрув → выполнение** (репетируем на каждом узле).
- **Ревизор critic** смотрит каждый фунд. док строгим верхним взглядом → **лид (ассистент) сам критично оценивает находки и применяет** → эскалирует пользователю только неоднозначное → пользователь апрувит спорное.
- **Лид делегирует** разведку/тяжёлое сабагентам, синтез оставляет себе (беречь контекст).
- Прогресс по узлам — в трекере задач + этой заметке.

## 8. Отложено (осознанно)
- **Планирование `/tidy` на ночь** — нужен always-on (узел F, п.12); пока вручную.
- **Агенты `explorer`/`implementer`/`verifier`** (доступы `tools:`, `SendMessage`, общение) — узел оркестрации (B).
- **`morning` тяжёлая** (git все репо + Taiga + вики в контексте лида) — кандидат №1 на делегирование сабагенту в узле B.
- **Бэкап vault** — нет remote, единственный экземпляр на маке (узел надёжности/автономности).
