## ПРИНЦИП: ТРЕК СТРОЙКИ ≠ ТРЕК МЕРЖА (президент 2026-07-24 ночь)
Лиды НИКОГДА не ждут пуш/PR/мерж, чтобы продолжать. **Трек стройки идёт до финала независимо**: лид строит ВСЕ оставшиеся проходы сразу (стеком branch-на-branch), версии манифестов ребейзит при мерже. Держится только PUSH (по гейту ГД). Контенция версий разводится стеком+ребейзом, НЕ ожиданием мержа. Простой лида на «жду мерж» = МОЙ недосмотр (ГД обязан держать всех в работе). Мерж-трек (президент мержит очередь) догоняет отдельно.

## ПРОТОКОЛ PUSH/PR (ОБНОВЛЁН 2026-07-24 — президент ДЕЛЕГИРОВАЛ push-апрув ГД)
**Президент 2026-07-24 дословно: «больше не спрашивай меня апрувы на пуш, сам всё проверяй и убеждайся, потом просто сразу давай мне PR».** Директор владеет push/PR ПОЛНОСТЬЮ до PR; президент только МЕРЖИТ. Последовательность на КАЖДЫЙ push:
1. Лид готов → директор велит прогнать батарею: fidelity к ТЗ + critic + git-чистота (controller).
2. Лид прогнал → **директор САМ сверяет ОБА гардрейла (строго-по-ТЗ + прод-safe) + git-чистоту — это ЕДИНСТВЕННЫЙ гейт перед push, вся ответственность на ГД.**
3. Проверки прошли → **директор СРАЗУ велит лиду пушить (БЕЗ спроса президента).** Лид синкает свежий main → пушит явно ветку, без force → финал-проверка чистоты.
4. **Директор → президенту: create-link PR + заголовок + описание** (лид PR не создаёт — gh нет).
5. **Президент создаёт+мержит PR** ← единственный шаг президента.
Лид без команды директора НЕ пушит. Гейт качества (оба гардрейла + git) целиком на ГД — быть СТРОЖЕ, т.к. президент больше не перепроверяет перед push. Необратимое сверх мержа (деплой/прод-сид/сервер) — по-прежнему явный gated-шаг президента.
