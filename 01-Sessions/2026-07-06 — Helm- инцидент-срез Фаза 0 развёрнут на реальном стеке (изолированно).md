# 2026-07-06 — Helm: инцидент-срез Фаза 0 развёрнут на реальном стеке (изолированно)

Полный цикл Фазы 0 (вычленить→граф→RAG→фронт→проверить) собран на ПРОДОВОМ сервере `helm` (159.194.233.33), изолированно от боевого. Боевое (`helm-helm-1`) не тронуто — живо всё время (traefik 401).

## Что развёрнуто
- [outcome] **Граф-lite в продовом Postgres** — новая БД `incidents` в `helm-postgres-1` (НЕ трогая БД `helm`). Схема `node/edge` (детерминированный upsert, не LLM-экстракция — §8.3-J волна 1a). Загружено из `crm_open_requests` (782 обращения): **812 узлов** (782 обращение + 15 продукт + 9 статус + 4 тариф + 2 команда) + **3128 рёбер** (по_продукту/уровень/в_статусе/исполняет).
- [outcome] **Числа из графа** = структурная плоскость (SQL-обход): застряло >90д — MCU 347, по тарифам Премиальный 186, всего 522/782 (66%).
- [outcome] **RAG через продовый Gateway** (`llm.cifragen.ru/v1`, модель `tacticum/cheap`): вопрос → LLM отвечает на фактах графа, числа НЕ выдумывает, честный отказ где нет данных (§8.3-F). Пример работает.
- [outcome] **Лёгкий фронт** — новый контейнер `incidents-front` (FastAPI+asyncpg, python:3.12), за traefik роут `Host(helm.tacticum.ru) && PathPrefix(/incidents)` priority 100, отдельный сервис (боевой роут `helm` не изменён). **URL: https://helm.tacticum.ru/incidents** — дашборд (застрявшие по продуктам/тарифам/командам + топ висяков) + поле RAG-вопроса.

## Как устроено (для воспроизв/тимдолга)
- [reference] Артефакты на сервере: `/opt/helm/_incidents/` (schema.sql, load_incidents.py), `/opt/helm/_front/` (app.py, Dockerfile). Образ `incidents-front`. Сеть `helm_default`.
- [gotcha] `HELM_DATABASE_URL` боевого — в docker-compose environment, НЕ в `.env` (в .env только GATEWAY/PROJECTHUB/RESOLVE/AUTH/OAUTH). Фронту передан явно `-e HELM_DATABASE_URL=<...>/incidents` + `--env-file .env` для Gateway.
- [gotcha] Gateway модель — `tacticum/chat`|`tacticum/cheap` (не gpt-4o-mini → 403). Список: /models вернул tacticum/{cheap,chat,code,flash-3.5,flash-3}.

## Auth v4 (2026-07-06)
- [outcome] **Фронт `/incidents` закрыт OAuth2 PKCE как боевой helm.** Server-side flow в incidents-front: `/incidents/login` → redirect на Tacticum ID (`master.tacticum.ru/authorize`, PKCE S256, client_id=helm, redirect_uri=/incidents/callback) → `/incidents/callback` меняет code→token (project-hub `/token`) → валидация через `/resolve` (service-key, приватная сеть 10.16.0.17:8770) → **гейт по тенанту `iva`** (membership tenant_slug=iva или platform_admin) → cookie `inc_token` 8ч. Email в шапке + `/incidents/logout`.
- [reference] Настройки берутся из `/opt/helm/.env` (--env-file): HELM_OAUTH_ISSUER=master.tacticum.ru, HELM_RESOLVE_URL/SERVICE_KEY, HELM_TENANT=iva, HELM_AUTH_REQUIRED=true. Все POST-роуты (find/by-exec/ask) отдают 401 без сессии. Прототип-режим (открытый) остался бы при HELM_AUTH_REQUIRED=false.
- [gotcha] issuer в .env = `master.tacticum.ru` (не дефолтный project.cifragen.ru) — берётся из env, не хардкод.
