# Разбор созвона 2026-07-23 10-30

Участники: Саша (я), Дима Солонко (руководитель), Ваня Монахов, ещё коллеги. Сырьё: `90-Materials/Созвон 23:07 10-30.rtf`.

## Решения / развилки закрыты
- **«Кто пишет тест-кейсы» — РЕШЕНО:** **аналитики пишут** (расширенные юз-кейсы + тест-кейсы), **QA/тестировщики дополняют на ревью**. Аналитику дать скилл написания расширенных юз-кейсов/тест-кейсов (у них уже почти всё есть — «первый слой бесплатный»); тестировщикам — возможность дописать + скилл ревью фичи-реквеста (добавить неочевидные сценарии). Обоснование — пирамида тестирования: максимум тестов на юнит-этапе, инфа должна быть в фичер-реквесте. → закрывает открытую развилку из [[qa-profile-model-opis-multi-stek-model-qa-leinov]].
- **Профили ПЕРЕСЕКАЮТСЯ, части ОТДЕЛЯЕМЫ (материал для ADR-концепта):** есть выделяемые переиспользуемые части — анализ / QA / разработка. Профиль аналитика пишет всю аналитику; разработчик может по ней разрабатывать И сам написать юз-кейс; при необходимости можно «залезть и провалидировать» чужую часть. Части должны быть отделимы и переиспользуемы между профилями. Долгосрочно — минимальная BPMS для фиксации статуса (пока в Project).

## QA-профиль (уточнения к нашей работе)
- **Два слоя QA:** (1) первый слой — тест-дизайн/написание тестов БЕЗ генерации кода (по сути то, что уже есть у аналитиков) → уходит к аналитику; (2) второй слой — 9 скиллов + 3 субагента → генерация/проверка/автозапуск/валидация автотестов (сколько прошло и т.д.).
- Профиль строить на базе скиллов команды Брейкина (Никита) — они уже привыкли, используют; интегрировать с аналитиками **без разрыва процесса**. Сделать «дырку» (лёгкую опцию) под разделяемые/переиспользуемые части.
- Целевое видение (Дима): аналитики пишут всё, тестировщикам остаётся реализовать тест-кейсы.
- Саша: доступ к Брейкину есть; сделает профиль QA (kie) сегодня; по развилкам отпишет Диме Солонко.
