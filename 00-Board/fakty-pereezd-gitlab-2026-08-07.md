# Переезд в GitLab — проверенные факты на 07.08 19:00

Проверено ГД в четырёх местах: локальные ремоуты обоих репозиториев, `origin` и `gitlab` в
`tacticum-dev`, рабочие каталоги на обоих прод-серверах, образы контейнеров.

## Переехал ОДИН репозиторий из двух — не путать

| Репозиторий | Где живёт сейчас | Прод тянет | Образ |
|---|---|---|---|
| **`tacticum-dev`** | **GitLab** `git@git.cifragen.ru:tacticum/dev.git` | `/opt/tacticum` → GitLab | `registry.cifragen.ru/tacticum/dev/backend:<sha>` |
| **`helm`** | **GitHub** `git@github.com:TacticumApps/helm.git` — **НЕ переехал** | `/opt/helm` → GitHub | `helm-helm`, собирается на месте |

**GitLab опережает GitHub на 16 коммитов; в GitHub нет ничего своего** — он стал хвостом.
GitHub-репозиторий `tacticum-dev` больше не источник правды.

## Пять утверждений в нашей памяти, которые теперь неверны — для `tacticum-dev`

1. **«Источник правды — GitHub `TacticumApps/tacticum-dev`»** → GitLab `tacticum/dev`.
2. **«Сид каталога делает внешний деплой-агент по SSH»** (уточнялось 31.07) → **сид делает CI**.
3. **«Версии профилей бампает автор правки руками»** → есть **автобамп**: в GitLab лежит коммит
   `chore(autobump): версии профилей после мержа [autobump]`. Ручной бамп теперь может
   конфликтовать с машинным.
4. **«PR готовим ссылкой на github.com/TacticumApps/...»** → для `tacticum-dev` такие ссылки
   ведут в мёртвый хвост. Всё, что ГД отдавал Президенту сегодня в этом формате, для новой
   работы неверно.
5. **«`gh` не установлен намеренно, PR создаёт человек через веб»** — правило остаётся, но
   веб теперь другой; форма merge-request в GitLab, не pull request в GitHub.

**Для `helm` все пять пунктов пока в силе** — он на GitHub, деплой ручной, PR-ссылки на GitHub
верны.

## Что это меняет в работе прямо сейчас

- **не пушить ветки в GitHub `tacticum-dev`** — уедет в хвост, никто не увидит;
- **не готовить GitHub-ссылки на PR** по `tacticum-dev`;
- **не бампать версии профилей руками**, не убедившись, как это уживается с автобампом;
- **сверять базу с GitLab**, а не с GitHub: `origin/main` в локальной копии отстаёт на 16;
- в `helm` работать как раньше.

## Чего мы НЕ знаем

- как именно устроен автобамп: на что триггерится, что делает при конфликте версий, можно ли
  его перебить руками;
- переносятся ли открытые ветки и PR из GitHub автоматически;
- что с остальными ~10 репозиториями платформы (Project Hub, LLM Gateway) — на дейли 07.08
  говорилось «сначала те, что активно дорабатывают».

Это вопросы к Воронцову и Глебу, не к нам.
