Пётр, привет. Ты ведёшь дизайн на KMP — держи короткую сводку, что у нас уже готово и что можно пощупать руками прямо сегодня.

## Сразу о главном: чтобы попробовать, нужно поставить профиль

Всё описанное ниже работает не отдельной утилитой, а изнутри твоего репозитория — через агента в
твоём CLI. Поэтому без установки профиля потрогать не получится. Ставить нужно **`iva-role-kmp`** —
это актуальная роль KMP-разработчика, одной установкой приезжает всё нужное для сценариев ниже.

Что понадобится, чтобы решить, ввязываться сейчас или нет:

| Что | Комментарий |
|---|---|
| **Токен доступа `phk_…`** | выдаётся один раз в чате поддержки Tacticum, личный. Если ты уже пользуешься любым профилем Tacticum — токен тот же, новый не нужен |
| **Клон KMP-репозитория** | работа идёт по коду локально |
| **JDK + Gradle** | сборка через gradle wrapper репозитория |
| **CLI — пока только Claude Code** | ⚠️ **под Codex установка этой роли сейчас не пройдёт** — у нас дефект на стороне сервера, чиню сегодня. Скажу, когда можно. Если всё же будешь пробовать Codex — сначала обнови до свежего, старые версии вдобавок не стартуют с MCP, заданным ссылкой |
| **Активный платный тариф на рабочее пространство** | без него инструменты дизайн-системы не отдадут токены — выглядит как поломка, хотя дело в тарифе. Упрёшься — напиши, решается на нашей стороне |
| **Figma desktop с Dev Mode** | только для сценариев с макетами; для первой проверки не нужен |

Если сам код гонять не планируешь, а нужно просто увидеть, что работает, — скажи, покажу вживую на
созвоне, ставить ничего не придётся.

## Что можно брать готовым

**Токены для мобильной ДС собраны и лежат на сервере.** Это `iva-mobile` версии 0.2.0: 966 токенов,
светлая и тёмная темы. Отдельный JSON заводить не нужно.

**Есть словарь «компонент → код» на 34 компонента.** Мобильные компоненты сопоставлены с конкретными композаблами в `:core:design-system` — Avatar, Badge, Bottom Sheet, Alert Dialog,
Text Field, Toast, Bottom Bar, Search Bar и далее, с указанием файла-источника для каждого. Привязка
снята с коммита `8f65eea2ff` от 23 июля.

**Токены раздаются с сервера — но это канал для инструмента разработчика, не для приложения.** Значения каждого токена хранятся сразу под обе темы, сервер отдаёт нужную по запросу и попутно раскрывает ссылки токенов друг на друга; версия прибита к рабочему пространству, опубликованная версия неизменяема — два разработчика гарантированно получают одинаковые значения.

Отдельно про твой вопрос «где и как хранить тему для мобил»: **это другой слой, и он у нас не закрыт.** Наш канал ходит от агента в CLI и требует установки профиля; клиент приложения по нему тему забрать не сможет. Чтобы json с токенами приезжал в рантайм рядом с wasm+js, нужна отдельная доработка — так что твоя оценка верна, я поначалу решил, что мы это уже покрыли, и ошибся.

## С чего начать: пятиминутный смоук

Сначала убедись, что связка «твой репозиторий → сервер → словарь» жива — это пять минут.

1. Поставь `iva-role-kmp` по инструкции из каталога (что для этого нужно — в таблице выше).
2. В чате агента в своём репозитории попроси показать, сколько компонентов лежит в словаре
   дизайн-системы `iva-mobile`. Ответ **34** означает, что всё сошлось: профиль подключён, сервер
   отвечает, версия правильная.
3. Для сценариев с макетами включи в Figma desktop MCP-сервер (Dev Mode → секция MCP → Enabled) и
   подключи его к своему CLI. Figma desktop должен быть запущен, пока агент работает с макетом.

Дальше — то, ради чего всё делалось.

## Сценарии, которые стоит проверить по существу

**Порядок пересмотрен после созвона 27.07 13:30.** Корнюшин поправил постановку: основная задача —
не новый экран, а **обновление дизайна на существующих экранах** (экран написан по старому макету,
есть новый макет, надо привести к нему), и первый этап этой работы — **токены**. Поэтому первыми
идут два сценария про обновление, перенос и новый экран — следом.

Ссылку на макет давай всегда на **конкретный фрейм**: правый клик → Copy link to selection, в ссылке должен быть `node-id`.

### 0. Обновить дизайн существующего экрана по новому макету (главный)

**Как запустить:** «приведи экран X к макету» + ссылка на фрейм.
**Приёмка:** агент читает макет, сопоставляет элементы со словарём, заменяет самодельную вёрстку на
компоненты дизайн-системы, цвета и отступы берёт из темы, а не задаёт числами.
**Не сработало, если:** остались `Color(0xFF…)` и сырые `dp`/`sp`, или экран переписан «на глаз» без
сверки со словарём.

### 0-bis. Смена токенов и починка отвалившегося

**Как запустить:** поменять значения токенов → задача «пройдись по экрану и приведи в соответствие».
**Приёмка:** экран реагирует на смену токенов без правок кода; там, где не изменилось, агент находит
и чинит захардкоженные значения. Именно это на созвоне назвали первым этапом работы.

### 1. Перенос готового экрана из веб-клиента в мобильный

Самый ценный сценарий: берётся существующий экран веб-клиента и переносится в KMP.

**Как запустить:** дай задачу вида «перенеси экран X из веб-клиента в наш репозиторий», укажи исходный экран и, если есть, макет.
**Приёмка:** исходный репозиторий агент только читает и не пишет в него ни строки; перевод идёт по
таблице соответствий «Angular → Compose», а не переписыванием на глаз; в конце он сам сверяет
паритет с исходным экраном и называет расхождения.
**Не сработало, если:** агент полез править исходный репозиторий, или выдал вёрстку, не сверив состав экрана с оригиналом.

### 2. Новый экран по макету

**Как запустить:** обычная задача со ссылкой на фрейм.
**Приёмка — главное здесь:** на элементе, которого нет в словаре, агент **обязан остановиться** и
сказать «компонент X не замаплен», а не выдумать свой. Это ключевое поведение: лучше стоп, чем
самодельный компонент, который потом никто не найдёт.
**Не сработало, если:** появились ручные `Row`/`Column` с отступами там, где есть готовый компонент,
или агент молча нарисовал недостающий элемент сам.

**Честное уточнение по этому сценарию.** Для мобильной части последовательность шагов приезжает не
самим профилем, а разовым правилом, которое добавляется в `AGENTS.md` репозитория (это описано в
инструкции по Figma, один раз копируется). Если правило не вставлено — агент словарь проигнорирует,
и выглядеть это будет как «не работает». Проверь маркеры в `AGENTS.md` в первую очередь.

### 3. Токены вместо хардкода

**Как запустить:** любая задача, где нужны цвета, отступы, типографика.
**Приёмка:** в диффе значения идут через тему и токены; `Color(0xFF…)` и сырые `dp`/`sp` не
появляются.
**Не сработало, если:** в коде оказались числовые цвета — значит агент не дотянулся до токенов.
Самая частая причина — неактивный тариф на рабочее пространство (строка в таблице выше); напиши мне,
проверим.

### 4. Сверка результата с макетом по числам

Здесь нужно сказать прямо, **потому что иначе ты потратишь на это время зря**.

Возможность «сравнить собранный экран с макетом по числам — цвет с допуском, отступы с допуском» в продукте есть, но **в мобильном профиле она сейчас работает только против HTML-макета, не против Figma**. Ссылки Figma и PNG-экспорты в этой версии проверки прямо объявлены вне области — то есть
задача «сверь мой экран с этим фреймом по цифрам» не отработает так, как звучит. Полная версия с
числовым сравнением по Figma живёт сегодня в веб-контуре.

Проверить в мобильном имеет смысл более скромное: агент собирает экран и сам сверяет, что цвета и
отступы взяты из токенов, а не заданы руками. Если тебе нужна именно числовая сверка с Figma на
мобильном — скажи, это отдельная работа, и лучше заявить её сейчас, пока идёт неделя.

## Чего в мобильном контуре нет вообще — чтобы не искал

Два блока из сделанного относятся к веб-команде и в мобильном профиле их нет:

- **Извлечение компонента из существующего кода в дизайн-систему** — «пройтись по экрану, увидеть
  повторяющийся компонент, вынести его в библиотеку». Правила создания компонента библиотеки
  (анатомия, полнота вариантов, витрина) реализованы для веб-контура; в мобильном профиле этого нет.
  На созвоне 13:30 такая возможность прозвучала — уточняю честно, потому что на неё нельзя
  рассчитывать в текущем виде. Нужна на KMP — заявляем отдельной работой.
- **Перевод целого репозитория со старой библиотеки на новую** — правило миграции батчами. Тоже веб.

То есть из семи блоков, сделанных по дизайн-процессу, для проверки доступны четыре сценария выше,
один работает частично (числовая сверка), а два — не твой стек.

## Ещё одна вещь, которую стоит знать заранее

**Словарь можно запросить отдельно — не тяните всю систему целиком.** Полная дизайн-система весит
около 325 КБ, и если запросить её без фильтра, ответ может обрезаться, а агент начнёт выдумывать
значения цветов вместо того, чтобы брать их из темы. Правильный путь — запрашивать нужную ветку
токенов, а словарь соответствий забирать отдельным запросом: так он занимает около 10 КБ вместо
двухсот.

Это учтено в самих правилах профиля, отдельно делать ничего не нужно — пишу, чтобы ты понимал
причину, если увидишь обрезанный ответ.

## Что честно не закрыто

Два места, где мы сами знаем о пробеле — лучше узнать от меня, чем наткнуться на пятый день.

**У мобильных компонентов нет ключей Figma — ни у одного из 34.** Причина не в том, что не дошли руки: мобильной библиотеки компонентов в Figma фактически не существует, файл пустой, а мобильные
экраны исторически рисуются на веб-компонентах. Поэтому сопоставление сейчас идёт по именам, а не
по ключам. Это работает, но это развилка, которую стоит решить на неделе: либо мобильную библиотеку
заводят, либо мы фиксируем как норму, что мобильное ключуется на веб-мастера.

**Внутри самого KMP связи с Figma нет вообще.** В модуле дизайн-системы 251 файл, генераторов из
Figma — ноль, цвета заданы руками в Kotlin, и названы они по палитре (`primary80`, `critical70`),
тогда как в вебе имена смысловые. Одно из другого автоматически не выводится — это, насколько
понимаю, и есть основной разрыв, который закрывается на этой неделе.

## Если что-то не работает

Напиши мне напрямую — разберусь быстрее, чем ты будешь искать причину. Особенно если увидишь:
нет инструментов Figma (обычно Figma desktop не запущен или MCP не включён), пусто вместо словаря

запись просто нужно добавить, скажи какой компонент.

## Что я фактически проверил, а не переписал из инструкции

- **`design_get_tokens` не имеет ограничения размера** — проверено по коду
  (`design/interface/mcp/design_get_tokens.py`, поиск `max_chars|truncat|limit` пуст), возвращает

  форма `--transport http <name> <url>` актуальна.

- **Грабля со старым Codex подтверждена** записью в `00-Board/brief-analyst-profile-2026-07-27.md`

каталогов навыков, а не по описанию.

| Перенос экрана веб → мобильный | **да** — `web-to-kmp-screen-port` + `web-to-kmp-source-reference` в `iva-kmp-development-base` | работает, в письме описан полностью |

**Главная находка этой проверки.** `ui-mockup-match`, который роль получает из `tacticum-ui-base`, —

То есть сценарий «сравни экран с макетом Figma по числам» в мобильном профиле **не отработает так,

Формулировку в задании («`ui-mockup-match` → сравнение цвета и отступов с допусками») пришлось
скорректировать — для KMP она верна только применительно к HTML-макету.

## Расхождения инструкции с реальностью — найдено три

1. **Figma-квикстарт KMP требует профиль `iva-kmp-brownfield`** (строка 15), тогда как профильный
   квикстарт `iva-role-kmp-profile-quickstart.md` прямо называет `iva-kmp-brownfield` **старым**
   профилем и описывает переход на роль. Документ написан до перехода на роли и не обновлён.
   **Это надо поправить в репозитории отдельной правкой** — в письме я об этом предупредил.
2. **В квикстарте роли `iva-role-kmp` про платный тариф не сказано ни слова** (grep по
   `402|seat_required|подписк|premium|тариф` пуст). Человек, ставящий роль, узнает про гейт только
   когда упрётся в ошибку. В письме предупредил явно.
3. **Расхождение в формулировке ошибки.** Figma-квикстарт говорит «AuthError» — и это **верно**:
   код бросает `AuthError("seat_required")`. А вот навыки в профилях учат ловить «402 Payment
   Required», которого design-тулы не возвращают вовсе (402 отдаёт совсем другой контекст). То есть
   квикстарт точнее навыка. В письме описал нейтрально — «ошибка доступа», чтобы не привязываться к
   формулировке, которая сама расходится между документами.

## Чего я НЕ делал

Правок в репозиторий не вносил — это разведка под письмо. Расхождение №1 (устаревшее имя профиля)
стоит завести отдельной задачей: документ вводит в заблуждение нового человека на входе, а неделя
как раз про то, чтобы новые люди зашли быстро.
