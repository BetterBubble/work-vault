# Финал: что делать каждому из двоих

Отменяет мою прежнюю рекомендацию «работать по скринам» — она была неверной по приоритету.
Скрины в навыке `figma-access-setup` стоят пятым шагом, то есть последним, когда не работает
ничего. У нас работает: **Солонко ходил в Figma по REST с персональным токеном**, и это видно
в коде — `scripts/figma_core_bindings_check.py`, `https://api.figma.com/v1`, заголовок
`X-Figma-Token`. Никакого Dev Mode и никакого десктопа этот путь не требует.

## Что оказалось решающим фактом

Лимит Figma считается **по плану файла, который читаешь, и по твоему seat в ЭТОМ плане** — не по
плану твоего личного аккаунта. Дословно из документации Figma:

> «if you use a personal access token to get the content of a file in a Starter plan, requests to
> that file are limited to up to 6 per month **even if you have a Full seat in a different plan**»

Таблица лимитов на чтение файлов (`GET file`, `GET file nodes`, `GET image`):

| Seat в плане файла | Starter | Professional | Organization |
|---|---|---|---|
| View / Collab | 6/месяц | 6/месяц | 6/месяц |
| Dev / Full | — | 15/мин | 20/мин |

Отсюда два следствия, которые меняют постановку задачи:

1. **Отдельный аккаунт Фадину покупать бессмысленно.** Пока он не участник плана, которому
   принадлежат макеты, он упирается в 6 запросов в месяц независимо от того, что оплачено на его
   стороне.
2. **Ключевой вопрос не «есть ли у нас оплаченный аккаунт», а «в каком плане лежит UI KIT и кто
   в этом плане с каким seat».** Именно так у Солонко всё работало: он имел доступ к плану с
   макетами и читал их по REST.

## Фадину — три шага, сегодня

1. **Локальный MCP-сервер не поднимать.** На free-плане он невозможен в принципе (Dev Mode —
   только Dev/Full seat платного плана), и он не нужен: рабочий путь другой.
2. **Выпустить персональный токен:** figma.com → Settings → Security → Personal access tokens →
   Generate new token. Scopes: `file_content:read` и `file_dev_resources:read`. Вариант «без срока»
   Figma больше не даёт — максимум 90 дней, это нормально.
   `file_variables:read` **не брать** — Variables API у нас всё равно Enterprise-only, цвета
   берутся из каталога Tacticum.
3. **Сразу одна дешёвая проверка** на файле макетов: `GET /v1/files/:key?depth=1`. Она за один
   запрос показывает и наличие доступа, и реальный лимит. **403** — нет доступа к файлу (решается
   не токеном, а членством в плане, см. ниже). **429** — лимит уже выбран.

**Чего не делать:** не дёргать `/v1/images`. Именно этот эндпоинт сжигает квоту — 28.07 на нём
словили `429` с `Retry-After` почти на четверо суток. Узлы читать батчем, одним запросом:
`GET /v1/files/:key/nodes?ids=…`, а не по одному.

## Беспалову — один вопрос, административный

Нужно **включить Фадина и Мирина в тот план Figma, где лежат макеты, с seat уровня Dev или Full**.
Не завести им отдельные аккаунты и не купить отдельный план — именно членство в плане файлов.
С View-seat там будет всё те же 6 запросов в месяц, сколько за него ни заплати.

Чтобы это сделать, надо сначала ответить на вопрос, который пока не отвечен ни у кого:
**в каком плане Figma лежит UI KIT** (файл `AG11paSthGC7zSoovfjip0`) и кто им владеет —
дизайнеры или отдельная команда. Дальше seat выдаёт админ этого плана.

Утверждение «у нас нет ни одного работающего оплаченного аккаунта с Dev Mode» проверить я не
могу — нужен доступ к биллингу Figma. Но по факту оно вторично: даже оплаченный аккаунт вне
плана макетов даёт 6 запросов в месяц.

## Что сделать с установками (независимо от Figma)

Обе KMP-установки отстали от прода — им нужен `pull_installation_content` с `update=true`:

- `687db0e8` (боевая, brownfield): пин 0.11.0, фактически 0.10.0;
- `cbb20b79` (пилотная, роль): пин 0.4.5, фактически 0.4.3.

В 0.11.0 и 0.4.5 приехал обновлённый `figma-access-setup` — тот, где Солонко сегодня добавил
проводку Codex и правило не объявлять Dev Mode недоступным раньше трёх проверок.

**И отдельно для Codex:** у аккаунта 23 неархивированные установки, а его ключ не привязан ни к
одной. Пока `installation_id` не передаётся явно, вызовы `design_*` падают с
`installation_id_required` — это выглядит как «нет прав», хотя дело в отсутствующем параметре.

## Что в наших навыках надо поправить (не делал — правки запрещены)

`figma-access-setup` ведёт лестницей «локальный MCP → включи локальный → PAT → экономия →
скрины». Для человека без Dev seat первые два шага — тупик, а рабочий путь стоит третьим.
REST с PAT надо поднимать выше, и там же назвать настоящее условие лимита: план файла плюс seat
в этом плане, а не план аккаунта. Плюс удалённый сервер `mcp.figma.com` не упомянут нигде,
включая сегодняшнюю правку.

> **Поправка 04.08:** Variables REST API записан здесь как Enterprise-only — по актуальной
> странице цен Figma он доступен **с Organization**. На выводы не влияет (токены берём из
> каталога), но опираться на «Enterprise-only» нельзя. Подробнее — [[status-ds-figma-2026-08-04]].
