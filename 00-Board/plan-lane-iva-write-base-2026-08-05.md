# План: лейн `iva-write-base`

Вес — **крупная**: новый профиль в каталоге, три профиля меняют версию, дальше
раскатка на девять ролей. Ветка `feat/iva-write-base-lane` от `origin/main`
(`d607513`), рабочее дерево `~/tacticum-worktrees/iva-write-lane`.

Эталон и способ сверки — [[baseline-etalon-analyst-030-2026-08-05]].
Блокирующая находка, из-за которой план не совпадает с постановкой дословно —
[[nahodka-marker-codex-lomaet-pereezd-2026-08-05]].

## Что изменилось против постановки и почему

Постановка велит завести лейн с каналом **и текстами**. Проверка показала, что
механизм этого сегодня не умеет: на codex два `instruction_pack` в один файл
склеиваются в одну секцию, и **маркер роли исчезает**. Эталонный человек сидит
именно на codex. Поэтому в план добавлен **шаг 0 — починка рендерера**, без
которого пункт (б) постановки нельзя выполнить, не сломав эталон.

Второе отличие: постановка говорит только про аналитика, но канал сегодня
композицией получает **и архитектор**. Просто убрав ингредиент из
`iva-analysis-fr`, мы молча отберём канал у него — и это отменит записанное в
коде решение Президента от 04.08 («принять и записать явно»). Поэтому архитектор
включён в правку — **чтобы его состав не изменился**, а не чтобы расширить объём.

## Шаг 0 — починить склейку маркеров в рендерере (корень)

`_dedupe_actions_by_path` (`apps/backend/src/backend/catalog/domain/renderer.py:367`)
не должен сливать действия с РАЗНЫМИ `marker_id`. Действия без маркера
по-прежнему прилипают к первой группе своего пути — это сохраняет смысл #677
(markerless `rule_set` не должен деградировать в голый `write_file` и затирать
пользовательский файл).

**Цена измерена:** 0 композиций из 21 роли имеют сегодня два разных маркера в
один файл. Правка — no-op для всех существующих профилей.

Тест: композиция «rule_set без маркера → пак лейна → пак роли» даёт на codex
ДВЕ секции, оба маркера на месте. Формулировка проверки — «что оказалось в файле
у человека», не «сколько действий вернул рендерер» (грабли п. 1).

## Шаг 1 — завести `templates/iva-write-base/`

Форма — по образцу `iva-architect-mcp` (тонкий leaf-лейн, **без `depends_on`**).
Три файла: `manifest.yaml`, `README.md`, `CHANGELOG.md`.

Несёт:

| ingredient_id | kind | назначение |
|---|---|---|
| `helm-iva-write` | mcp_server_spec | канал, адрес `https://helm.tacticum.ru/mcp/iva-write` |
| `iva-write-claude-md` | instruction_pack | текст в `CLAUDE.md`, маркер `tacticum:iva-write-base` |
| `iva-write-agents-md` | instruction_pack | текст в `AGENTS.md`, тот же маркер |
| `iva-write-codex-toml` | instruction_pack | блок в `.codex/config.toml`, `create_if_missing` |

Версия — `0.1.0`. Имя чистое: профиля `iva-write-base` в прод-каталоге нет
(проверено SELECT'ом), на `main` каталог такого шаблона никогда не был.

**Тексты пишутся ролево-нейтрально** (решение Президента): «от имени самого
человека, за которым закреплена установка», а не «самого аналитика». Иначе на
девяти ролях QA и разработчик прочитают про себя «аналитик».

## Шаг 2 — убрать канал из `iva-analysis-fr`

Снять блок `helm-iva-write` (`manifest.yaml:239-268`), поправить счётчики в шапке
(`15 ingredients`, `mcp_server_spec (3)`), встречный комментарий у
`iva-atlassian-write`, описание и `post_install_notes`, README, CHANGELOG.
Версия `0.2.0` → `0.3.0`.

`iva-atlassian-write` **остаётся** в `iva-analysis-fr` — снятие interim
отдельный шаг, он завязан на `KNOWN_OVERRIDES` архитектора.

## Шаг 3 — аналитик

- `depends_on` += `iva-write-base` (в конец: ингредиент уникален, приоритет ни на
  что не влияет);
- из трёх паков убрать текст про канал, оставив ролевое (точки входа, KB, привязка
  установки). **Роль обязана сохранить хотя бы один свой пак** —
  `test_role_carries_only_role_packs`; она его и сохраняет;
- `/start-research` из текста не выкидывать — `test_role_modes_routed` требует имя
  команды в паке;
- версия `0.3.0` → `0.4.0`, CHANGELOG.

## Шаг 4 — архитектор (сохранение статус-кво, не расширение)

`depends_on` += `iva-write-base`, версия +minor, CHANGELOG. Без этого он **теряет
канал молча**.

Побочный эффект, названный вслух: архитектор впервые получит **текст** к каналу.
Сегодня он получает инструмент без объяснения — это прямо описано в комментарии
`test_install_flow.py:983-989` как известный дефект. Лейн его чинит.

## Шаг 5 — сторожа

1. **Дописать зеркальную половину** сторожа
   `test_iva_write_roles_covers_every_role_that_gets_the_channel`: сегодня он
   ловит только «канал достался, а роль не записана», и НЕ ловит обратное —
   «роль записана, а канал больше не достаётся». Именно вторая половина поймала бы
   тихую пропажу канала у архитектора. Паттерн в каталоге устоявшийся
   (`test_not_a_role_list_has_no_stale_entries`).
2. `ROLE_LANES` для аналитика и архитектора — сверяется с точностью до порядка.

## Шаг 6 — голдены и приёмка

Прогон **до** правки (зафиксировать зелёный baseline), потом после.

```bash
cd apps/backend
uv run --python 3.12 --extra dev python -m pytest tests/catalog -q -p no:randomly
uv run --python 3.12 --extra dev python -m pytest tests/e2e_install -q -p no:randomly
```

Плюс дисциплина версий:

```bash
python scripts/check_profile_version_discipline.py --diff-against origin/main
python scripts/check_mirror_sync.py
python scripts/check_install_links.py --mode paths --all-profiles
python scripts/check_install_links.py --mode xrefs --all-profiles
```

**Предсказание diff'а голдена — это и есть приёмка.** Обязано выполниться:

| Файл | Ожидание |
|---|---|
| `repo/.mcp.json` | **байт-в-байт прежний.** MCP пишутся `merge_json` по указателю, файл сохраняется с `sort_keys=True` → порядок лейнов не влияет. Хеш поехал = состав канала реально изменился, регенерировать НЕЛЬЗЯ |
| `user/.codex/config.toml` | может измениться: порядок TOML-блоков. Diff обязан показать **те же четыре блока** `[mcp_servers.*]` |
| `repo/CLAUDE.md`, `repo/AGENTS.md`, `repo/.codex/config.toml` | меняются ровно настолько, насколько правились тексты |
| любой другой файл | **задето лишнее** — разбираться, не регенерировать |

## Шаг 7 — тексты, которые описывают поведение словами (грабли п. 3)

- три предупреждения «прежний шлюз… (удалённый лейн `iva-write-base`) не
  воспроизводить» (`iva-analysis-fr/manifest.yaml:255`, `README.md:29`,
  `runbooks/iva-write-rollout-to-roles.md:45`) становятся двусмысленными, когда
  имя переиспользовано — переписать так, чтобы речь была про АДРЕС, а не про имя;
- `docs/runbooks/iva-write-rollout-to-roles.md` предписывает другую стратегию
  («класть в существующий лейн роли») — после правки он неверен, обновить;
- `docs/user_manuals/iva-role-analyst-profile-quickstart.md`: раздел про согласие
  написан под аналитика. На девяти ролях он превратится в девять копий — **это
  грабли п. 2**. Вынести общую часть в отдельный документ канала, из квикстартов
  ссылаться.

## Приёмка

1. **Машинная сверка состава**: множество `(ingredient_id, kind)` разрешённой
   композиции аналитика ДО и ПОСЛЕ — обязано совпасть; `helm-iva-write` меняет
   владельца с `iva-analysis-fr` на `iva-write-base`. То же для архитектора.
2. **Свойство, а не механика**: в собранных `CLAUDE.md` / `AGENTS.md` обоих CLI
   присутствуют утверждения — канал основной путь публикации · пишет от имени
   человека · нужно однократное согласие · отказ до согласия не поломка · interim
   только если основной недоступен. И **оба маркера на месте**.
3. **Живой прогон установки на стенде** (решение Президента о критерии). Требует
   сида новой версии в каталог, то есть **слова Президента** — ставится как
   финальный шаг приёмки, работу не блокирует.
4. Два `critic` с оппонированием — вес крупный.

Читать всё, включая прод — свободно. Править локально, пуш feature-ветки — можно.
**Мерж в `main`, деплой, сид каталога, перевод пинов, сообщения людям — только по
слову Президента.**
