## Что изменилось

**Причина, а не симптом.** Раньше почту через бота человек называл в чате, и она не была
подтверждена ничем. Теперь адрес выводится из `author.login` платформы (`login@<домен>`) и
**проверяется у Jira** служебной учёткой; совпало — личность подтверждена внешней системой.
Не совпало / учётки нет / Jira недоступна / соглашение об именовании нарушено — поведение
прежнее: спрашиваем почту в чате. Fail-closed везде.

**Служебный доступ не заводился заново.** Взята учётка ингеста (`HELM_RAG2_JIRA_USER` /
`HELM_RAG2_JIRA_PASSWORD`) — ингест запускается внутри контейнера helm, значит переменные там уже
есть. Адрес Jira и туннель — из `iva_oauth_jira_*`, то есть тот же путь, которым helm уже ходит в
Jira за обменом кода.

## Граница безопасности — чем закрыта

`platform` **не даёт** права сохранить доступ без сверки: `identity_weak` в
`application/iva_write._verify_identity` по-прежнему разрешён ТОЛЬКО для `auth`. Подтверждено,
чей адрес мы ждём, а не кто откроет ссылку.

Два теста держат это прямо:

- **`test_declared_email_never_becomes_platform_identity`** (`tests/interface/test_bot_iva_write.py`)
  — логин справочнику неизвестен → бот спрашивает почту → человек отвечает адресом, который
  справочник подтвердил бы сам. Ссылки выдаются, но `subject_source` обязан остаться `declared`.
  Это ровно тот дефект, о котором предупреждал лид: путь, где строка из чата попадает в
  подтверждённую личность. Источник считается по происхождению строки, а не по её значению;
- **`test_platform_identity_still_verified_on_callback`** — ссылка выдана на подтверждённый адрес,
  согласие даёт ДРУГАЯ учётка → 400, доступа нет, «готово» не пишем.

## Что осталось непроверенным

1. **Что платформа реально кладёт в `login` — по-прежнему неизвестно.** Примера значения нет ни у
   кого. Код к этому готов: внутренний идентификатор просто не найдётся в справочнике (тест
   `test_unknown_login_falls_back_to_question` гоняет UUID), и бот спросит почту.
2. ~~**Живая Jira не трогалась**, право служебной учётки на `/rest/api/2/user` не подтверждено.~~
   **СНЯТО 31.07:** лид проверил на боевом контуре 30.07 —
   `GET /rest/api/2/user?username=monakhov-tech` отвечает 200 и отдаёт `emailAddress`. Право есть,
   путь рабочий; факт вписан в комментарий у `USER_PATH` в `directory.py`. Остаётся непроверенным
   только одно из прежнего пункта: сетевая достижимость этого пути ИЗ КОНТЕЙНЕРА helm (туннель и
   адрес те же, что у обмена кода, но отдельным запросом это не гонялось).
3. **Соглашение «логин = локальная часть почты» проверено на 4 учётках из 4** — это наблюдение
   Президента, а не гарантия ИВА. Ради этого и сделан выключатель.
4. **Сетевой запрос идёт при открытой сессии БД** (разобрать сообщение без базы нельзя: нужно знать,
   ждём ли мы ответа в этом чате). Транзакция к этому моменту уже удалила просроченные диалоги, то
   есть держит блокировки до `iva_oauth_timeout_s`. Для единиц пользователей приемлемо, помечено в
   докстринге; при росте нагрузки чинится порядком шагов.
5. **Расхождение X≠Y закрыто не целиком.** Убран источник ошибки «человек назвал не тот адрес», но
   случай «ключ Tacticum выписан на другой адрес того же человека» остаётся — это варианты В1/В5 из
   `razbor-403-pochty-2026-07-30`, отдельное решение.
