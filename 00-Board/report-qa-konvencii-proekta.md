# Подчинение конвенции проекта — сделано, доказано мутацией

## 1. Как сформулировано правило подчинения

Во все восемь фрагментов (`iva-role-qa{,-web,-mobile,-desktop}` × claude-code/codex) добавлен
раздел **«Конвенция проекта старше нашей — порядок проверки»**, сразу после описания роли и
ДО первого упоминания `.tasks/`. Он даёт агенту исполнимую процедуру, а не декларацию:

- наши пути объявлены **значением по умолчанию для репозитория, где своего правила нет**;
- порядок проверки — три шага: `AGENTS.md`/`CLAUDE.md` вне нашей секции (секция названа
  маркером `tacticum:<роль>`) → правила репозитория (`.agents/`, `.cursor/rules/`, `docs/`,
  CONTRIBUTING) → `README.md` корня и `README.md` каталога записи;
- прямое **«работай по ней»**, класс конвенций назван явно (рабочая директория, раскладка
  артефактов, имена веток, формат коммитов);
- требование назвать расхождение вслух: «в проекте <их>, у нас <наш>, беру <их>»;
- правило распространено **и на карты, на которые фрагмент ссылается** (`work-dir.md` и
  прочие) — иначе агент подчинился бы разделу и тут же прочитал наш путь как закон.

Два дополнения, без которых правило не работало бы:

- **абзац с нашим путём больше не стоит один**: везде, где назван `.tasks/work/`, рядом
  стоит «это наш дефолт, он уступает рабочей директории, объявленной проектом (см. «Конвенция
  проекта старше нашей»)». Правило, лежащее отдельно от пути, не исполняется: агент читает
  абзац про рабочие файлы и уходит работать, до раздела не дойдя;
- **преамбула связана с механизмом**: обещание «мы уступаем» теперь указывает на раздел
  ниже. Это то самое место, где текст расходился с поведением.

## 2. Как именно тест падает на подмене

Оракул — `apps/backend/tests/catalog/test_project_convention_precedence.py` (51 тест).

**Что он делает.** Собирает НАСТОЯЩЕЕ дерево установки роли (`build_install_tree` из
`scripts/check_install_links.py` — тот же вход, что у штатного чекера), заворачивает точку
входа в маркеры НАСТОЯЩИМ `renderer._wrap_body_with_markers` и дописывает её НАСТОЯЩИМ
клиентским `apply_actions` (`append_section`) в `AGENTS.md`/`CLAUDE.md` подложенного проекта.
Дальше по получившемуся файлу работает резолвер рабочей директории:

1. режет файл по маркерам на «нашу секцию» и «текст проекта» — правило ищется в нашей,
   чужая директория **только** в проектной части (иначе подчинение самоподтверждалось бы);
2. разбирает правило: нет раздела, нет слов «по умолчанию», нет «работай по ней», нет
   нумерованного порядка, есть формулировка главенства нашего пути → правило считается
   неисполнимым, и резолвер возвращает наш `.tasks/work/`;
3. **порядок проверки берётся из самого правила**, а не зашит в тест: шаги парсятся из
   нумерованного списка, источники — из бэктиков;
4. ищет объявленную директорию в источниках в объявленном порядке.

**Подложено четыре проекта:** реальный кит заказчика (`.agents/state/work/<slug>/` в его
`AGENTS.md` — ровно то, что наш пак перебил на стенде), объявление в правилах репозитория
(`.agents/conventions.md` → `var/agent-runs/<task>/`), объявление только в README
(`tmp/ai-scratch/`), и проект **без** своего правила. Последний обязателен: без него резолвер
мог бы всегда возвращать «что-нибудь чужое», и проверка была бы бессодержательной.

Роли **выводятся из каталога** структурно (композит лейн `tacticum-autotest-core`, который
везёт карту `.tasks/`), а не перечисляются руками — ручной список это та же дыра, из-за
которой две QA-роли уехали в main мимо install-смока. Плюс страховка от вырождения: список
не пуст и содержит все четыре QA-роли поимённо.

**Пять мутаций оставлены постоянными тестами** в том же файле (идиома
`tests/e2e_install/test_oracle_mutations.py` — зелёные в CI, доказывают редность): снести
раздел · вывернуть смысл на «наш путь главный» при сохранённом заголовке · потерять шаг
README (проект с конвенцией только в README снова читается по-нашему, а проект с конвенцией
в `AGENTS.md` — ещё верно: значит краснеет именно потерянный шаг, а не резолвер целиком) ·
оторвать оговорку от пути · убрать признание про `create_if_missing`.

**Честная граница, названная в докстринге теста.** Резолвер — модель того, как правило читает
агент, а не сам агент; живое поведение LLM тестом не воспроизводится. Доказано ровно: правило
есть в каждом из восьми фрагментов и доезжает до установленной точки входа; оно исполнимо;
наш путь нигде не назван без оговорки; любая правка обратно на «наш путь главный» делает файл
красным.

## 4. Что решил с `create_if_missing` и почему

**Доставка не чинилась — чинилось молчание.** Разобрался: механика за полем ЕСТЬ и работает
как задумано. `create_if_missing` — клиентский контракт (`oracles.apply_actions`: файл
существует → действие пропускается и считается в `skipped`), он покрыт e2e-тестом
`test_apply_preserves_user_owned_files` и описан в quickstart. То есть это не «поле без
механики» (не случай `metadata.assets`), а механика, которая делает ровно обещанное: **не
перезаписывает пользовательский файл**.

Чинить доставку значило бы одно из двух, и оба плохи:

- перезаписывать чужой `.codex/config.toml` — это прямо противоречит решению, ради которого
  правка и делается: мы гости, конфигурацию проекта не трогаем;
- вводить настоящий TOML-мерж (новая стратегия в схеме, рендерере, клиентских `apply.ps1`
  всех профилей) — это правка контракта установки для всего каталога, далеко за границами
  задачи и с риском задеть чужие профили.

Поэтому выбран второй разрешённый ГД вариант — **честный текст**, и он привязан к манифесту
проверкой: если роль объявляет `.codex/config.toml` с `create_if_missing`, Codex-фрагмент
обязан назвать и сам факт («файл есть → наш конфиг не приедет»), и потерю `max_depth = 1`, и
дать кусок TOML для ручной дописки. Если стратегию когда-нибудь сменят на настоящий мерж,
тест потребует оговорку **убрать** — так текст не разойдётся с манифестом ни в одну сторону.

## 5. Добавка по мобильной роли (хвост от соседней ветки)

В оба мобильных фрагмента внесено то, что закрыто в каноне стека ветки
`fix/qa-mobile-hard-findings` (канон читал, не правил):

- **предусловий прогона пять, а не четыре** — к `--env` и трём опциям устройства добавлена
  локальная сборка в корне (`one.apk` / `iosApp.app` / `Ucim.ipa`); в репозиторий не
  приезжает, кладёт человек; без неё падает и прогон, и разведка — **до контакта с Appium**,
  класс `AUT_BUILD_MISSING`, дискриминатор: в трейсе `aut.clear_data` / `apk_reinstall` /
  `simctl install` и нет кадра `webdriver.Remote`;
- **устройство занято человеком — прогон не запускать вовсе** (🔴): каждый прогон
  переустанавливает приложение и стирает данные **мимо сессии**, через `adb`/`simctl`, поэтому
  прежняя гигиена «чужую сессию не убивать» этот случай не закрывала.
