# Демо Роскосмос — геройские фичи ИВА (разведка на живых данных)

_tenant=iva · as_of данных: Jira/Confluence ~10.07, helm-реестр ~13.07, Allure ~22.07 · собрано 2026-07-22, к демо 16:00 · только чтение_

## Ландшафт продуктовых областей (что реально в данных)
Пять систем C1: **IVA One** (мессенджер/звонки/календарь/файлы/почта-клиент; 40 архрисков, 17 high — самая богатая), **IVA CS** (телефония), **IVA MAIL/Phoenix** (свой почтовый сервер, протокол JUMP), **IVA MCU/ВКС** (видеоконференции), **IVA Terra** (AI: транскрибация/суммаризация/перевод).
Продуктовые компоненты с богатыми данными (Jira+Confluence+граф): Мессенджер, ВКС, Звонки, Календарь, Почта, Адресная книга, DiskStorage, Профиль/настройки, **IVA ID (SSO)**, Федерация, Push, Presence.

## Шортлист геройских кандидатов (по демо-силе)

1. **SSO / IVA ID — ТОП-1, идеально под Роскосмос.**
   - Прямое попадание: **IVAONE-12438 «Поддержка SSO от двух провайдеров УЗ (мульти-провайдерный SSO)» — статус Готово, исполнитель Андрияшин Анатолий, в описании явно «Заказчик РосКосмос (AD + ALDpro)»**.
   - Богато: Confluence (Документация IVA ID, ADFS best practices, настройка Kerberos, IVA ID Service), helm-требования 1.0-455 (Kerberos/ADFS/SAML/ЕСИА), 1.0-451 (LDAP/AD), цепочка задач (стенд SSO IVAUC2-845, IP Auth IVAONE-11835).
   - Топология: контейнер `id` «IVA ID» (Java 21, форк Keycloak 26.6), рёбра web→id (вход OIDC), apigw→id (проверка токенов), id→NATS (события iva.id.*).
   - Слабое место: автотестов в Allure нет (matched_by=none) — шаг «тесты» по SSO не показывать.

2. **Мессенджер (федерация: групповые чаты/каналы/треды) — ТОП-2, богатейший статус-нарратив.**
   - Идеален для «заглубления в фичу в процессе»: покрытие по каждому требованию с честными вердиктами — Реализовано / Частично реализована / «Есть следы реализации».
   - Заказчики: Алроса, ЦБ. Кросс-платформенные задачи (iOS/Web «Федерация ч.3»).
   - Топология: `fedgw` Federation Gateway (Go, ECDHE/AES-GCM) + `ivcs-server`. Владельцы Медведев В.И., Родионов А.Л.; недавние исполнители Серов, Малых, Семеренко, Грибцов.
   - Тесты: 160 тест-кейсов заведено (автоматизация 0, прогонов в снапшоте нет).

3. **Федерация b2b (кросс-срез)** — как отдельная область для шагов 3–4 (контракты/топология/зависимости): federation-gateway ↔ ext-peer (инсталляция другой организации), шифрование ECDHE/AES-GCM. Пересекается с мессенджером — брать как «зависимости».

4. **ВКС / MCU** — широкий набор требований (демонстрация нескольких экранов, запись), 249 тест-кейсов, владелец Родионов А.Л. Осторожно: часть задач по записи отклонена (IVAONE-2632 Rejected).

Прочие богатые, но не в топе: Календарь (множественные календари, приглашения/статусы участия), Terra (транскрибация/суммаризация/мультиязычный перевод), Почта Phoenix/JUMP.

## ТОП-1 SSO — история статуса реальными данными
- **Сделано:** внешние провайдеры входа + redirect-URL (клиент знает провайдеры); мульти-провайдерный SSO Kerberos (IVAONE-12438 Готово, Роскосмос AD+ALDpro); LDAP/AD интеграция (1.0-451 met/partial); SIEM-интеграция (met).
- **В работе / частично:** 1.0-455 SSO Kerberos+ADFS+SAML+ЕСИА — вердикт **partial** («подтверждена только часть SSO-сценария, без явной клиентской настройки нескольких LDAP»); интеграция с SSO/IAM Keycloak/Avanpost (1.0-488, partial, заказчик Мосбиржа); 2FA (partial).
- **Не начато:** аутентификация через ЕСИА для публичного/SaaS-сервера IVA 360 (3.0-..., вердикт na).
- **Владелец/люди:** Андрияшин Анатолий (мульти-провайдер, DevOps), Лисенкова Дарья. NB: `who_to_involve(system_id=id)` вернул пустых владельцев — брать людей через requirement_text-вариант.
- **Топология-точки:** контейнер `id` IVA ID; интеграции web→id (OIDC), apigw→id (JWT), связь с ext-ldap (LDAP/Kerberos федерация каталога).
- **Тесты:** нет (matched_by=none).

## Валидированные демо-вопросы (что реально возвращается)

Красивый ответ (использовать):
- «Что по SSO сделано / в работе / не начато?» → analyst_context богато: 1.0-455 partial, IVAONE-12438 Готово, LDAP, мульти-провайдер. **GOOD**
- «Мульти-провайдерный SSO — статус и владелец?» → IVAONE-12438 Готово, Андрияшин, явный Роскосмос AD+ALDpro. **GOOD (killer-слайд)**
- «Что покрыто и какие зависимости по SSO?» → requirement_coverage 5 пунктов с вердиктами (SSO partial, Keycloak/IAM partial, 2FA partial, ЕСИА na, SIEM met). **GOOD**
- «Какие системы затрагивает, кому раздать?» → affected_systems даёт контейнер IVA ID (Keycloak fork), заказчик Мосбиржа; топология из arch_map. **GOOD** (но людей брать через requirement_text, не system_id).
- Мессенджер-федерация: «Статус федеративных чатов/тредов?» → пофичевые вердикты Реализовано/Частично/Есть следы, заказчики Алроса/ЦБ. **GOOD**

Избегать на демо:
- «Покажи % зелёных автотестов / прогон по SSO» → пусто (тестов нет). По любой области зелёного % нет: Allure отдаёт только счётчик тест-кейсов (Мессенджер 160, ВКС 249), automated=0, прогонов в снапшоте нет — не обещать зелёные дашборды.
- `who_to_involve` только по `system_id` (id и ряд контейнеров) → пустые владельцы; спрашивать через requirement_text.
- affected_systems по самому 1.0-455 → пустые контейнеры (требование не мапится на контейнер напрямую); опираться на 1.0-488 (→IVA ID) и arch_map.
