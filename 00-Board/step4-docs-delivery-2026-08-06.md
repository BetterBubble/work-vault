# Шаг 4: документация канала записи доезжает до людей

Три коммита в ветке `feat/iva-write-docs-delivery` от `origin/main` (`b905c5c9`).
Не мержено, не пушено, прод не трогался.

## Какое место оказалось правильным

Установлено фактом, а не догадкой. `scripts/wiki_sync_manuals.py:35-37` публикует в
**вики ИВА**: `https://wiki.iva.ru`, space `IVAPROJECT`, родитель `208703447`
«Набор профилей». Никакой «вики Tacticum» в дереве не существует — фраза
встречалась ровно в трёх местах шаблонов лейна и не имела referent'а нигде больше
(проверено грепом по всему репозиторию). Значит правильное место одно, и это то,
куда пишет скрипт.

Хост живой: `wiki.iva.ru/pages/viewpage.action?pageId=208703447` отвечает 302 на
логин с сохранённым `os_destination` — форма URL для этого инстанса верна (она же
используется в `templates/iva-analysis-fr/.../fr-authoring/SKILL.md:621`).

**Чего проверить не удалось и почему.** Прямой адрес самой дочерней страницы: REST
API отдаёт 401 анонимно, а токен я не запрашивал и не использовал. Поэтому в текстах
стоит адрес **каталога** (id родителя — константа скрипта, за неё ручаюсь) плюс
точное имя страницы и указание на колонку «Инструкция». Ссылка, которую я не могу
проверить, — это ровно тот дефект, который чиню.

## 2. Синк запускается сам

`.github/workflows/wiki-sync-manuals.yml` — push в `main` по путям
`docs/user_manuals/**`, `templates/*/manifest.yaml`, сам скрипт, сам workflow;
плюс `workflow_dispatch` для ручного повтора. `concurrency` на одну очередь: две
публикации разом переписали бы родительскую страницу с разных версий и получили бы
конфликт версии от Confluence.

Манифесты в триггере — небольшое расширение против брифа, называю явно: версии в
таблице каталога скрипт берёт из манифестов, и без этого триггера bump профиля
оставлял бы в колонке «Версия» прошлое значение.

Нет секрета `CONFL_TKN_SOL` — прогон падает с явным сообщением. Молчащий пропуск
создавал бы видимость свежей вики; тот же довод уже записан в
`nightly-install-e2e.yml`. Значение секрета нигде не печатается и в репозиторий не
кладётся — только имя, которое и так было в дереве.

**Что нужно от человека (единственное, чего я сделать не могу):** убедиться, что
репозиторный секрет `CONFL_TKN_SOL` в GitHub заведён. Проверить его наличие я не
могу — `gh` не установлен намеренно. Если секрета нет, первый же мерж даст красный
прогон с понятным текстом, и это лучше тишины.

`.github/workflows/*` в этом репозитории игнорируется по умолчанию, трекинг опт-ин
через `!`-правила — добавлена строка в `.gitignore`, иначе workflow просто не уехал
бы в коммит (и я бы это заметил только в CI).

## 3. Сторож

`apps/backend/tests/catalog/test_iva_write_wiki_address.py` — 12 тестов, падает если:

1. вики упомянута без URL там, где текст отсылает человека к документу;
2. адрес в текстах разъехался со скриптом — хост, space и id родителя тест
   вытаскивает из `scripts/wiki_sync_manuals.py`, а не хранит у себя;
3. имя страницы разъехалось с H1 квикстарта, по которому синк её заводит (ссылка
   остаётся формально живой, а нужной строки в каталоге уже нет);
4. синк перестал запускаться из CI — без этого первые три про красивый текст.

**Все четыре ветки доказаны мутацией**, каждая роняет ровно свой тест:

| Мутация | Поймал |
|---|---|
| убрать URL из фрагмента, вернуть «в вики Tacticum» | `test_wiki_is_mentioned_only_with_an_address` |
| `PARENT_ID = "999999999"` в скрипте | `test_address_matches_where_the_sync_actually_publishes` |
| переименовать H1 квикстарта | `test_page_is_called_by_the_title_the_sync_gives_it` |
| workflow больше не зовёт скрипт | `test_the_sync_is_actually_wired_into_ci` |

Слово «вики» само по себе адреса не требует: «привязка логина переносится на вики» —
про механику, и первая редакция сторожа на этом падала ложно. Гейт, который мешает
по делу, снимают целиком, поэтому адрес требуется только там, где рядом есть слово
про документ (страница/инструкция/каталог/пошагово/…).

## Чем правил

Символьных операций Serena — **0**, `Edit`/`Write` — 9 правок. Причина честная:
все изменения это markdown-фрагменты, YAML-манифест, CHANGELOG, workflow и новый
файл теста — символов там нет. Дополнительно: `activate_project` на worktree
проходил, но по ходу работы указатель проекта Serena увело на чужой worktree
(`helm-observability`) — состояние Serena общее на сессию, и параллельные агенты
его перебивают. Для правки по путям это безразлично, но для символьной работы в
многоагентной сессии — грабли, которые стоит знать.

## Что осталось

1. **Секрет `CONFL_TKN_SOL` в GitHub** — проверить наличие (я не могу).
2. **Первый прогон синка** после мержа опубликует страницу; до этого момента ссылка
