# Подключение: от нуля до первого теста

Пётр, ниже полный путь — от пустой машины до момента, когда агент собирает экран из компонентов
дизайн-системы. Порядок важен: каждый шаг проверяется до перехода к следующему, чтобы не искать
причину в конце.

Займёт около получаса, из них большая часть — разовая настройка, второй раз она не нужна.

## Что понадобится заранее

| Что | Где взять |
|---|---|
| Токен доступа `phk_…` | в чате поддержки Tacticum, приходит один раз. Ключ **личный**; если ты уже пользуешься другим профилем Tacticum — токен **тот же самый**, новый не нужен |
| Клон KMP-репозитория | мобильный клиент, работа идёт по коду |
| JDK и Gradle | проверка: `./gradlew --version` |
| Figma desktop | аккаунт с Dev Mode (Dev или Full seat) и доступом к мобильным макетам |
| CLI | Claude Code **или** Codex — инструкция покрывает оба, выбери свой |

**Про тариф, чтобы не выглядело как поломка:** инструменты работы с дизайн-системой идут по платному
тарифу. Если подписка на рабочее пространство не активна, сервер вернёт ошибку доступа, и со стороны
это выглядит как «всё сломано», хотя дело только в тарифе. Упрёшься — напиши мне, решается на нашей
стороне.

**Если у тебя стоял старый профиль `iva-kmp-brownfield`:** переход штатный, руками ничего править не
надо. Токен остаётся тот же, но **`installation_id` будет новый** — не переиспользуй старый. Секцию
старого профиля в `CLAUDE.md` / `AGENTS.md` удали целиком по её маркерам, роль впишет свою.

## Шаг 1. Подключить сервер Tacticum

**Если Claude Code** — один раз на машину:

```bash
claude mcp add --transport http --scope user tacticum-mcp https://mcp.tacticum.dev/mcp \
  --header 'Authorization: Bearer ${TACTICUM_TOKEN}'

claude mcp add --transport http --scope user context7 https://mcp.context7.com/mcp
```

Кавычки именно одинарные — тогда `${TACTICUM_TOKEN}` попадёт в конфиг literally и развернётся из
переменной окружения при старте.

**Если Codex** — в `.codex/config.toml` рабочей папки:

```toml
[mcp_servers.tacticum-mcp]
url = "https://mcp.tacticum.dev/mcp"
bearer_token_env_var = "TACTICUM_TOKEN"

[mcp_servers.context7]
url = "https://mcp.context7.com/mcp"
```

Дальше в обоих случаях: `export TACTICUM_TOKEN="phk_…"` (в PowerShell — `$env:TACTICUM_TOKEN = "phk_…"`)
и **перезапусти CLI**.

> ⚠️ **Codex — проверь версию до первого запуска:** `codex --version`. Старые сборки не понимают
> url-форму MCP и падают на чтении конфига с `url is not supported for stdio`. Лечится
> `npm install -g @openai/codex@latest`, конфиг менять не нужно.

**Проверка:** скажи агенту «вызови `whoami` через tacticum-mcp». Должен вернуться объект со списком
установок. Если «No authenticated scope» — не подхватился токен или не было перезапуска.

## Шаг 2. Узнать свой `installation_id`

В ответе `whoami` найди строку, где `profile_id = "iva-role-kmp"` — её `id` и есть твой
`installation_id`. Запиши, он понадобится на следующем шаге.

Такой строки нет — скажи агенту: «вызови `provision_installation(profile_id="iva-role-kmp")`».
Это самообслуживание, повторный вызов ничего не ломает.

## Шаг 3. Поставить профиль

Скажи агенту в чате своего репозитория, подставив свой идентификатор:

> Установи Tacticum-профиль **iva-role-kmp** в эту папку.
> 1. Вызови `pull_installation_content_manifest(installation_id="<ТВОЙ_ID>", target_cli="claude-code", update=false)` — для Codex подставь `target_cli="codex"`.
> 2. Для каждого `action` из `actions_meta` вызови `tacticum_fetch_action(action_id=…)` и **запиши тело в файл** по `action.path` — сервер файлы сам не пишет.
> 3. Фрагмент для `CLAUDE.md` придёт отдельным действием: **допиши секцию между маркерами, не заменяй файл целиком**.
> 4. Создай привязку установки — скилл `tacticum-context` запишет `.tacticum/context.yaml` с моим `installation_id`.
> 5. Сверь с `expected_action_count` и назови счёт: сколько записано, сколько пропущено как дубли.

**Проверка** — глазами по файлам:

```bash
ls .claude/commands/    # run-implementation.md, fix-bug.md, setup-code-intelligence.md
ls .claude/agents/      # coder.md, tester.md, test-runner.md
cat .tacticum/context.yaml   # реальный installation_id
```

## Шаг 4. Поднять навигацию по коду

```
/setup-code-intelligence
```

Команда добавит serena, проиндексирует репозиторий и попросит перезапуск. После него — всё, базовая
часть готова: можно реализовывать задачи и чинить дефекты. Дальше идёт часть про макеты.

## Шаг 5. Подключить Figma

1. **В Figma desktop:** открой любой design-файл → Dev Mode → секция «MCP» в inspect-панели →
   Server status **Enabled**.
2. **В своём CLI**, в корне KMP-репозитория:
   - Claude Code: `claude mcp add --transport http figma-desktop http://127.0.0.1:3845/mcp`
   - Codex, в `~/.codex/config.toml`: блок `[mcp_servers.figma-desktop]` со строкой
     `url = "http://127.0.0.1:3845/mcp"`

Адрес всегда локальный — сервер поднимает сама Figma на твоей машине.

**Проверка:** «перечисли инструменты figma-desktop» — должны появиться `get_metadata`,
`get_design_context`, `get_variable_defs`, `get_screenshot`, `get_code_connect_map`.

> **Figma desktop должен быть запущен всё время, пока агент работает с макетом.** И учти: квота
> запросов к Figma MCP общая на аккаунт, порядка 200 в день. Правило из следующего шага её экономит —
> поэтому его лучше не пропускать.

## Шаг 6. Разовое правило в репозитории

Это то, что связывает макет со словарём компонентов. Без него агент словарь просто проигнорирует, и
выглядеть будет как «ничего не работает» — а причина в одном непрочитанном файле.

Добавь в `AGENTS.md` репозитория (для Claude Code — в `CLAUDE.md`) блок целиком, вместе с маркерами:

```markdown
<!-- figma-mapping-pilot -->
## Макеты Figma → компоненты дизайн-системы

Если в задаче есть ссылка на макет Figma (figma.com/design/...):
0. Предпроверка макета: фрейм должен быть на auto layout и состоять из
   инстансов компонентов. Если это нарисованная руками геометрия — остановись
   и верни макет с конкретным списком проблем, не генери вёрстку.
1. Вызови design_get_tokens(design_system_id="iva-mobile") (tacticum-mcp) и
   возьми из ответа tokens["$extensions"]["dev.tacticum.code-bindings"] —
   словарь соответствия Figma-компонентов композаблам :core:design-system.
   Следуй его полю usage.
2. Через figma-desktop MCP: сначала get_code_connect_map по узлу (если непусто —
   используй его сниппеты), иначе get_metadata → имена инстансов → резолв по
   словарю (матчинг по имени: ключи Figma будут добавлены после подтверждения
   файла ДС дизайнерами).
3. Перед использованием композабла прочитай его source-файл из словаря —
   точные параметры и модели оттуда, не угадывай.
4. Цвета/типографика/отступы — только через IvaMessengerTheme
   (colors/typography/dimensions) и токены design_get_tokens; Color(0xFF...)
   и сырые dp/sp запрещены.
5. Квота Figma MCP общая: один get_metadata на узел, затем точечные вызовы.
6. Инстанс не найден в словаре → остановись и сообщи «компонент X не замаплен
   в code-bindings», не верстай вручную.
<!-- /figma-mapping-pilot -->
```

## Шаг 7. Смоук — пять минут, и понятно, что связка жива

Скажи агенту:

> Вызови `design_get_tokens` для `iva-mobile` и покажи, сколько компонентов в
> `tokens.$extensions["dev.tacticum.code-bindings"].components`.

- **34 или больше** — всё сошлось: профиль подключён, сервер отвечает, версия правильная.
- **Нет `$extensions`** — на сервере версия дизайн-системы ниже 0.2.0, напиши мне.
- **Ошибка доступа** — почти наверняка тариф, тоже напиши мне.

# Что тестировать дальше

После смоука имеет смысл пройти четыре сценария — они в отдельном письме, здесь коротко, чтобы было
в одном месте:

Порядок пересмотрен 27.07 после созвона с Беспаловым и Корнюшиным: их реальная задача —
**обновление дизайна на существующих экранах**, а не новый экран с нуля.

| Сценарий | Как запустить | Что значит «сработало» |
|---|---|---|
| **1. Обновить дизайн существующего экрана по новому макету** (главный) | «приведи экран X к макету» + ссылка на **конкретный фрейм** (правый клик → Copy link to selection, в ссылке есть `node-id`) | в диффе появляются `Iva*`-композаблы и обращения к теме; уходят ручные `Row`/`Column` и `Color(0xFF…)` |
| **2. Смена токенов и починка отвалившегося** | поменять значения токенов → задача «пройдись по экрану и приведи в соответствие» | экран реагирует на смену токенов без правок кода; там, где не изменилось, агент находит захардкоженные значения |
| **3. Перенос экрана из веб-клиента** | «перенеси экран X из веб-клиента в наш репозиторий» | исходный репозиторий только читается; перевод по таблице соответствий; агент сам сверяет паритет и называет расхождения |
| **4. Новый экран по макету** | обычная задача + ссылка на фрейм | на незамапленном элементе агент **останавливается** и говорит «компонент X не замаплен», а не выдумывает свой |

**Числовая сверка с макетом** в мобильном профиле работает **только против HTML-макета, не против
Figma** — ссылки Figma и PNG-экспорты в этой версии проверки объявлены вне области. Нужна числовая
сверка по Figma на мобильном — это отдельная работа, заявлять сейчас.

**Извлечения компонента из существующего кода в дизайн-систему в мобильном профиле НЕТ** — правила
создания компонента библиотеки реализованы для веб-контура. На созвоне 13:30 эта возможность была
подтверждена вслух; расхождение зафиксировано в [[call-2026-07-27-1330 — Беспалов и Корнюшин: реальный сценарий это обновление дизайна старых экранов]].

Общий критерий успеха на глаз: вёрстка из `Iva*`-композаблов и токены темы. Критерий провала:
самодельные `Row`/`Column` с ручными отступами там, где есть готовый компонент, или числовые цвета
в коде.

# Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| Нет инструментов `figma-desktop` | Figma desktop не запущен, или MCP не включён (шаг 5.1), или конфиг попал не в тот файл (шаг 5.2) |
| Агент игнорирует словарь, верстает сам | не подхватилось правило из шага 6 — проверь, что маркеры на месте |
| Нет `$extensions` в токенах | на сервере версия дизайн-системы ниже 0.2.0 — напиши мне |
| «Компонент X не замаплен» | это штатное поведение, а не ошибка: скажи мне, какой компонент — добавим запись в словарь |
| Ошибка квоты Figma | общий лимит на аккаунт исчерпан, до завтра; задачи без макетов не затронуты |
| Ответ агента обрывается на словаре | словарь лежит внутри общего файла токенов, целиком это ~325 КБ. Для проверки связки спрашивай список дизайн-систем, за конкретным цветом ходи точечным запросом. Мы это чиним |
| `url is not supported for stdio` | старый Codex — `npm install -g @openai/codex@latest` |

Что угодно из этого — пиши мне напрямую, разберусь быстрее, чем ты будешь искать причину.

# Служебное — в отправку НЕ идёт

**Источники шагов, всё сверено с репозиторием на 27.07:**
- Шаги 1–4 — `docs/user_manuals/iva-role-kmp-profile-quickstart.md` (части A и B, обе ветки CLI).
- Шаги 5–7 и блок правила — `docs/user_manuals/iva-kmp-figma-mapping-quickstart.md`.
- Состав роли (что именно приезжает одной установкой) — `templates/iva-role-kmp/manifest.yaml`,
  `depends_on`: core-base, development-core, iva-kmp-development-base, bugfix-base, lite-base,
  research-base, ui-base.

**Сознательные отличия от исходных квикстартов:**
1. **Имя профиля исправлено.** Figma-квикстарт требует `iva-kmp-brownfield` (строка 15) — это
   предыдущее поколение; здесь везде `iva-role-kmp`. Расхождение в репозитории надо править отдельно.
2. **Добавлен блок про платный тариф** — в квикстарте роли о нём не сказано ни слова, человек узнаёт
   об ограничении только по ошибке.
3. **Ошибка доступа названа нейтрально.** Код бросает `AuthError("seat_required")`, а навыки в
   профилях учат ловить «402», которого design-тулы не возвращают. Формулировка обходит расхождение.
4. **Сценарий числовой сверки описан честно:** `ui-mockup-match` в `tacticum-ui-base` — версия на
   149 строк с прямой оговоркой «HTML mockups only, Figma URLs and PNG exports are out of scope».
   Версия с числовым сравнением по Figma есть только в веб-контуре.
5. **Про `CLAUDE.md` против `AGENTS.md`** — исходная пилотная инструкция знает только `AGENTS.md`
   (конвенция Codex); для Claude Code добавлено указание на `CLAUDE.md`. **Проверено не было** —
   если у Корнюшина Claude Code, стоит подтвердить на первом же прогоне.
