**Гейт + три критика прошли, и критики нашли то, чего не нашёл гейт:**
- **#621, критик A:** приёмка задачи написана про другую популяцию. Сид идёт от вершины манифеста и
  вниз не ходит, поэтому названные в задаче `iva-rn-brownfield` 0.4.2/0.4.3 не заполнятся никогда.
  **Критерий переопределён:** вершина каждого профиля заполнена, 64 из 64. Основание — `iva-rn-brownfield`
  монолит (ни входящих рёбер, ни исходящих), а курс на роли из лейнов; и потребителя у исторических
  строк нет — `check_updates` отдаёт changelog ВЕРШИНЫ, а не версии клиента.
- **#621, критик B:** ключ `changelog` в манифесте ВХОДИТ в `canonical_payload_hash` — это был
  единственный сторож на поле, и широкое условие его снимало. По истории каталога секция опубликованной
  версии правилась без бампа **7 раз**. Условие сужено до «только в пустую колонку активной версии».
  **Моё прежнее решение «редактируемость намеренна» отменено.**
- **#670, критик:** обоснование устояло под тремя заходами — белый список фильтрует по ВЕСУ, не по
  безопасности (контроль доступа выше, на уровне профиля). Взяты 3 правки из 7 долгов: фикстура из
  невозможной комбинации, пин состава константы (3 ключа из 5 не были покрыты ничем), докстринг с ложью
  про «<10KB … never exceed» (реальный худший ответ **21.3 КБ**).

**Прод-числа по #621** (SELECT, `tacticum_catalog`): 525 строк, пустых **524**, фикс заполняет 64 (12.4%),
останется пусто 460 — роли 179/200, лейны 112/145, монолиты 169/180. Одна строка заполнена ВРУЧНУЮ через
