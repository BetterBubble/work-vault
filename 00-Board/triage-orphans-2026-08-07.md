# Подзадачи-сироты #145–#152 — разбор

Восемь подзадач в статусе `New` под четырьмя историями в статусе `Archived`. Все восемь — из одного
эпика **E5**: Qdrant-кластер (#43), embedding-модель (#44), пайплайн загрузки atomic-notes (#45),
retrieval API `search_practices` (#46).

## Что это за работа и что с ней стало

E5 описан в **ADR-0004** (`docs/adr/0004-postgres-qdrant-catalog-backend.md`, статус Accepted,
дата 2026-05-08 — тот же день, когда заведены подзадачи). Там же — вся терминология заголовков:
коллекция `tacticum_dev_practices`, atomic-notes, тулы `search_practices` и `recommend_stack`.

**Направление не реализовано и отменено. Шесть независимых подтверждений в `origin/main` и на проде:**

1. `search_practices` в коде **нет вообще** — единственное вхождение во всём дереве это упоминание
   в самом ADR-0004.
2. `recommend_stack` — «отложен в v1.x post-MVP per ADR-0011» (`README.md:124`).
3. Там же: «Vector embeddings в Qdrant для Knowledge — **post-MVP** per ADR-0013». ADR-0013 (MVP =
   3 deliverables) — тот акт, которым scope урезали.
4. `qdrant_collection: str = "tacticum_dev_practices"` в `apps/backend/src/backend/platform/config.py:47`
   — **мёртвый дефолт**: во всём дереве его никто не читает, Knowledge BC ходит в свою коллекцию
   через `KB_QDRANT_COLLECTION` / слаг модели.
5. **На проде коллекции practices нет.** Qdrant отдаёт ровно две: `knowledge_blocks` и
   `knowledge_blocks__baai_bge_m3_1024`.
6. «atomic-notes» во всём дереве встречается дважды: в ADR-0004 и в **списке отклонённых
   альтернатив** ADR-0048 («Atomic-note (Zettelkasten) вместо hybrid. Тяжело для
   авторинга/валидации архитектором»).

Нишу занял другой контур — Knowledge BC (`kb_*`, KBRun, MinIO+Qdrant): он индексирует **код
репозитория**, а не базу best-practices заметок. Это не переименование E5, а другая задача.

**Следов работы по самим подзадачам нет.** `git log --grep` по `#145`…`#152` и по родителям
`#43`…`#46` даёт только merge-коммиты GitHub PR с теми же номерами (все от 2026-07-24) — совпадение
нумерации PR и Taiga, к делу отношения не имеет. Описания всех восьми подзадач **пустые**, все
восемь изменены в одну минуту 2026-05-08T12:19 (заведены пакетом при планировании) и с тех пор не
трогались.

## Про даты: версия про каскад 18 июня не подтверждается

Все четыре родителя изменены **2026-06-20T09:52** — в одну минуту, то есть массовым действием. Но
это **не 18 июня**, а два дня спустя. То есть восемь сирот не «не попали под каскад» той уборки: их
родителей архивировали отдельным более поздним пакетным действием, и подзадачи за ним не потянулись.

Оговорка: у меня есть только поле «изменена» (последнее изменение), а не журнал операций. Что
именно произошло 20 июня в 09:52, из этого поля не следует — следует только что четыре истории
изменены одновременно.

## По каждой подзадаче

**#145 — Qdrant в Docker compose (namespace `tacticum_dev_practices`).** Половина сделана другим
контуром: Qdrant есть в `docker-compose.dev.yml` и в проде, контейнер `tacticum-qdrant-1` работает.
Вторая половина — тот самый practices-namespace — не создавалась никогда и не будет: коллекций на
проде две, обе от Knowledge BC. → **ЗАКРЫТЬ.**

**#146 — Backup/restore процедура + capacity planning по ADR-0004.** Единственная из восьми, где
работа **не сделана, а потребность жива**. На проде: `crontab -l` → «no crontab for root», в
`systemd list-timers` нет ни одного бэкап-таймера (только штатные ОС-шные), в `/root/backups` лежат
только **ручные** дампы Postgres, снятые перед рискованными сидами (последний — 2026-08-06 перед
qa-kit). У Qdrant **ноль снапшотов** (`/collections/.../snapshots` → `result: []`), а в нём живёт
прод-коллекция KB. Процедуры восстановления и capacity planning в репозитории нет. Формулировку
надо перецелить с practices на `knowledge_blocks`, но сама работа осмысленна без родителя. →
**ПЕРЕПОДЧИНИТЬ.** Кандидата назвать не могу: списка живых историй по эксплуатации я не видел,
доступа к Taiga у меня нет.

**#147 — Решение TEI vs external (OpenAI/Voyage/Cohere) — ADR с benchmark.** Решение принято и
реализовано: **ADR-0037** (Accepted, 2026-06-08) вводит порт `EmbeddingProvider` и два адаптера —
TEI и OpenRouter, выбор через `EMBEDDER_PROVIDER`. Вопрос подзадачи снят по существу, хотя сделано
это под другим эпиком (#464, US #466–475) и для Knowledge BC. Оговорка: замеров-benchmark, которые
просила подзадача, в ADR-0037 нет — есть выбор архитектуры и обоснование. → **ЗАКРЫТЬ.**

**#148 — Embedding service интегрирован; throughput target 100 notes/min.** Сервис интегрирован и
работает в проде: `TeiEmbeddingProvider` на bge-m3/1024, живая коллекция
`knowledge_blocks__baai_bge_m3_1024`. Цель «100 notes/min» потеряла объект вместе с notes — считать
её не на чем, и замера throughput в репозитории нет. → **ЗАКРЫТЬ.**

**#149 — Idempotent ingest-script: hash-based update detection.** Скрипта загрузки atomic-notes нет,
и самого объекта загрузки нет. Хеш-идемпотентность в проекте есть, но в другом месте и про другое —
`seed_profile.canonical_payload_hash` / `body_hash` для профилей каталога. → **ЗАКРЫТЬ.**

**#150 — Логирование added/updated/skipped + cron schedule.** Вторая половина того же
несуществующего пайплайна из #149: нечего логировать и нечего ставить в cron (на проде cron-задач
нет вовсе). → **ЗАКРЫТЬ.**

**#151 — MCP tool `search_practices(query, top_k)` с similarity scores.** Тула нет в коде;
направление отменено (ADR-0013 → post-MVP, `README.md:124`). Функционально нишу семантического
поиска занял Knowledge BC (`kb_get_task_context`, `kb_discover`) — но по коду репозитория, а не по
practices-заметкам. → **ЗАКРЫТЬ.**

**#152 — Latency target p95 < 300ms; load-test.** Относится к `search_practices`, которого нет.
Load-теста в репозитории нет; «p95 < 300ms» встречается только как цитата вендорского бенчмарка
Qdrant в ADR-0004 и как текст фикстуры в тесте извлечения НФТ. Если латентность KB-поиска нужна как
НФТ — это новая задача с новым объектом, а не эта. → **ЗАКРЫТЬ.**
