# Desktop (Squish): что за модель и что из нашего процесса применимо

Цель — обеспечить фактами **любой** ответ Президента по развилке desktop / мобильные, а не
угадывать заранее. Источник первичный: `90-Materials/squish-main.zip`, 47 файлов.

**Итог одной строкой: «не pytest» верно, но «не Python» — неверно.** Тесты пишутся на Python;
не работает не язык, а **вся механика pytest**. Это меняет оценку стоимости: применимого больше,
чем казалось, но применимо оно **выше уровня прогона**, а не в самом прогоне.

## Что это за модель — по `suite.conf`

```
AUT=CoreDesktopShell --modulesconfig modules_config_iva.json
LANGUAGE=Python
WRAPPERS=Qt
OBJECTMAPSTYLE=script
TEST_CASES=tst_setup tst_start_app tst_set_server tst_calendar_set_yesterday_30195 …
VERSION=3
```

| Свойство | Squish | Наши два стека |
|---|---|---|
| Язык тестов | **Python** | Python |
| Сбор тестов | **явный список в `suite.conf`** | автосбор pytest |
| Единица теста | каталог `tst_<имя>_<id>/test.py`, точка входа `main()` | функция `test_*` |
| Маркеры/наборы | **нет** | `-m suite_smoke` и др. |
| Фикстуры | **нет**, декоратор `@with_setup` | `@pytest.fixture` |
| Опции раннера (`--env`) | **нет** | есть, и это был блокер |
| Адресация элементов | **объектная карта Qt** — словари свойств (`type`, `container`, `visible`) в `names.py` | CSS/XPath (web), `locators/<платформа>/` (mobile) |
| Публикация прогонов | **следов Allure/TestOps не найдено** | `allurectl` + TestOps |

**`id` тест-кейса зашит в имя каталога** (`tst_calendar_set_tomorrow_30194` → TC 30194) — связь с
TMS есть, но соглашением об именовании, а не инструментом.

## Что из нашего процесса применимо, а что нет

**Применимо (выше уровня прогона):** разбор входа и постановка задачи · генерация кода теста
(язык тот же) · починка падений как процесс · дисциплина коммита и подготовка MR · ретро и
метрики ledger · конвенции page-object (в репе уже есть слой `shared/scripts/utils/`,
`chunks/`, 287 строк — структура узнаваемая).

**Неприменимо (уровень прогона и ниже):** всё, что завязано на pytest — маркеры, наборы,
опции раннера, фикстуры, `--strict-markers`, `conftest.py` как механизм. И **вся разведка UI**:
`playwright-cli` тут бесполезен, объектная карта Qt снимается инструментами Squish
(Spy/Object Map), которых у нас нет и лицензия на которые — отдельный вопрос.

**Практический вывод:** desktop — это **не третий стек в существующей рамке**, а вторая рамка.
Процессный лейн `tacticum-autotest-core` частично переиспользуем, но `run-tests`,
`fix-failed-test` и `dom-explorer` для него надо писать заново, а не параметризовать. Оценка
«отдельная работа, а не третий стек» из карты поверхностей — **подтверждается**.

## Находки по самой репе — не наши дефекты, но знать надо

**🔴 Учётные данные в открытом виде.** В теле теста:

```python
server_addres = "gamma-one.ivcs.su"
user_name = "t.morozova"
user_pass = "testtest"
```

Так в **5 файлах тестов** из 8. Плюс `shared/scripts/config.yaml` содержит пароли БД и админа
(`password: ivcs`, `password: 333666`) прямо в репозитории.

Это их репозиторий и их решение, чинить не нам. **Но для нас это ограничение проекта:** любой
наш скилл, который будет готовить MR из этого репозитория, обязан считать, что в диффе могут
быть секреты, — и предупреждать. У нас уже есть похожая норма про `allure-raw-*` в MR.

**Репозиторий незрелый.** `README.md` — **неотредактированный шаблон GitLab** («Already a pro?
Just edit this README.md»), содержательного описания нет. Тестов восемь, из них два служебных
(`tst_setup`, `tst_start_app`). `shared/scripts/conftest.py` **пустой** — то есть кто-то завёл
файл по привычке из pytest-мира, но механики за ним нет. Ровно тот класс, который мы у себя
называли «объявлено поле, механики нет».

## Сравнение развилки — фактами, решение не наше

| | Мобильные (ios + android) | Desktop (Squish) |
|---|---|---|
| Стек | `pytest+appium`, **один на две поверхности** [факт: `pytest.ini` и `options.py` идентичны] | Squish/Qt, рамка своя |
| Переиспользование процесса | высокое — механика pytest та же | частичное — только выше прогона |
| Готовность канона | стека нет, но есть два образца рядом | образцов нет вообще |
| Известные блокеры | `--env` без дефолта в сессионной фикстуре — **найден** | лицензия и инструменты Squish — **[?] не выяснено** |
| Постановка от заказчика | **нет** | **нет** |
| Что говорит канон | — | «дальше desktop», слова Президента с его же оговоркой |

**Обе поверхности упираются в одно и то же:** дословных требований заказчика нет ни по одной.
Это гейт приёмки, и он одинаков для обоих вариантов.

## Открытые вопросы

- **[?] Лицензия Squish** — коммерческий инструмент Qt. Есть ли она у команды, сколько мест,
  доступна ли нам для разработки профиля. Без ответа объём работы не оценить.
- **[?] Кто ведёт desktop-автотесты** — репозиторий выглядит заброшенным (8 тестов, шаблонный
  README). Возможно, поверхность вообще не в активной работе, и приоритет стоит перепроверить.
- **[?] Публикация прогонов** — следов TestOps нет. Значит либо не публикуют, либо делают вручную.
