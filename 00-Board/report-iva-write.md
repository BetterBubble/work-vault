# iva-write — где стоим

## Где стоим

**Код готов и проверен, ждём внешних людей.** Ветка `feat/iva-write-keystore` в helm: 18 коммитов,
42 файла, +9767 строк, **2371 тест / 0 падений**, одна голова миграций (`idn340_identity_binding`).
Локально, **не отправлено**, `main` не тронут, деплоя не было, живого прогона не было.

Сделано: хранилище личных доступов с шифрованием (мастер-ключ в окружении, без него сервис не
стартует) · поток согласия OAuth 2.0 к Jira/Confluence DC · сверка личности по двум идентификаторам
с привязкой при первом согласии · продление, отзыв, журнал подстановок · канал записи `/mcp/iva-write`
внутри helm + контейнер `mcp-atlassian` с пустым окружением рядом · бот выдачи доступа целиком ·
шов под будущую выдачу ключа Tacticum · `.env.example` · инструкция и текст запроса администратору.

## Следующий шаг

Ничего своего не осталось. По приходу ключей: развернуть по инструкции → живой прогон, **проходит
не автор** (норма от 29.07) → отчёт со ссылками на созданную страницу и задачу.

## Что заблокировано

1. **4 ключа от администратора Atlassian** (Client ID + secret на Jira и на Confluence). Без них
   экран согласия не существует. Текст запроса готов, не отправлен.
2. **2 ключа от команды ботов** + связность: их платформа **ни разу за 90 дней** не достучалась до
   helm при включённом канале. Ключи этого не решают.
3. **Слово Президента на деплой** — прод у нас только на чтение.
4. **Выдача ключа Tacticum тому, у кого его нет.** Проверено: ключи людям ИВА выпускает
   **project-hub** (`10.16.0.17:8770`), не tacticum-dev. Развилка вынесена, ответа нет: выпускать
   самим из нашего бэкенда (появится второй источник ключей) или просить право у project-hub.

## Что отсеяно — не делать

- **ADP и шлюз `platform`** — не нужны: у helm свой туннель к Jira/вики. Ветка шлюза (~1190 строк)
  лежит неиспользованной, выбрасывать не стал.
- **Профили** (переиздание манифестов, перевод людей) — отдельная тема по решению Президента.
- **Allure** — отложен решением руководителя.
- **Стадии на личных PAT** — отклонены Президентом, делаем сразу OAuth.
- **Свой инстанс Jira для проверки** — отклонён; обмен гоняется против заглушки по спецификации DC.

## Ключевые факты

- Выпустить PAT за другого человека **нельзя** — ограничение продукта, проверено на боевом сервере
  заказчика (API отвечает, что у запроса ровно два поля) и подтверждено тикетом Atlassian.
- **Адрес возврата:** `https://helm.tacticum.ru/api/iva/oauth/callback`, один на обе системы.
- Заголовок авторизации **не должен уезжать наверх**: ветка персональных заголовков в пакете
  включается только при его отсутствии. Держится кодом + тестом.
- Контейнер записи поднимается **с пустым окружением** — иначе сбой подстановки даст запись под
  служебной учёткой молча, с успешным ответом.
- **Не проверяемо до живых ключей:** поддержка PKCE (вынесена в настройку) · набор прав ·
  видимость почты (без неё бот не заработает целиком) · совпадение имён учётных записей между
  Jira и Confluence (на этом держится сверка для вики).
