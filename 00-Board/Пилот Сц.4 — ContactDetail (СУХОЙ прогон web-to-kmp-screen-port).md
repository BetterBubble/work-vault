## 2. Парити-гэпы

**Веб есть → KMP нет/расходится:**
- **G-1 (loading/error view-state):** нет паритета skeleton (SidebarUserSkeleton) и not-found→navigate. Требует правки State+Component+маппер → больше мелкого фикса, скоуп-флаг.
- **G-2 (guest-profile):** нет `ContactDetailVO.Guest` — внешний гость не покрыт.
- **G-3 (primary vs additional emails):** веб `additionalEmails` фильтрует `!isPrimary`; KMP-маппер `emails.orEmpty()` без разделения, `isPrimary` не переносится.
- **G-4 (call history):** `LastPastCalls` в KMP-экране отсутствует.
- **G-5 (general vs personal email/phone, contactGroup, company name):** `employee-info` различает generalEmail/generalPhone/contactGroup/company; KMP Default имеет только email/phone/emails/phones + companyId (id, не имя).

**KMP есть → веб-образец (эти 3 компонента) нет:** notification bottom sheet (mute), Favorites/Bot/Blocked как first-class VO, callStatus/mcuIsEnabled/call-кнопки. (Вероятно живут в веб-`ActionBar`/др. компонентах вне образца — н/д, не гэп-в-минус, отмечено как богаче.)

## 3. Статическая приёмка (4 критерия Сц.4)

- **(а) Собран из Iva*, ноль сырых Color/dp/material3 — ЧАСТИЧНО НЕ ПРОШЁЛ.** Findings: `ContactDetailScreen.kt` helper `ContentSpacer` (стр. 70-77) использует сырые `Spacer` + `Modifier.padding(top=size)` + тип `Dp`, `size=compose.utils.contentPadding` (похоже на сырую dp-константу, не токен `IvaTheme`). Есть роль `spacers`→`IvaSpacer` → FIX-1. Внутренности виджетов (`DefaultContactWidget` и др., `ContactInfoComponent`) НЕ в скачанных файлах → их Color/dp не проверяемы, н/д. Ноль `Color(0xFF…)` в скачанных файлах.
- **(б) Состояние поднято — ПРОШЁЛ.** `ContactDetailScreen` stateless: `component.contactDetailState.collectAsState()`, все события через `component::onUiEvent`. Ноль `mutableStateOf`/stateful-листьев в экране. State владеет Decompose-компонент.
- **(в) Списки LazyColumn с key — Н/Д (проверяемо частично).** Рендер emails/phones/team/buttons — в виджетах/`ContactInfoComponent` (не в файлах). В самом `ContactDetailScreen` списков нет. Канон для ported-фрагмента задан (keyed). Нюанс: короткие вложенные списки в скроллящемся профиле → keyed `forEach`/`key()` в Column, не вложенный LazyColumn (см. F-2).
- **(г) Незамапленный компонент → СТОП — ПРОШЁЛ (пробелы зафиксированы, не выдуманы).** См. п.4.

## 5. Фидбэк на навык `web-to-kmp-screen-port` (первый прогон)

**Помогло:**
- §1 «Read the source — fixed order» — прямой чеклист извлечения (route→store→view-state→pipeline→DS-имена→Transloco→REST). Дал структуру парити-анализа.
- §2 crosswalk Angular→Compose (`*ngFor`→`LazyColumn key`, `signal`→`mutableStateOf`, signalStore→Decompose) — готовая таблица соответствий.
- §3 Level-1 (MutableStateFlow+onXxx) с явным «не вводить MVIKotlin как часть порта» — удержало от over-engineering состояния.
- §5 guardrail «незамапленное → СТОП, не выдумывать Iva*» + §9 (инвентарь = shared kmp, 49) — прямо отработал на LastPastCalls/guest/skeleton.
- §7.1 component-level критерии (ноль Color/dp, keyed списки, hoisting) — дали чек-лист статприёмки.

**Не хватило / споткнулся:**
- **F-1 (объём входа для парити):** навык требует route/store/view-state/REST/Transloco (§1.1-1.8), но образец = 3 `.component.ts` без `.html`-шаблонов, без `data-access`, без shell-route. → Transloco-ключи и REST-контракт неизвлекаемы. Навыку стоит явно сказать: для парити нужны ещё `*.component.html` + `data-access` + shell-route, иначе легов §1.7/§1.8 нет.
- **F-2 (вложенные списки):** §7.1 «списки = LazyColumn с key» конфликтует с реальностью коротких вложенных списков (emails/phones в скроллящемся профиле) — вкладывать LazyColumn в LazyColumn нельзя. Навыку добавить оговорку: короткий вложенный список → keyed `forEach`/`key()` в Column, внешний контейнер = один LazyColumn.
- **F-3 (fix-parity скоуп):** для «починить существующий экран» навык не разграничивает мелкий фикс UI (ContentSpacer→IvaSpacer) vs структурную правку (добавить loading/error view-state, затрагивает State+Component+маппер). Полезен явный триаж «уровень изменения» (как §0 упоминает triage-tree, но для fix-parity кейса не раскрыт).
- **F-4 (figma_key=TODO):** §1.6/§5 матч по имени/роли работает, но словарь провизорный без ключей → матч Iva*↔веб-блок нельзя подтвердить (только назвать). Ожидаемо (Figma-доступ у президента), но каждый матч в п.«Матч-таблица» — provisional.
- **F-5 (виджеты вне экрана):** реальная Compose-вёрстка (Color/dp/списки) — в `*ContactWidget`/`ContactInfoComponent`, не в `*Screen.kt`. Крит. (а)/(в) на уровне одного `Screen.kt` почти не проверяемы. Навыку отметить: статприёмка требует читать и виджеты/part-компоненты, не только Screen.
