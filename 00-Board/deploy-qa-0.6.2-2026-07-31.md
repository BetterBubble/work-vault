# Деплой 31.07: выборочный сид сработал, обе роли проверены на стенде

**Вердикт: доставлено и проверено. Прод не задет ничем, кроме трёх QA-профилей.**

## Выборочный сид — впервые, и он работает

**Старый факт «сидер сидит весь каталог, выбрать один профиль нельзя» — УСТАРЕЛ.** Сидер
принимает каталог аргументом (`seed_community.py [templates_dir]`), значит достаточно смонтировать
папку с нужными манифестами:

```
docker compose -f docker-compose.prod.yml run --rm --no-deps \
  -v /opt/tacticum/apps/backend/scripts:/app/scripts \
  -v /tmp/templates-qa:/app/templates \
  catalog-mcp python scripts/seed_community.py templates
```

Вывод сида — дословно: `Seeded 3 profile(s) successfully`, и в нём же
`depends_on ordering: seeding base profiles first; deferred dependents: iva-role-qa, iva-role-qa-web`.
То есть двухпроходный порядок «лейн → роли» соблюдается и внутри подмножества.

**Почему это важно:** в `main` к моменту деплоя накопились чужие мержи по **19 профилям**, не
имеющим отношения к QA. Полный сид выкатил бы их заодно. Выборочный — не выкатил.

## Проверки после сида

**Ребро `depends_on` село верно** — единственная проверка, ради которой стоит останавливаться:
обе роли указывают на `tacticum-autotest-core` **0.4.3** и `tacticum-core-base` **0.4.0**.
Совпадает с тем, против чего гонялись тесты локально.

Ничего не сломалось: **битых пинов 0**, живых установок 26, версий в каталоге 336, контейнер
`catalog-mcp` healthy.

**Инженер перепинен** с 0.5.5 на **0.6.2** (установка `b258bb6b`, HTTP 200). Контент к нему не
толкается — доедет, когда он сам скажет «обнови»; признаком доставки будет его
`last_synced_version`.

## Прогон на стенде — обе роли, живой codex

Каноническим путём: агент сам вызывает `provision` → `pull` → применяет действия.

| Прогон | Результат |
|---|---|
| `iva-role-qa` — **обновление** до 0.6.2 | 79 действий, **удалений нет**; дерево 80 файлов, 15 скиллов, 3 субагента, 57 файлов канона, пустых 0 |
| `iva-role-qa-web` — чистая установка 0.2.1 | 74 действия, 73 файла, 14 скиллов, 52 файла канона, стек `pytest-selenium`, пустых 0 |

**Главное — правка `retro` доехала до живого дерева обеих ролей:** описание скилла читается как
«инфраструктуры **автотест-проекта**», вхождений `one-web-kmp` — **ноль**. То есть цепочка
«правка лейна → бамп → переиздание ролей → сид → установка» замкнулась и проверена на конце, а не
в середине.

**Осиротевших файлов нет** (`.agent-kit/craft/*.md` — 0): дерево уже было на 0.6.x, переезд
канона в `stacks/` случился раньше. Предупреждение про девять файлов актуально только для тех, кто
идёт с версий ниже 0.6.0.

## Мелочь, стоящая упоминания

`provision_installation` в первом прогоне вернул **существующую** тестовую установку с её старым
пином (0.6.1), и агент честно поставил именно её. Это заложенное find-or-create поведение, не
дефект — но означает, что **пин надо двигать до прогона, а не после**. Учтено: обе тестовые
установки перепинены, повторный прогон дал 0.6.2.

## Что осталось на утро

  безопасен, риск возникает в момент его обновления;
- **живая приёмка web-роли** — только у Евгения, нужен стенд `one-web` и учётки;
- **ключ стенда** `phk_7cd4f383` — **отозвать после ночной работы**.
