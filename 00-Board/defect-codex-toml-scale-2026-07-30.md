# Codex-рендерер пишет невалидный TOML: масштаб, обход, issue

**Дефект платформенный, сами не чиним** (указание ГД 30.07). Ниже — три вещи, которые
запрашивались: масштаб фактом, наличие обхода на нашей стороне, готовый текст issue.

Как воспроизвели и чем доказали — [[verify-qa-canon-install-2026-07-30]].

## 1. Масштаб — по живому каталогу, а не по `templates/`

Считано запросом к прод-базе (`ingredients` × `profile_versions`, только `status='active'`).
**Условие срабатывания:** `mcp_server_spec` со `stdio`-запуском И непустым `env_required` —
только тогда рендерер выводит словарь.

**Лейнов задето 7, активных версий — 25:**

| Лейн | Ингредиент | Активных версий |
|---|---|---|
| `iva-fr-analyst` | `iva-atlassian-write` | 8 |
| `iva-2-client-shell-dev` | `github` | 9 |
| `iva-analysis-base` | `iva-atlassian-write` | 3 |
| `iva-architect-mcp` | `iva-atlassian-write` | 2 |
| `iva-analysis-fr` | `iva-atlassian-write` | 1 |
| `iva-qa-mcp` | `iva-atlassian-write` | 1 |
| `iva-techwriter-mcp` | `iva-atlassian-write` | 1 |

**Ролей задето 5** (тех, что зависят от этих лейнов):
`iva-role-analyst` (4 версии) · `iva-role-architect` (3) · `iva-role-qa` (5) ·
`iva-role-qa-web` (1) · `tacticum-role-techwriter` (1).

**Живых установок на задетых ролях — 4, из них 2 наши тестовые.** Реальных пользователей **двое**:

- `iva-role-analyst` 0.1.2, метка «Codex work1 analyst role», `sync_count` 2 — **аналитик на Codex**;
- `iva-role-qa` 0.5.5 — инженер ИВА, `sync_count` 4.

**Уточнение к прежней оценке.** В памяти значилось «до 12 профилей». Цифра завышена и получена
счётом по файлам, а не по связям: считать надо активные версии лейнов (25) либо роли (5) — это
разные числа с разным смыслом, и путать их нельзя. Тот же класс ошибки, на котором обожглись с
дефектом F 28.07 (29 → 17 → 1).

## 2. Обход на нашей стороне — есть ровно один, и он с ценой

**Чего сделать НЕЛЬЗЯ:**

- **Подложить свой правильный TOML через манифест.** У `mcp_server_spec` нет per-CLI подмены тела.
  Докстринг `renderer.py:_cli_body_passthrough` говорит прямо: «Only agent ingredients carry a
  per-CLI body (skills/mcp/commands share one body across CLIs and are rendered canonically)».
  Механизм `codex_body_path`, которым мы обходили дефект склейки скиллов 28.07, здесь недоступен.
- **Убрать `env_required` из метаданных.** Он нужен claude-рендереру: `claude_code.py:121-122`
  собирает из него `env` для `.mcp.json`, и **там JSON уместен** — эта сторона работает. Убрав
  ключ, мы чиним codex и молча ломаем claude. Громкую поломку менять на тихую нельзя — это ровно
  тот анти-паттерн, из-за которого неделю разбирали доставку.

**Что сделать МОЖНО — единственный чистый обход:**

Пометить ингредиент `iva-atlassian-write` в `iva-qa-mcp` как `supports: [claude-code]`, то есть
**не отдавать codex ломающееся действие вовсе**, и добавить его блок в quickstart для ручной
настройки — правильным TOML:

```toml
[mcp_servers.iva-atlassian-write]
command = "uvx"
args = ["mcp-atlassian"]
env = { JIRA_URL = "${env:JIRA_URL}", JIRA_PERSONAL_TOKEN = "${env:JIRA_PERSONAL_TOKEN}" }
```

**Почему это приемлемо:** quickstart уже требует от codex-пользователя добавить руками три блока
MCP на Шаге 0. Четвёртый блок — не новая практика, а достройка существующей. Прецедент наш же:
28.07 дефект склейки скиллов на codex обошли на своей стороне, `renderer.py` не трогая.

**Цена, названная честно:**

1. Обход чинит **только наши две QA-роли**. Аналитик, архитектор, техпис и client-shell остаются
   сломанными до правки платформы — а аналитик **на проде с живым пользователем**.
2. Ручной шаг — это шаг, который забывают. Пока действие приезжало автоматически, оно хотя бы
   декларировало намерение; после обхода останется только текст инструкции.
3. Обход требует бампа `iva-qa-mcp` и переиздания обеих ролей (ребро замерзает на сиде) — то есть
   это не однострочная правка, а полноценный цикл доставки.

**Рекомендация:** обход **не делать до ответа платформы**. Дефект бьёт по всем профилям сразу,
правка у них тривиальная (для `dict` выводить TOML inline-таблицу вместо `json.dumps`), а наш
обход лечит седьмую часть проблемы ценой отдельного релиза. Если платформа не берётся в разумный
срок — тогда обход, и уже вместе с ним чинить остальные лейны единообразно.

## 3. Текст issue — готов, НЕ заведён

> **Заголовок:** `renderers/codex.py` пишет невалидный TOML для stdio-MCP с `env_required` — Codex не запускается вообще
>
> **Что происходит.** После установки профиля, содержащего stdio-MCP сервер с `env_required`,
> Codex перестаёт стартовать: конфиг не парсится, и не работает ничего, включая задачи, не
> связанные с профилем.
>
> ```
> Error loading config.toml:
> ~/.codex/config.toml:15:18: missing assignment between key-value pairs, expected `=`
> env = {"JIRA_URL": "${env:JIRA_URL}", "JIRA_PERSONAL_TOKEN": "${env:JIRA_PERSONAL_TOKEN}"}
> ```
>
> **Причина.** `apps/backend/src/backend/catalog/infrastructure/renderers/codex.py:162`:
>
> ```python
> body_lines.extend(f"{k} = {json.dumps(v)}" for k, v in entry.items())
> ```
>
> `json.dumps` сериализует словарь как JSON-объект (`{"k": "v"}`), а TOML требует inline-таблицу
> с присваиванием (`{ k = "v" }`). Для строк и списков JSON и TOML совпадают, поэтому дефект не
> проявлялся, пока не появился словарь — он возникает ровно в ветке `env` (строки 152-155) для
> stdio-серверов с `env_required`.
>
> **Как воспроизвести.** Установить на Codex любой профиль с таким сервером (например
> `iva-role-qa` или `iva-role-analyst`), применив действия из
> `pull_installation_content_manifest`, затем запустить `codex` — падает на загрузке конфига.
>
> **Масштаб.** 7 лейнов / 25 активных версий / 5 ролей; на проде две живые установки на задетых
> ролях (аналитик и QA-инженер). Список — в приложении.
>
> **Тяжесть.** Не деградация одного сервера, а полный отказ CLI. Пользователь получает нерабочий
> инструмент сразу после установки профиля.
>
> **Почему не поймали раньше.** Наши quickstart’ы велят настраивать MCP руками, и там блоки
> написаны верным TOML. Дефект срабатывает только когда действие применяет агент из манифеста —
> то есть в сценарии, который мы продвигаем как основной.
>
> **Предлагаемая правка.** Выводить значения по типу: для `dict` — TOML inline-таблица
> (`{ k = "v", ... }`), для остального оставить текущее поведение. Плюс тест, который парсит
> отрендеренный блок настоящим TOML-парсером — иначе тот же класс ошибки вернётся с любым новым
> типом значения.
>
> **Обходной путь для пользователя.** Убрать блок `env = {...}` из `~/.codex/config.toml` и
> прописать его вручную корректным TOML.
