# Агентный слой — официальные источники best practices

> **Коротко:** поверх любого стека живёт один и тот же слой — `AGENTS.md`, `llms.txt`, скиллы `SKILL.md` и MCP; за год у всех четырёх появились владельцы и спецификации (AGENTS.md и MCP — в одном фонде под Linux Foundation), а **семь из восьми проверенных вендоров уже отдают что-то машиночитаемо** — эти правила надо подключать, а не переписывать в профиль.

## Что покрывает эта заметка

Девять заметок `bp-*` разбирают конкретные стеки. Эта — то, что общее у всех двадцати профилей
разработчиков и не зависит от языка: **каким способом агенту вообще передают знание**. Четыре
механизма:

| Механизм | Что это | Кто владеет | Статус |
|---|---|---|---|
| `AGENTS.md` | файл инструкций в репозитории, «README для агента» | Agentic AI Foundation (Linux Foundation), передан OpenAI | открытый стандарт с фондом |
| Agent Skills (`SKILL.md`) | переиспользуемый набор инструкций с ресурсами, грузится по требованию | `agentskills.io`, изначально Anthropic | открытая спецификация |
| MCP | протокол доступа агента к инструментам и данным | Agentic AI Foundation, передан Anthropic | спецификация, ревизия `2026-07-28` |
| `llms.txt` | машиночитаемый индекс документации сайта | Jeremy Howard (Answer.AI) | **неформальное предложение, не стандарт** |

Для двух профилей — `brownfield-task-workflow` и `tacticum-dev-base` — эта заметка **единственная
релевантная**: они стек-агностичны, и всё, что у них есть, — это как раз агентный слой.

**Главный поворот года.** Раньше правила фреймворка приходилось пересказывать своими словами в
инструкции агента. Теперь вендоры публикуют их сами — файлом правил, скиллами, доками внутри пакета
или MCP-сервером. Всё, что мы переписываем руками, немедленно становится второй копией, которая
разойдётся с первой на ближайшем мажоре. Поэтому таблица ниже — не справка, а список того, что можно
**удалить из профиля и заменить подключением**.

**Итог: семь вендоров из восьми отдают хоть что-то машиночитаемо.** Правила как таковые — четверо
(Angular, Qt, Quarkus, Next.js) плюс Go с оговоркой. Только доки — Kotlin и React. Только инструменты
— Apple. Firebird в этот список не попал вовсе: агентного контура у него нет (см. `bp-firebird`).

**Два разных способа доставки правил, и они не эквивалентны:**

- **Скиллами** (Angular, Qt, Quarkus) — вендор пишет, как надо писать код. Это замена нашему тексту в профиле.
- **Доками в пакете** (Next.js) — вендор не пишет правил вообще, а лишает агента повода выдумывать: `AGENTS.md` из одной фразы отправляет его читать документацию своей же версии. Дословно из шаблона Next.js: «Your training data is outdated — the docs are the source of truth». Дёшево и работает на любом стеке, где доки можно положить рядом с кодом.

## Что изменилось за последний год

**1. У `AGENTS.md` и MCP появился общий владелец — и это не вендор.** 2025-12-09 Linux Foundation
объявил создание **Agentic AI Foundation**: Anthropic передала туда MCP, OpenAI — `AGENTS.md`, Block
— goose. Platinum-участники: AWS, Anthropic, Block, Bloomberg, Cloudflare, Google, Microsoft, OpenAI.
Практический смысл прямой: **это больше не форматы одного вендора**, и риск «нас бросят или закроют»
упал. Год назад закладываться на `AGENTS.md` было ставкой, сейчас — нормальным решением.

**2. Скиллы стали открытым стандартом с формальной спецификацией.** `agentskills.io` живёт отдельно
от документации Claude Code, у спецификации есть валидатор (`skills-ref`) и явные лицензии (код
Apache-2.0, доки CC-BY-4.0). Скилл, написанный под Claude, работает в Codex, Gemini CLI, GitHub
Copilot, Cursor и VS Code. **Это меняет экономику:** скилл пишется один раз на все инструменты, а не
под каждый.

**3. MCP `2026-07-28` — это заметно другой протокол, чем `2025-11-25`.** Крупное:
- **Протокол стал stateless.** Убраны сессии и заголовок `Mcp-Session-Id`, убрано рукопожатие `initialize`/`notifications/initialized`. Каждый запрос несёт свою версию протокола и возможности клиента в `_meta`. Состояние между вызовами — только явными хендлами, которые сервер выдаёт и которые передаются обычными аргументами инструмента.
- **Добавлен обязательный `server/discover`** — сервер обязан уметь рассказать о поддерживаемых версиях, возможностях и себе.
- **Roots, Sampling и Logging объявлены deprecated.** Рекомендованные замены: каталоги и файлы передавать параметрами инструментов или URI ресурсов вместо Roots; идти напрямую в API провайдера вместо Sampling; писать в `stderr` или OpenTelemetry вместо Logging.
- **Появился паттерн Multi Round-Trip Requests (MRTR)** вместо запросов, инициируемых сервером: сервер возвращает `resultType: "input_required"` со списком нужных данных, клиент повторяет исходный запрос, приложив ответы.
- **Введены политика жизненного цикла фич и реестр deprecated** — минимум **12 месяцев** окна депрекации. У протокола впервые появились предсказуемые правила устаревания.
- Ушли `ping`, `logging/setLevel`, `notifications/roots/list_changed`; ушла resumability SSE-потока (порванный поток = запрос переотправляется заново).

**4. У MCP появился слой расширений.** Tasks (долгие операции) уехали из ядра в официальное
расширение; рядом — MCP Apps (UI в диалоге) и расширения авторизации. Расширения **всегда выключены
по умолчанию**, эволюционируют независимо от ядра и требуют согласования обеими сторонами.

**5. Вендоры начали доставлять знание вместе с зависимостью, а не по сети.** Next.js кладёт доки в
`node_modules/next/dist/docs/`. Quarkus кладёт скилл в `META-INF/quarkus-skill.md` внутри JAR
расширения — добавил расширение, агент уже знает, как с ним работать. Это решает главную проблему
агента, **устаревшие данные обучения**, и решает её без сети и без ручной синхронизации.

**6. `AGENTS.md` научились генерировать инструменты сборки.** `create-next-app` создаёт `AGENTS.md`
и `CLAUDE.md` автоматически, для существующих проектов есть кодмод. Файл инструкций стал частью
скаффолда, а не ручной работой.

**7. IDE стала MCP-сервером.** Xcode 26.3 (февраль 2026) выставляет тулчейн наружу по MCP — ФС,
сборка, симулятор, превью, документация, отладчик. Разворот направления: раньше агент приносил
инструменты в IDE, теперь IDE отдаёт инструменты агенту.

**8. `llms.txt` разошёлся широко, но стандартом так и не стал.** Его отдают Angular, Next.js, React,
Kotlin, Claude Code, MCP, Agent Skills — и при этом за форматом по-прежнему нет ни консорциума, ни
RFC, только автор и GitHub. Опираться можно, гарантий стабильности нет.

## Что переписать в профиле прямо сейчас

- **Свести правила агента к одному `AGENTS.md`, а `CLAUDE.md` сделать однострочным (`@AGENTS.md`).** Так делает Next.js. Остальные инструменты читают тот же файл — правила физически не могут разойтись. [agents.md](https://agents.md/), [nextjs.org](https://nextjs.org/docs/app/guides/ai-agents)
- **Удалить из профилей вендорские правила там, где вендор отдаёт их сам** — Angular, Qt и Quarkus отдают готовые скиллы, Next.js бандлит доки в пакет. Вместо копии — подключение и ссылка; копия гарантированно разойдётся на следующем мажоре. Это касается как минимум четырёх наших стеков.
- **Для стеков без официальных скиллов повторить паттерн Next.js вместо написания правил.** Одна фраза в `AGENTS.md` — «читай доки из <путь> перед тем, как писать код, твои данные обучения устарели» — плюс доки рядом с кодом. Дёшево, не требует сопровождения и работает даже там, где вендор не дал ничего.
- **Разложить длинные разделы профиля в скиллы.** Всё, что является процедурой (чеклист ревью, порядок миграции, разбор типовой ошибки), должно стать `SKILL.md`: тело грузится только при активации, а раздел в `AGENTS.md` съедает контекст всегда. [code.claude.com/docs/en/skills](https://code.claude.com/docs/en/skills)
- **Привести наши `SKILL.md` к спецификации и поставить `skills-ref validate` в CI.** Требования жёсткие: `name` ≤64 символов только из `a-z0-9-`, обязано совпадать с именем каталога; `description` ≤1024 и обязано отвечать не только «что делает», но и «когда применять» — по нему агент решает, брать скилл или нет. Тело — под 500 строк, длинное в `references/`. [agentskills.io/specification](https://agentskills.io/specification)
- **В монорепо класть свой `AGENTS.md` в каждый пакет.** Побеждает ближайший к правимому файлу — единственный способ дать подпроекту свои правила, не раздувая корневой файл.
- **Пересмотреть наши MCP-серверы под ревизию `2026-07-28`.** Roots, Sampling и Logging — deprecated, новые реализации их не добавляют; окно депрекации 12 месяцев, то есть время есть, но планировать надо сейчас. Протокол стал stateless: серверы, державшие состояние в сессии, придётся переводить на явные хендлы. [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- **В инструкциях по MCP снять предположение о доверии к описаниям инструментов.** Спецификация прямо требует считать описания и аннотации недоверенными, если сервер не доверенный, — а у нас в контуре подключены сторонние MCP-серверы. [спецификация](https://modelcontextprotocol.io/specification/latest)
- **Не включать MCP-расширения «на всякий случай».** Они выключены по умолчанию по замыслу и требуют явного согласования; включённое лишнее расширение — это лишняя поверхность.

## Чего не нашёл / где источник слабый

- **`llms.txt` не является стандартом ни в каком формальном смысле.** Автор — один человек, площадка — GitHub и Discord, органа стандартизации нет. Все «спецификации llms.txt» из поиска — пересказы одной страницы. Завязывать автоматику можно, обещать стабильность формата нельзя. Это единственный из четырёх механизмов без владельца.
- **Официальные скиллы Go — не нашёл.** У Go есть MCP-сервер в `gopls`, но он про семантику кода (переходы, ссылки, переименования, диагностика), а не про best practices. Инструкции модели через `-instructions` существуют, но их содержимое я не разбирал — только факт наличия флага. Всё, что в поиске выглядит как «скиллы Go», принадлежит сообществу (`samber/cc-skills-golang`), а не команде Go.
- **Kotlin/JetBrains: свода правил для агента нет.** Есть `llms.txt` и постраничные `.txt`, есть MCP Kotlin SDK и фреймворк Koog — но это инструменты для *построения* агентов, а не правила *для* агента, пишущего на Kotlin. Материал существует постами блога JetBrains, то есть в форме, непригодной для подключения.
- **React отдаёт только `llms.txt`.** Ни скиллов, ни MCP, ни файла правил. То, что в поиске выглядит как «официальные скиллы React», принадлежит `vercel-labs`, а не команде React.
- **Apple не публикует правила текстом.** Xcode 26.3 отдаёт около 40 MCP-инструментов, но файла «как правильно писать на Swift для агента» у Apple нет; правила по-прежнему рассыпаны по документации и сессиям WWDC. Число инструментов взято из вторичных разборов, официального перечня я не открывал.
- **Число «60 000+ проектов» у `AGENTS.md` — заявление самого сайта и пресс-релиза**, не независимый замер. Порядок правдоподобен, но как метрику в отчёт брать не стоит.
- **Реестра скиллов в строгом смысле нет.** У `agentskills.io` есть Client Showcase (список поддерживающих инструментов), у Qt — присутствие в официальном MCP-реестре. Единого каталога скиллов, сопоставимого с npm, я не нашёл; распространение идёт через git-репозитории, плагины и, у Quarkus, через артефакты Maven.
- **Содержимое `angular.dev/assets/context/best-practices.md` — промпт, а не спецификация.** Файл начинается с «You are an expert in TypeScript, Angular...», то есть это готовая системная инструкция. Вклеивать его целиком в наш профиль поверх нашей же роли — конфликт ролей; брать надо содержательные разделы, не преамбулу.
- **Версии спецификации Agent Skills не нашёл.** Ни номера, ни даты ревизии на странице спецификации нет — понять «что изменилось с прошлой сверки» можно только диффом репозитория.
- **Governance AAIF по пресс-релизу не восстанавливается.** Формулировка «neutral, open foundation» есть, конкретная модель (directed fund и т.п.) в самом релизе не названа; вторичные источники говорят о directed fund, но первичного подтверждения я не получил.
