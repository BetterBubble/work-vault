## Что канон ДС говорит по существу (ADR-0061, Accepted 30.07)

Это и есть то «в репе всё есть в виде ADR», на что указывал Президент. Дословно ключевое:

> **`iva-mobile` — не самостоятельная ДС, а лист переопределений поверх веб-основы.**

> **Эталонная поверхность KMP — iva-one `@iva/design-system`** (подтверждено разработчиком).
> Не iva-core: конференц-поверхность — чужая ДС.

> **Гард источников макета** (лейн, с 0.13.0): доверенные входы — веб/десктоп фрейм UI KIT
> (`AG11paSthGC7zSoovfjip0`), живой iva-one, записи DQA-реестра (из любого раздела).
> Мобильный фрейм вне DQA → стоп с переспросом; фрейм iva-core → стоп.

> **DQA-реестр — обратная петля процесса (Сценарий 5).** Инструкция реестра версионируется и
> читается агентом живьём при каждом заходе (не вшивается); маршрутизация записей — навык
> `dqa-registry-intake` (0.14.0): Баг → `/fix-bug`, задача с эталоном → трек M, компонентный
> уровень → `ds-component-adoption`.

> **Геометрия KMP — ручная by design** (шкалы отступов/радиусов в ДС нет и не будет): сырой `dp` —
> инвентаризация в отчёт, не провал гейта; сырой цвет — нарушение всегда (870+ токенов).
> `letterSpacing` исключён из допусков сверки **постоянно** (команда 30.07).

Три факта-основания (Контекст ADR-0061):
- **Ф-1.** «Мобильной ДС в Figma не существует и не планируется» — файл «IVA Mobile DS: Elements»
  пуст; мобильный вид = адаптив веб/десктоп-макетов.
- **Ф-2.** Код KMP стоит на веб-рампе (body L/M/S + caption = 16/14/12/10 = веб `body.L/M/S/XS`).
- **Ф-3.** Мобильные макеты Figma для KMP — источник путаницы; дизайнеры завели DQA-реестр
  «IVA KMP DQA» с версионируемой инструкцией для ИИ-агента.

**Числа:** словарь code-bindings KMP — **34 привязки `Iva*` ↔ веб-мастер-компоненты**, живут в
`iva-mobile`; `figma_file_key` = веб UI KIT; **9 ключей + ~20 обоснованных `null`**.
Прод: ДС **iva-mobile 0.3.0**, **931 leaves / 841 цветов / 297 семантических**, лейн
`iva-kmp-development-base` 0.13.0…0.19.0.

**ADR-0062** — петля фидбэка: правило `maintainer-feedback` в `tacticum-core-base` 0.2.0 (все роли
получают бесплатно), метки `skill-drift:` / `skill-gap:` / `skill-conflict:` / `alt-approach:` /
`component-gap:`, читалка `GET /api-backend/stats/feedback` (scope `stats:read`, префикс
`/api-backend` обязателен), командные сигналы — сводкой в реестр helm, не в разработку.

## Конспект ТЗ `figma-ds-process-tz` — по зеркалу от 24.07 (⚠️ УСТАРЕЛО)

Живую страницу не читал. Локально есть её исходник в `90-Materials/figma-ds-process.zip`
(файл `figma-ds-process-tz.md`, **24.07.2026**). **Расхождение с заданием прямое:** лид просил
Сценарии 1–5 и августовский бэклог с пунктом D1 — **в зеркале от 24.07 сценариев ЧЕТЫРЕ и
никакого бэклога D1 нет**. Что ADR-0061 называет Сценарий 5 (DQA-реестр как обратная петля) —
в зеркале отсутствует. Значит **вики новее зеркала минимум на один сценарий и на весь бэклог**.

**Что в зеркале от 24.07 есть.**

Комплект: сводка + «Выбор ДС + мульти-репо» + четыре сценария отдельными документами.

Роли:

| Участник | Что делает | Чего не делает |
|---|---|---|
| Дизайнер | ведёт ДС в Figma: мастер-компоненты, варианты, именованные токены, описания | не трогает код и словарь |
| Конвейер | Figma-токены → сервер; словарь из кода; проверки расхождений; отчёты | не принимает решений |
| Разработчик + ИИ-агент | реализует компоненты и экраны из готовых деталей по словарю | не выдумывает самоделки |
| Администратор | переводит пин репо на новую версию ДС | — |

> **Общее правило всех сценариев:** источник правды по внешнему виду — **Figma**, источник правды
> по коду — **репозиторий**, а словарь и токены на сервере — **мост**, который автоматика держит
> актуальным. Руками словарь не правится.

- **Сц.1 — наполнение библиотеки:** gap-отчёт «есть в Figma, нет в коде» → реализация → словарь
  пересобирается. Приёмка: согласовано в четырёх местах (Figma, код, витрина, словарь).
  Первый gap-отчёт для веба построен, **~35 компонентов на разметку**.
- **Сц.2 — новый экран по макету:** предпроверка качества макета (auto layout, распознаваемость
  инстансов — иначе стоп и возврат дизайнеру) → резолв по словарю → незамапленный компонент = стоп.
  Приёмка: **ноль самодельной разметки**. Пилот для веба задеплоен.
- **Сц.3 — перевод репо на новую ДС:** нужна **переходная таблица** старое→новое («без неё —
  угадывание»), версии токенов параллельны, отчёт покрытия в штуках, откат = перевод пина назад.
  Живой пример: iva-one, **72 файла с легаси-импортами, 556 уже на новом**.
- **Сц.4 — перенос экрана iva-one (Angular) → KMP (Compose):** две опоры — макет Figma (внешний
  вид, приоритетен) + готовый экран iva-one (структура, состояние, контракт API, локализация).
  Это **переписывание**, не перемещение. Дословно: «отдельной мобильной библиотеки компонентов в
  Figma **нет** (файл „IVA Mobile DS: Elements“ пустой) — мобильные экраны рисуются на
  веб-компонентах» (ревью Figma 24.07). Приёмка: `runComposeUiTest` + Roborazzi.

Таблица статусов на 24.07: ✅ токены+словарь на сервере (прод 0.3.0, 49 компонентов, 32 со
стабильными Figma-ключами), ✅ quickstart web, ✅ **легитимный Figma-токен для конвейера**
(«выпущен владельцем; для CI позже — org-токен»), ✅ ревью-скрипт `scripts/figma_ds_review.py`;
⚙️ gap-отчёт вручную, ⚙️ словарь v1; 🔜 предпроверка макета, автосборка словаря + CI, git-sync
токенов из Tokens Studio, числовое сравнение экрана с макетом, переходная таблица, навык
web-to-kmp-screen-port, словарь KMP, выбор ДС по репо (ось 1), отдельная ДС `iva-core`,
мульти-репо source+target (ось 2).

> Главные дефициты дисциплины дизайнеров по ревью: **описания компонентов (6%)** и карта
> многофайловой ДС.

## Про Figma-доступ, квоты, токены, seat'ы — всё найденное

**Найдено НЕ в Taiga и НЕ в вики** — в ADR, CHANGELOG'ах, handover и сегодняшнем разборе.

1. **#749 — разведение токенов, статус New.** Личный PAT владельца используется конвейером;
   REST-квота `/v1/images` считается **на аккаунт**, поэтому инцидент 28.07 (разметка iva-core,
   ~50 скриншотов, `429 Retry-After: 352407` ≈ 4 суток) посадил именно владельца.
   **Бан держится до ~03–04.08.**
2. **Три Figma-хвоста ждут сброса квоты:** #747 (каталог Elements), #748 (чтение DQA findings),
   #744 (второй проход). В плане тиража это записано как «**A1 — только после сброса
   Figma-квоты ~03–04.08**».
3. **Планы и seat'ы (из разбора 31.07, проверено по доке Figma и живому `whoami`):**
   локальный desktop MCP-сервер — «available on a **Dev or Full seat for all paid plans**»;
   на Starter лимит **6 вызовов в МЕСЯЦ** при любом seat; Dev/Full на Professional — 200/день.
   Удалённый сервер на free отвечает, но с тем же лимитом 6/мес.
   `whoami` — вне лимита, им можно проверить план бесплатно.
4. **Второе условие, которое легко упустить:** аккаунт должен принадлежать **тому же плану, что и
   файлы макетов** («Ensure the user belongs to the plan to which the file being accessed belongs»).
   UI KIT — `AG11paSthGC7zSoovfjip0`.
5. **Figma Variables API — 403 навсегда** (scope Enterprise-only). Поэтому token-join цветов идёт
   через `design_get_tokens("iva-mobile")` из каталога Tacticum, а не из Figma.
   **Пилот не блокируется отсутствием Figma-MCP.**
6. **Навык `figma-access-setup`** (лейн 0.19.0, lane-only, в зеркало не входит) — визард канала:
   probe локального Dev Mode (127.0.0.1:3845) → инструкция включить → выпуск PAT со scope
   (`file_content:read`, `file_dev_resources:read`) + один дешёвый проверочный запрос → режим
   экономии REST → fallback на скрины. **Удалённого канала (`mcp.figma.com`) в лестнице нет** —
   пробел документации, зафиксирован сегодня.
7. **Наш quickstart уже требует платный тариф:** `docs/user_manuals/iva-kmp-figma-mapping-quickstart.md`,
   таблица «Что понадобится» — «платный тариф Figma и seat уровня Dev или Full».
8. **В зеркале ТЗ от 24.07** отдельная строка: «Легитимный Figma-токен для конвейера — ✅ есть
   (выпущен владельцем; **для CI позже — org-токен**)». Похоже, это предок того самого пункта D1,
   про который спрашивал лид, но подтвердить по живой вики я не могу.
