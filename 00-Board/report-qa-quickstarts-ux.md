## Какие проверки переписаны и почему теперь не дают ложных тревог

Формат у всех: **команда → ждём → не сошлось (что это значит и что делать)**.

Убраны/заменены проверки, дававшие «не установилось» при исправной установке:

| Было | Почему ложная тревога | Стало |
|---|---|---|
| `python -m tools.testops --help` | модуля у роли нет и от репозитория он не требуется — клиент TestOps едет в поставке; команда падает `ModuleNotFoundError` при полностью исправной установке | `ls .agent-kit/tms/scripts/testops_cli.py`, плюс запуск **интерпретатором проекта**; отдельной строкой «чего делать НЕ надо» |
| `grep "INSTALLATION_ID" CLAUDE.md` | плейсхолдера нет ни в одном лейне QA-ролей (проверено грепом по `tacticum-core-base`, `tacticum-autotest-core`, `iva-qa-*`, `iva-pytest-*`, `iva-squish-*`) — текст был скопирован из `iva-fr-analyst` | удалена; из промптов установки убран и шаг «замени плейсхолдер» |
| `grep -c "tacticum:iva-role-qa"` | это **префикс** для `-web`/`-mobile`/`-desktop`: проверка проходит при установленной чужой роли | `grep -c "<!-- tacticum:<PROFILE_ID> -->"` — полная форма маркера, различает однозначно; разобраны исходы `0` и `2+` |

| `ls ~/.claude/skills/` | навыки кладутся в репозиторий | осталась одна строка в таблице симптомов «ищете в `~/` — смотрите `./.claude/skills/`» |

## Остальное из списка

- **Перезапись — до установки.** Шаг 2 общей инструкции: чистый `git status` → ветка-бэкап →
  установка → `git diff` глазами → своё вернуть `git checkout`. В mobile-странице продублировано
  отдельной врезкой: там свой кит богаче нашего.
- **Порядок в разделе Claude Code:** токен → регистрация серверов → перезапуск (был обратный,
  гарантированный 401 на первой попытке). PowerShell-присваивание помечено как Windows, для
  bash дан `export`.
- **Откуда брать значения:** `TESTOPS_ENDPOINT`/`TOKEN`/`PROJECT_ID` (хост и `project_id`
  называет команда, apitoken выпускается в профиле TestOps), Atlassian PAT (профиль Jira),
  `--env` (называет человек; закрепляется параметром `default_env` секции `[craft]` в
  `.kit/answers.toml`).
- **Первая полезная команда:** три готовых промпта на каждой странице; у web — со стендом в
  тексте промпта, у mobile — с таблицей четырёх значений и командами их получения
  (`adb devices`, `xcrun simctl list devices available`, `local:15555`/`local:25555`) и
  расшифровкой `<pytest-проекта>` = `./.venv/bin/python -m pytest`.
- **Codex-шаг в web** перенесён после установки и снабжён оговоркой: `playwright-cli` не входит
  в число 18, после ручного шага в каталоге навыков будет 19.
- **Десктоп:** карточка `qa-role-desktop-card.md` на 42 строки (кому · 🔴 лицензия Squish как

  пака · чего не обещаем: TestOps не подтверждён, креды в референсе открытым текстом). Строка
  десктопа в таблице ролей — «по запросу», без ссылки.

## Отклонение от постановки — одно, сознательное

В пункте 8 списка был указан референс `--env` = `at-test-1-one`. **Не взял.** Живой канон знает
для `one-web-kmp` дефолт `kmp-stage`, а `at-test-1-one` встречается только в CHANGELOG
депрекированного монолита — как **отозванный хардкод**, который и дал
`KeyError: 'at-test-1-one'` в первом прогоне инженера. Написал по канону: имя стенда называет
человек, закрепляется через `default_env`; для mobile — договорный `at-develop3` из README
проекта.

## Что нужно решить лиду (за пределами моей зоны)

**Общая инструкция не попадёт в вики.** `scripts/wiki_sync_manuals.py` синхронизирует только
`docs/user_manuals/*-profile-quickstart.md`, у которых есть `templates/<profile_id>/manifest.yaml`.
`qa-role-install-common.md` и `qa-role-desktop-card.md` под шаблон не подходят — а три страницы
ролей, которые синхронизируются, теперь на общую ссылаются. В вики ссылка будет битой.

Варианты: добавить в скрипт список «страниц без профиля» (правка `scripts/`, вне моей зоны) ·
либо публиковать общую страницу руками · либо оставить обратную совместимость и продублировать
механику. Ждёт решения.
