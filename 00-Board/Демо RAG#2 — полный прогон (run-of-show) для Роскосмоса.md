# Демо RAG#2 `/analyst` — полный прогон (run-of-show)

Сценарий по логике Димы с созвона: **ответственный за область → «что у нас с этим?» → сделано / не сделано / в процессе → «то, что в процессе — как технически сделать, кому задачу, что спросить» → система отвечает.** Персона — ТПО/ответственный, tenant=iva. Шпаргалка вопросов — [[demo-stsenarii-rag-2-shpargalka-vse-akty-voprosy]]; факты по фичам — [[demo-hero-features-iva]] + [[demo-hero-features-iva-part2]].

**Формат акта:** Постановка · В (вопрос дословно) · **Эталон ответа** (сверять живой ответ морды с этим — рубрики, факты, ID; `[n]` = цитаты) · Углубление · Нарратив · Переход. Эталон — ориентир по СОДЕРЖАНИЮ и структуре, не по буквам.

## АКТ 1b — SSO: как ДОБАВИТЬ вход через ЕСИА (design-режим) ⭐ killer
Не статус, а **проектирование на фактах** — то, что просил Дима: «продумаем, как технически сделать, кому дать, что уточнить». Прямое попадание в ИБ/on-prem-повестку Роскосмоса.

**Постановка:** «Статус увидели. Теперь проектная задача: нам нужен вход через Госуслуги (ЕСИА). Как добавить?»

**В (design):** *Как нам добавить в IVA ID вход через ЕСИА (Госуслуги)? Куда встраивать, что затронет и кого подключить?*
**Эталон ответа (design-рубрики):**
> **Куда встраивать.** ЕСИА добавляется как ещё один внешний Identity Provider на контейнере IVA ID (форк Keycloak 26.6) — механизм тот же, что для действующих внешних провайдеров (OAuth2-редирект, RedirectAuthStrategy); отдельной новой службы не нужно [1][2].
> **Что затронет.** Рёбра `web→id` (вход OIDC), `apigw→id` (проверка токенов), `id→nats` (события iva.id.*) — ЕСИА-логин идёт по тем же путям [1]. Требования: 1.0-455 (SSO+ADFS+SAML+ЕСИА), 1.0-497; 2FA — 1.0-500 [3].
> **Прецедент (на что опереться).** В ВКС вход через ЕСИА уже реализован («Вход в мероприятие через ЕСИА», OpenID в TatSud) — переиспользовать подход/конфигурацию [4]. Jira: VCSWEB-6884, VCSWEB2-8182.
> **Кому задача.** Владелец IVA ID — Андрияшин Анатолий; ЕСИА-конфиг — команда IVA ID совместно с ВКС-командой (у них есть опыт) [1][4].
> **Что уточнить.** Отдельной API-ручки «добавить IdP» нет — это конфигурация Keycloak (api_registry_check: found=false) [5]; уточнить: регистрацию системы в ЕСИА (мнемоника/сертификаты); нужен ли ЕСИА в on-prem-контуре Роскосмоса или только для публичного 360; сроки (в требованиях к IVA One 3.0 статус «Не реализовано, Q2 2027»).

**Почему killer:** система не пересказывает статус, а **проектирует по фактам** — видит топологию, находит прецедент (ЕСИА в ВКС), честно говорит, что API-ручки нет. «Мозг, а не поиск».
**Нарратив:** «Вот это и есть постановка задач: куда встроить, что затронет, кому дать, что уточнить — из наших же данных.»
**Запасной design-вопрос:** *Как добавить в загрузку файлов мессенджера DLP-проверку по аналогии с антивирусом ICAP?* (владелец Сухов; прецедент — антивирус IVAONE-7081 закрыт).
**Переход:** «Возьмём область пошире — мессенджер.»

⚠️ **Работает только после правки промпта (design-режим) + добора `nearest_spec`/`related_tasks` в контекст** — иначе морда ответит как на статус. Спека для лида ниже/на доске.

## Закрытие
Формула «поставим ADP вам»: **Защищённость** (контур) → **Управляемость** (Helm) → **Интеллект** (синтез, не поиск). Про сроки осторожно: глубина = результат долгого ингеста данных ИВА.

## Как сверять живой ответ с эталоном
Совпадать должны: (1) набор рубрик; (2) ключевые факты/ID (IVAONE-12438 «Готово», владельцы, %); (3) цитаты `[n]` реально ведут на источники; (4) нет выдуманного сверх контекста. Расхождение по фактам/галлюцинация = дефект, не «стилистика».

## Чего избегать во всём прогоне
- «% зелёных автотестов» вне Звонков/Почты. Запись/скачивание ВКС; настройка SIP-trunk; ссылка переводчика Terra. `who_to_involve` по system_id (пусто).
