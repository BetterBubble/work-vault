## Пробел 1 — ADR-first вход `/start-task`
**Вход:** `/start-task "<задача>" <target-dir> <путь-к-готовому-ADR>` (3-й аргумент = ADR-черновик, напр. из `/start-research`).
**Ожидается:** конвейер работает ОТ поданного ADR — НЕ пишет решение с нуля; проверяет полноту (context/decision/alternatives/consequences); сверяет упомянутые API/модули с кодом по KB+helm; расхождения показывает ДО планирования; молча не досочиняет. Гейт классификации при заданном `$3` **исключает режим research** (решение уже принято) → классифицирует ПОЛНЫЙ vs ЛАЙТ.
**Зелёный =:** в выводе Phase 1 — явная фраза «работаю от поданного ADR», перечень сверенных API + список расхождений (или «расхождений нет»); НЕ сгенерирован новый ADR с нуля; при `$3` агент не предлагал `/start-research`.
**Контракт research→build:** прогнать связку `/start-research` (получить ADR-черновик) → `/start-task … <ADR>` — черновик принят как вход, конвейер продолжает от него. Зелёный = наработка research не потеряна, приёмник её использует.
**Контроль (без ADR):** `/start-task "<задача>" <dir>` без `$3` — поведение как раньше (регресса нет).

## Пробел 2 — 2-й слой mode-review в Фазе-1 (`tacticum-workflow`)
**Вход:** задача, которую на постановке (Phase 1) видно как «не тот режим»:
- PIN выродился в 1 стадию без UI/новых классов → ожидается предложение `/lite-task`;
- KB не отвечает / механизм не ясен / «шаги неизвестны» → предложение `/start-research`;
- вскрылись независимые работы (второй дефект / «заодно») → предложение split A→B.
**Ожидается:** после Phase 1, перед Gate summary — агент **предлагает** смену (не молча, не деградирует сам), формула «Похоже, режим выбран неверно. Факт: … Предлагаю …», сохраняет наработки через `handoff.md` (причина было→стало→почему в самом handoff).
**Зелёный =:** в логе Phase 1 — блок предложения смены с фактом + `Tasks/<N>/handoff.md` создан с причиной/сделано/выяснено/не-подтвердилось; НЕ начата Фаза 2 полного конвейера до подтверждения.
**Якорь-кейсы (из proposal):** 12470 (lite по ТЗ → раздувается в новую механику → эскалация на плане); 12114 («фикс» → неизвестный механизм → research).

## Пробел 3 — lite→research (мини) + внутрипроцессные триггеры
**Вход:** `/lite-task` на задаче, где по ходу корень/механизм НЕ подтверждается:
- правишь файлы вне ордера; корень дефекта не подтвердился; verify падает 2-й раз в одном месте.
**Ожидается:** STOP + предложение `/start-research` (мини) с тем же `handoff.md` — не «долбить вслепую», не капитуляция. (Плюс существующая эскалация вверх в полный сохранена.)
**Зелёный =:** в логе lite — блок «root/mechanism not confirmed → propose /start-research» + handoff; лайт не продолжает слепые правки. Отражено И в SKILL, И в командном `lite-task.md` (проверить оба).
**Якорь:** 12150 (страшный звонковый баг → мини-research → правка 28 строк).

## §1.2 — «инфра» как свойство лейна, а не отдельный режим (`tacticum-lite-base` 0.1.3)
**Вход:** `/lite-task` на инфраструктурной мелочи — правка сборки / версии зависимости / шага CI / конфигурации тулчейна, по объёму подходящая лайту (не новый модуль, не серверный контракт).
**Ожидается:** лейн **берёт задачу в работу и НЕ эскалирует** только из-за того, что она инфраструктурная. При этом внутри лейна: (а) предупреждение о радиусе поражения — что правка может потянуть хвост на соседних платформах/модулях; (б) ошибка тулчейна трактуется как **предмет работы, а не блокер** — стоп-правило «verify падает 2-й раз в одном месте» на намеренно прорабатываемую toolchain-ошибку не распространяется.
**Зелёный =:** в логе lite нет эскалации с обоснованием «infrastructure»; есть предупреждение о blast radius; при повторной ошибке сборки агент продолжает работу над ней, а не останавливается по стоп-правилу.
**Контроль (регресса нет):** настоящая эскалация вверх сохранилась — задача с новым экраном / новым модулем / серверным контрактом / >~10 файлов по-прежнему уходит в полный конвейер. Инфра **не стала** отдельным режимом: в таксономии режимов её нет.

## База (режимы #142) — быстрый смоук
- `/lite-task` на refactoring-S/feature-S: рабочий ордер + ок-гейт (правки только после «ок»), test-first, отчёт в чат без файлов, smoke в хрупкой зоне.
- `/start-research`: без клонирования репо, верификация утверждений по коду, честное «не найдено», report+ADR-черновик, без кода.
- 1-й гейт классиф. на входе `/start-task`: достаточность→классификация→ПОДТВЕРЖДЕНИЕ; bugfix→`/fix-bug`, refactoring-S/feature-S→`/lite-task`, research→`/start-research`.

## Как гонять (когда дойдём)
- Площадка: тест-стенд `teststand` (38.180.236.39, codex/node) или интеграция у команды-потребителя. Сервер НЕ трогаю — прогон делает держатель стенда/команда по этому чеклисту.
- По каждому пункту: подать вход → снять лог/артефакт → сверить с «зелёный =».
