### Как устроена поверхность

Не FastMCP-сервер, а чистое ASGI-приложение: ответ streamable-http идёт SSE-потоком, и
обычный обработчик пришлось бы буферизовать целиком. На каждый запрос:

1. **личность** — `require_write_identity` (та же зависимость, что у ручек согласия):
   токен обязателен ВСЕГДА, включая `auth_required=False`. Ни `subject`, ни почты во
   входе поверхность не принимает;
2. **доступ** — `iva_write.issue_credentials` в процессе, своя сессия и свой коммит
   (журнал должен пережить запрос и тогда, когда выдавать нечего);
3. **заголовки** — клиентские, кроме вырезанных, плюс пары доступов;
4. **прокси** — тело и метод как есть, ответ отдаётся чанками по мере поступления.

### Границы, которые держит код (и тесты)

- **`Authorization` наверх не уходит ни в каком виде.** Вырезается вместе с
  `proxy-authorization` и `cookie` на входе, а не «обычно не добавляется». Причина
  проверена по исходникам пакета: `UserTokenMiddleware` (`servers/main.py:689-700`) на
  `Bearer` ставит `user_atlassian_token` + `auth_type="oauth"`, а ветка пер-запросной
  подстановки (`servers/dependencies.py:855-861`) требует `auth_type == "pat"` И
  отсутствия `user_atlassian_token`. Протечка = молчаливый уход на глобальный клиент.
- **Клиентские `X-Atlassian-*` вырезаются целиком** (весь префикс, включая
  `X-Atlassian-Cloud-Id`): иначе вызывающий назначил бы себе адрес системы и токен.
- **Fail-closed**: нет живого доступа ни к одной системе → 403, наверх не уходит
  ничего. Неожиданная осечка выдачи → 503 без трейса (в трейсе обработчика в этот
  момент расшифрованные доступы). Контейнер недоступен → 502 без пересказа httpx.
- **Частичное согласие не блокирует**: одна пара заголовков вместо двух. Приятный
  побочный эффект, найденный в исходниках: пакет фильтрует и `tools/list` по
  присланным парам (`servers/main.py:260-268`), поэтому агент увидит инструменты
  ровно той системы, доступ к которой есть.
- **Журнал** ведёт `issue_credentials` — строка на каждую систему (`ok`/`denied`/
  `missing` + код причины), без секрета. Своей копии журналирования в поверхности нет
  намеренно: два места записи разошлись бы.
- **Секрет** живёт только в заголовках исходящего запроса: не логируется, не попадает
  в тела наших ошибок и не возвращается вызывающему. Наружу из ответа контейнера
  пропускается узкий список заголовков (`set-cookie` не проходит).

## Как поднимается контейнер (это в инструкцию)

```yaml
mcp-atlassian:
  image: ghcr.io/sooperset/mcp-atlassian:0.23.0
  environment:
    TRANSPORT: "streamable-http"
    HOST: "0.0.0.0"
    PORT: "9000"
    STREAMABLE_HTTP_PATH: "/mcp"
    ATLASSIAN_EXTERNAL_AUTH_ENABLE: "true"
    MCP_ALLOWED_URL_DOMAINS: "iva.ru"
  extra_hosts:
    - "jira.iva.ru:172.18.0.1"
    - "wiki.iva.ru:172.18.0.1"
  expose: ["9000"]
  restart: unless-stopped
```

Пояснения, без которых конфигурация не воспроизводится:

- **окружение пустое по учётным данным** — ни `JIRA_USERNAME`, ни `JIRA_API_TOKEN`, ни
  `JIRA_PERSONAL_TOKEN`, ни `CONFLUENCE_*`, ни `ATLASSIAN_OAUTH_*`. И `.env` helm сюда
  монтировать нельзя: пакет сам делает `load_dotenv(override=True)` из своего рабочего
  каталога;
- **`ATLASSIAN_EXTERNAL_AUTH_ENABLE=true` обязателен** — без него `JiraConfig.from_env`
  требует `JIRA_URL` и падает на старте (`jira/config.py:243-248`);
- **`MCP_ALLOWED_URL_DOMAINS=iva.ru` обязателен, и это неочевидно.** У пакета есть
  SSRF-проверка: адрес, чей hostname резолвится в неглобальный IP, отклоняется
  (`utils/urls.py:140-143`). У нас `jira.iva.ru` намеренно указывает на docker-gateway
  туннеля (172.18.0.1), то есть БЕЗ allowlist канал отказывал бы на каждом запросе.
  Allowlist отключает только DNS-проверку — запрет localhost, IP-литералов и проверка
  редиректов остаются;
- **транспорт задаётся переменными, а не `command:`** — так конфигурация не зависит от
  формы ENTRYPOINT образа (`__init__.py`, блок precedence: env → флаг);
- **`ALLOW_GLOBAL_CRED_FALLBACK` не ставить** (дефолт off): при нём пакет пропускал бы
  запрос без наших заголовков вместо 401;
- наружу контейнер не публикуется: своей аутентификации у него нет, его защита — это
  отсутствие маршрута снаружи.

Переменные helm (в git, не секреты; `docker-compose.prod.yml`):

```
HELM_IVA_WRITE_MCP_URL=http://mcp-atlassian:9000/mcp
HELM_IVA_WRITE_JIRA_URL=https://jira.iva.ru:8443
HELM_IVA_WRITE_CONFLUENCE_URL=https://wiki.iva.ru:8443
```

Адреса систем ДЛЯ КОНТЕЙНЕРА отдельны от публичных: контейнер видит Jira/вики через
туннель (порт 8443), а Host и TLS SNI остаются настоящими за счёт `extra_hosts` — тот
же приём, что у allure и у ингеста RAG#2. Не заданы → подставится публичный `base_url`
из OAuth-конфига. `HELM_IVA_WRITE_MCP_URL` не задан → поверхность отвечает 503 с
причиной, а не 404 (иначе «не настроено» неотличимо от «не задеплоено»).

**Сверить перед деплоем:** `HELM_IVA_WRITE_CONFLUENCE_URL` и `extra_hosts` обязаны
совпадать по имени с `HELM_IVA_OAUTH_CONFLUENCE_BASE_URL`. В прод-compose я записал
`wiki.iva.ru` (так назван туннель в задаче); в тестах фигурирует `confluence.iva.ru` —
это лишь адрес заглушки, но если боевой адрес другой, править надо оба места.

## Чего нельзя проверить без живых ключей и живого контейнера

1. **Что Jira/Confluence DC принимают OAuth-access как `personal_token`.** Пакет в
   header-ветке строит конфиг с `auth_type="pat"` и шлёт токен как Bearer к API — с
   OAuth-access это обычно работает, но на нашем инстансе не проверено. Если DC
   откажет, чинится не поверхностью, а видом токена в хранилище.
2. **Сеть контейнер → туннель**: `extra_hosts` + порт 8443 + валидность цепочки
   сертификатов внутри контейнера. Тесты берут границу сети заглушкой.
3. **Точное поведение `tools/list`** при одной паре заголовков — вывод сделан по
   исходникам пакета, не по живому вызову.
4. **Стартует ли образ `ghcr.io/sooperset/mcp-atlassian:0.23.0` с пустым окружением
   ровно с этими переменными.** Тег в реестре существует (проверил список тегов), сам
   образ не запускал.
5. **Валидация учётки на первом запросе**: пакет на каждом новом креде делает вызов
   «кто я» к Atlassian (`_create_and_validate`) и кеширует результат на
   `MCP_ATLASSIAN_VALIDATION_CACHE_TTL` (по умолчанию 300 с). Это добавляет один
   сетевой вызов к первому запросу человека — на живом контуре стоит померить.
