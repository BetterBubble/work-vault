## 4. Новый тест `test_project_convention_precedence.py` — не тавтологичен

**Правило берётся из поставки, а не дублируется в тесте.** Резолвер разбирает раздел «Конвенция
проекта старше нашей» из **тела фрагмента, взятого из дерева установки**, и строит порядок
проверки из нумерованного списка **самого правила** (`parse_precedence_rule`, `:161-190`). Точка
входа собирается настоящим `_wrap_body_with_markers` и настоящим клиентским `apply_actions`; наша
секция при резолве **вырезается**, иначе подчинение было бы самоподтверждающимся (`:236`).

**Сломал сам — покраснело.** Внёс мутацию в фрагмент роли `iva-role-qa`, которой **нет** в списке
мутаций теста (там `iva-role-qa-mobile`): удалил из порядка проверки шаг `3. README.md`.

```
FAILED test_installed_entry_point_defers_to_project_convention[readme-only-claude-code-iva-role-qa]
FAILED test_fragment_declares_the_rule[claude-code-iva-role-qa]
2 failed, 49 passed
```

Покраснели оба слоя — и контрактный («в порядке проверки нет источников `['README.md']`»), и
**поведенческий**: проект, объявивший конвенцию только в README, снова разрезолвился в наш
`.tasks/work/`. Это и есть доказательство, что порядок берётся из правила, а не зашит.

**Граница честности проведена в самом файле** (`:20-28`): резолвер — модель чтения, а не агент,
живое поведение LLM не воспроизводится. Согласен, и это правильная оговорка.

**Но одно предложение в этой оговорке сильнее факта** — см. находку 2: «любая правка, возвращающая
"наш путь главный", делает файл красным» неверно, я провёл мутацию, которая сохранила все
обязательные элементы, вывернула смысл именно для рабочей директории и оставила 51 passed.

Фрагмент восстановлен побайтно, рабочее дерево чистое, `HEAD` = `578a3c5`.

Требование решения ГД («подчинение держится **проверкой, падающей на подмене**») закрыто.
Второе требование ГД — про `.codex/config.toml` с `create_if_missing` — закрыто честным текстом
в codex-фрагменте («файл уже есть → наши значения не применяются… допиши `max_depth = 1` руками»)
