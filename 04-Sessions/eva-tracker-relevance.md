# Нужен ли EVA-трекер для analyst-MCP / ТЗ — анализ

Explorer, read-only, 2026-07-17. Вопрос: нужен ли EVA-трекер (`eva.iva.ru`, `data/real/eva/eva_tasks.csv` ~6635 задач, `source="eva"`) для нашего MCP и ТЗ, или лишний scope. Связано: [[rag2-corpus-map]], [[rag2-ivaonehalf-gap]]. NB: речь про ТРЕКЕР задач, не про eva-wiki.orionpro (HTML-доки, отдельно).

## Вердикт: для analyst-MCP / ТЗ — НЕТ (вне ядра). Ценность EVA — в управленческом контуре, не в аналитик-MCP.
Ни один MCP-тул аналитика не потребляет `source="eva"`; заингестить EVA в корпус `iva_jira` — extra scope без потребителя. EVA полезна отдельному продукту — управленческому контуру (coverage/зависимости/дашборды), который уже кормится CSV-дампом для offline-графа и не требует EVA в Qdrant.

## По слоям (доказательная база)

### 1. ТЗ
- `~/tacticum/mcp-доработка-промпт-новой-сессии.md`: **EVA/eva.iva/второй трекер НЕ упоминается** (единственный хит «eva» — подстрока в слове «explorer», ложный). Т.е. EVA-трекер вне ТЗ доработки MCP.
- ТЗ-RAG2-контракты в `~/Downloads` не найден (файла нет на месте) — но профильный MCP-промпт EVA не требует.

### 2. Код/архитектура — EVA интегрирована, но в ДРУГОЙ контур
- `ingest/eva_source.py` + `ingest/real_source.py` (:280–311): EVA — ВТОРОЙ трекер задач РЯДОМ с Jira, грузится ТОЛЬКО если есть `data/real/eva/eva_tasks.csv`; логины канонизируются картой идентичности. Даёт: genesis-эпики, сигналы `source="eva"`, зависимости §5.4 (`eva_task_links.csv`).
- `ingest/loader.py` (:549–598): eva_issues/eva_epics/eva_links → инициативы + `_build_link_dependencies` (граф зависимостей). Это **offline управленческий граф** (инициативы/генезис/критпуть).
- `application/tasks.py` (:36 `TASK_SOURCES={jira,eva}`, :217): EVA считается трекером задач ТОЛЬКО для `coverage_rate`/метрик покрытия — это управленческая аналитика, не аналитик-MCP.
- `domain/rag2.py` (:512–568): в RAG#2-роутере `_EVA` = интент **live-метрик** («активных пользователей», «метрики использования», «дашборд») → `mode=live`, «коннектора пока нет». Это EVA как ЖИВОЙ источник метрик, а НЕ оффлайн task-корпус. Ингест eva_tasks.csv этот интент НЕ закрывает.
- Полу-мёртвости нет: код рабочий и подключён, но обслуживает управленческий/графовый контур, не analyst-MCP.

### 3. MCP-тулы — EVA не потребляется ни одним
- `related_tasks` (:315): RAG#2-поиск, результат **явно фильтруется `h.source == "jira"`** → EVA исключён by design. Даже будь EVA в корпусе — тул её не вернёт.
- `affected_systems` (:534): путь Requirement→Component→repo→ArchNode + `EpicTask.fix_versions`. Источники — C4-граф (ArchNode) и Jira-mgmt (EpicTask). **EVA нет.**
- `contradiction_check` / `constraints` (:1102–1241): слой ADR + НФТ. **EVA нет.**
- Прямых обращений к `source="eva"` в `interface/`/`application/` (кроме метрик покрытия) нет → MCP не тянет EVA.
- Факт: в Qdrant `source=eva=0`. Для analyst-MCP это НИЧЕГО не ломает — ни один тул этот источник не запрашивает.

### 4. Что аналитик НЕ до-получает без EVA в MCP
- Практически ничего в рамках текущих тулов. related_tasks и так только Jira; affected/contradiction — граф/ADR/требования.
- Частичный «а если бы»: кросс-трекерные зависимости §5.4 (EVA↔Jira «что блокирует») обогащают граф зависимостей — НО этот граф сейчас выведен в дашборды/витрины, а НЕ в analyst-MCP-тулы. Чтобы EVA дала ценность аналитику, пришлось бы СНАЧАЛА вывести структурный интент зависимостей в MCP-тул — это отдельная фича, не текущее ТЗ.

## Контекст-риск (память)
Ранее зафиксировано (Taiga): «EVA снимается: ИВА переходят полностью на Jira → eva-mcp не нужен, Jira покроет RAG#2». Т.е. стратегически EVA-трекер вытесняется Jira — доп-аргумент не расширять MCP-scope на EVA.

## Итог
EVA-трекер для analyst-MCP/ТЗ — **НЕТ / маргинально**: ни related_tasks, ни affected_systems, ни contradiction_check его не используют; `source=eva=0` в корпусе ничего не ломает; ТЗ его не требует. EVA живёт и ценна в управленческом контуре (coverage, инициативы, §5.4-зависимости, дашборды) через offline CSV-граф — туда её ингест в Qdrant-корпус аналитика не относится. Стратегически EVA вытесняется Jira. Рекомендация разведки: НЕ включать EVA-трекер в scope ингеста analyst-корпуса без отдельной фичи «зависимости в MCP».
