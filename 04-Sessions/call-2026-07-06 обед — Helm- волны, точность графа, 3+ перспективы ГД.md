# call-2026-07-06 обед — Helm: волны, точность графа, 3+ перспективы ГД

Обрывок разговора с руководителем (`~/Downloads/Обрывок разговора.rtf`, первые 10-15 мин не записаны). Продолжение утреннего созвона по сущностям.

## Что сказано
- [decision] Порядок подтверждён: **сначала сущности (откуда брать, как заполнять), потом RAG** — волнами. «От неё скачет всё остальное».
- [decision] **Фокус сейчас — вычленить Need и Initiative** (красные/неполные); пользователь шлёт по конкретной сущности в фоне.
- [decision] **Главная забота — точность/достоверность графа, не сложность реализации.** «Данные всегда неполные, задача оценить эту точность — где срезаем углы из-за неточности».
- [reference] **Ценность инициативы** = связать `Инициатива ↔ Потребность ↔ SalesInitiative` (деньги) → отличить «золотой эпик» от «мимо цели».
- [reference] **3-4 перспективы ГД (будущие витрины, «RAG = витрина под роль», модель данных одна):** Task Management · CPO/бэклог-ценность · Сервис/качество-SLA-инциденты · Sales. Надо сфокусироваться на ОДНОЙ. Явно важные сущности: релиз, фича/требование, инициатива, ценность.
- [reference] Поколение сквозное: для каждого продукта у поколения свои требования (аналогия «танк 5-го поколения»). LeadTime оценивает стоимость из репы + CRM + что клиент просит.

## Что сделано в ответ (эта сессия)
- [outcome] Три концепт-Artifact: **ER-модель** (30 сущностей/44 связи), **Мосты графа** (Т1/Т2/Т3, sales_link, Assignment, порядок сборки), **Происхождение сущностей** + панель 4 бизнес-ролей. Markdown-источники в `data/concept-entities.md` и `data/concept-entity-provenance.md`.
- [outcome] **Независимое бизнес-ревью (4 роли IVA, веб, без канона) вскрыло:** (1) **портфель IVA 11-16 продуктов, не 5** — канон занижен, подтверждает product_economics (11); (2) **Need bad** — упущены discovery/пресейл/проигранные сделки; FR/SD = симптом, не потребность; (3) **Initiative bad** — склеивает 3 разные (эпик=delivery, цель=директива, сделка=продажа), реальная инициатива из портфельного планирования; (4) склейки: Организация (внутр.юрлица+клиенты), ЕОЛ дублирует Блок, Цель=Директива, Релиз из git-следа а не release-plan.
